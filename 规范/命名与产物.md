# 简言 · 命名与产物约定

> 这一页定的是"文件叫什么、产物叫什么"。看起来是小事，但它会跟着语言一辈子：
> 改扩展名等于让所有人的项目、脚本、编辑器配置全部失效。

---

## 一、源文件后缀：`.jy`

### 候选对比

| 候选 | 现状 | 结论 |
|---|---|---|
| `.el` | **Emacs Lisp 的标准扩展名**。装了 Emacs 的机器上 `file 主.el` 会报 `Emacs Lisp source`，编辑器按 Lisp 高亮，`load` 语义直接撞车 | ❌ 硬冲突，不能用 |
| `.jy` | 无主流格式注册（`.jy` 只在少数私有工具里出现过），MIME 未注册 | ✅ **采用** |
| `.jn` | 无冲突，但 `jn` 常被读成 "Java Native" | 备选 |
| `.简` | 好看，但非 ASCII 扩展名在 zip 编码、Windows 路径、部分 CI 工具里行为不一致 | 仅作兼容 |
| `.jian` | 太长，命令行里要多敲两下 | ❌ |

### 最终约定

```
主后缀          .jy
兼容后缀        .简      （工具链认，但会提示"建议改成 .jy"）
大小写          .JY 也认，统一按小写处理
```

**为什么 `.jy` 而不是 `.el`：**
`.el` 不是"可能冲突"，是"一定冲突"。语言选的扩展名如果和某个存量生态撞了，
那个生态的用户每天都会遇到"我的文件被识别成别的语言"，而简言没有任何办法纠正。
选一个干净的短后缀，比事后解释便宜一万倍。

**为什么还留 `.简`：**
中文写代码的人第一反应是"能不能用中文后缀"。答案是能，但别当主推——
`.jy` 在跨平台工具链里更安全。所以：认它，但不推荐它。

### 编辑器与 MIME

```
MIME              text/x-jianyan
VS Code 关联      *.jy, *.简
GitHub Linguist   暂不注册（等语法稳定后提 PR）
```

语法高亮规则放在仓库 `工具/vscode-jianyan/`，关键字表直接从
`词法/lexer.c` 的 `关键字表[]` 生成，保证"高亮的关键字"和"编译器认的关键字"永远一致。

## 二、二进制产物

### 最终可执行文件：不加后缀

```
Linux / macOS     主.jy  →  主          （无后缀，Unix 惯例）
Windows           主.jy  →  主.exe
```

理由很实在：

1. **系统惯例。** 在 Linux 上 `./主` 是所有人的肌肉记忆。加个 `.jyx` 之后，
   shell 补全、Makefile、Dockerfile、systemd unit 里全都要多写四个字符，而且看着别扭。
2. **打包工具会犯错。** 很多打包/部署脚本按扩展名判断"这是不是可执行文件"，
   非标准后缀容易被当成资源文件，权限位被丢掉。
3. **可辨识性有更好的办法**——见下。

#### 用 ELF note 打标记，而不是改后缀

每个简言编出来的 ELF 里塞一段 note：

```
.note.jianyan
  名字   "JianYan\0"
  类型   1
  描述   编译器版本 + 目标三元组 + 源文件内容哈希
```

于是：

```sh
$ file 主
主: ELF 64-bit LSB pie executable, x86-64, statically linked,
    JianYan v0.1.0 (x86_64-linux-musl), stripped

$ jy 检查 主
这是一个简言编译出来的程序
  编译器   简言 v0.1.0
  目标     x86_64-linux-musl
  源文件   主.jy（sha256: 3f9a…）
  编译于   2026-11-20 19:02:11
```

"一眼看出这是简言产物"的目的达到了，系统惯例一点没破坏。

#### 想要后缀也行

```sh
jy 编译 主.jy -o 主.jyx      # 显式指定就用你给的名字，工具链不拦
```

### 中间产物

| 后缀 | 是什么 | 类比 |
|---|---|---|
| `.jym` | **模块接口文件**。编译一个模块时顺带产出，只含公开的类型、函数签名、常量 | C 的 `.h`、TS 的 `.d.ts` |
| `.jyc` | **编译产物**。单态化之后的中间表示/目标文件，多个 `.jyc` 链接成可执行文件 | `.o` |
| `.jyd` | **调试信息**。行号表、变量名表，可剥离，剥离后程序照跑 | `.dSYM`、`.pdb` |

`.jym` 是这三个里最重要的：它让"改一个文件不用重编整个项目"成为可能，
也让跨模块类型检查有据可依（见 `语义分析说明.md` 的"已知边界"）。

```
项目/
├── 主.jy
├── 工具/
│   ├── 字符串.jy
│   └── 字符串.jym        ← 别人只读这个，不读你的源码
└── 构建/
    ├── 主.jyc
    └── 字符串.jyc
```

### 分发（可选）

| 后缀 | 是什么 |
|---|---|
| `.jyp` | 单文件分发包：一个可执行文件 + 依赖的 `.jym` + 资源，追加在 ELF 尾部，运行时按偏移读取 |

`.jyp` 不是必须的——简言默认静态链接，一个文件就是全部。它只用于"程序要带资源"
（字体、图标、模板）的场合。

## 三、命令行工具：`jy`

```
jy 编译 主.jy              → 主
jy 运行 主.jy              → 编译到内存并直接跑（开发时用）
jy 检查 主.jy              → 词法 + 语法 + 语义，只报错不产出
jy 格式化 主.jy            → 原地排版
jy 测试                    → 跑所有 测试 "..." 块
jy 文档 主.jy              → 从注释生成 HTML
```

中文别名 `简`，等价：

```
简 编译 主.jy
```

工具名和后缀呼应，`jy 编译 x.jy` 读起来是一句话。

---

## 四、命名的连带影响

定下 `.jy` 之后，这些地方要跟着统一：

| 地方 | 值 |
|---|---|
| 词法器的 `模块` 路径 | `示例.基础` 对应 `示例/基础.jy` |
| 编译器的默认输出名 | 源文件名去掉 `.jy` |
| `jy 检查` 的识别 | 只认 `.jy` / `.简`，其它后缀直接拒绝并提示 |
| 错误信息里的文件名 | 原样显示，不简化成 basename |
| 文档里的代码块 | ```` ```简言 ````，编辑器按 `.jy` 高亮 |

---

## 五、一句话总结

**源码 `.jy`，可执行文件不加后缀，中间产物 `.jym` / `.jyc` / `.jyd`，
靠 ELF note 而不是靠扩展名来标识"这是简言造的"。**

`.el` 出局，原因是它不是"可能撞"，是"已经撞了"。
