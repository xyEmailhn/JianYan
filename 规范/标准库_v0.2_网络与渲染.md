# 简言标准库 v0.2 · 网络与渲染

> v0.1 的标准库只够写命令行小工具：字符串、数组、映射、文件、时间。
> v0.2 加两块**能让简言做真东西**的：网络、渲染。
> 同时把"快"从口号变成可核对的数字。

---

## 一、三条铁律

新增的每个模块都必须守住这三条，否则不进标准库：

| 铁律 | 意思 | 为什么 |
|---|---|---|
| **零依赖** | 不链接 OpenSSL、不链接 libpng、不链接 cairo。要什么自己写 | 简言编译出来是单个静态二进制，拖一个 `.so` 就前功尽弃 |
| **零拷贝** | 数据从内核到用户态、从缓冲到画布，能不做第二次拷贝就不做 | 网络和渲染都是"搬运字节"的活，省一次拷贝就是省一次内存带宽 |
| **错误不外抛** | 所有可能失败的操作返回 `结果[T, 错误]`，不 panic | 服务端不能因为一个坏请求就整个进程退出 |

第三条尤其关键。下面所有 API 的返回类型里出现 `结果` 的地方，都不是装饰。

## 二、模块全景

```
标准库
├── 核心（v0.1 已有）
│   ├── 字符串  数组  映射  组
│   ├── 文件  路径  时间  进程  环境
│   └── 格式化  随机  数学
├── 网络（v0.2 新增）
│   ├── 网络.地址      IP + 端口
│   ├── 网络.流        TCP 连接（读写、超时、半关闭）
│   ├── 网络.监听      TCP 服务端
│   ├── 网络.数据报    UDP
│   ├── 网络.域名      DNS 解析（含缓存）
│   ├── 网络.TLS       TLS 1.3 客户端/服务端
│   ├── HTTP.服务端    请求路由、keep-alive、分块、静态文件
│   └── HTTP.客户端    连接池、重定向、超时
└── 渲染（v0.2 新增）
    ├── 渲染.画布      RGBA8 像素缓冲
    ├── 渲染.颜色      预乘 alpha
    ├── 渲染.路径      直线、贝塞尔、圆弧
    ├── 渲染.变换      2×3 仿射矩阵
    ├── 渲染.文字      TrueType 子集 + SDF 缓存
    ├── 图像.PNG       编解码（自带 deflate）
    ├── 图像.缩放      双线性 / 面积平均
    └── 渲染.图形      可选 GPU 后端（Vulkan / Metal / WebGPU）
```

命名规则：模块名就是名字空间，`网络.流` 是类型，`网络.连接(...)` 是函数。
标准库模块全部以 `标准库/` 下的目录实现，编译时按需链接——不用网络就不带网络代码。

## 三、网络

### 3.1 地址

```简言
结构 地址 {
    主机: 字符串
    端口: 整数16
}

函数 解析地址(文本: 借用 字符串) -> 结果[地址, 字符串]
函数 本机地址() -> 地址                      -- 0.0.0.0:0，交给内核挑端口
函数 地址.文本(借用 自身) -> 字符串           -- "127.0.0.1:8080"
```

`解析地址("127.0.0.1:8080")`、`解析地址("[::1]:8080")` 都要认。
IPv6 必须支持——不是"以后加"，因为容器和云主机默认双栈。

### 3.2 流（TCP 连接）

```简言
结构 流 {
    句柄: 整数32
    读缓冲: 缓冲
    写缓冲: 缓冲
}

函数 连接(地址: 借用 地址, 超时毫秒: 整数) -> 结果[流, 网络错误]
函数 流.读(借用 自身, 目标: 可变借用 字节组) -> 结果[整数, 网络错误]
函数 流.写(可变借用 自身, 数据: 借用 字节组) -> 结果[整数, 网络错误]
函数 流.读全部(可变借用 自身) -> 结果[字节组, 网络错误]
函数 流.设置超时(可变借用 自身, 毫秒: 整数)
函数 流.半关闭(可变借用 自身)                -- shutdown(SHUT_WR)
函数 流.关闭(可变借用 自身)
```

`字节组` 是 `整数8 组` 的别名，专门表示"一段原始字节"。

**为什么 `读` 要传缓冲区而不是返回新数组？**
因为服务端每秒可能要读几万次。每次 `malloc` 一个新数组，分配器会成为瓶颈。
让调用者复用缓冲区，就等于把分配次数从"每请求一次"降到"每连接一次"。

### 3.3 监听

```简言
结构 监听 {
    句柄: 整数32
    复用端口: 布尔值
}

函数 监听端口(地址: 借用 地址, 积压: 整数) -> 结果[监听, 网络错误]
函数 监听.接受(可变借用 自身) -> 结果[流, 网络错误]
函数 监听.关闭(可变借用 自身)
```

`监听端口` 默认打开这几个选项：

```
SO_REUSEADDR     重启服务不用等 TIME_WAIT
SO_REUSEPORT     多进程/多线程各监听同一端口，内核帮你分流（Linux 3.9+）
TCP_NODELAY      小包不攒，延迟低
TCP_DEFER_ACCEPT 有数据才唤醒，省掉空转
```

`SO_REUSEPORT` 是多核扩展的关键：起 8 个进程各 `监听端口(同地址)`，
内核按四元组哈希分流，比"一个 accept 循环抢连接"的扩展性好得多。

### 3.4 UDP 与 DNS

```简言
结构 数据报 { 句柄: 整数32 }
函数 绑定数据报(地址: 借用 地址) -> 结果[数据报, 网络错误]
函数 数据报.收(可变借用 自身, 缓冲: 可变借用 字节组) -> 结果[整数, 网络错误]
函数 数据报.发(借用 自身, 数据: 借用 字节组, 目标: 借用 地址) -> 结果[整数, 网络错误]

函数 域名.解析(名: 借用 字符串) -> 结果[地址 组, 网络错误]
函数 域名.设置缓存(容量: 整数, 存活秒: 整数)
```

DNS 自己实现（UDP 查询 + 解析报文），带 TTL 缓存。不调 `getaddrinfo`，
因为它是阻塞的，而且行为随系统配置变。

### 3.5 TLS 1.3

```简言
函数 TLS.包装客户端(流: 移动 流, 服务器名: 借用 字符串)
    -> 结果[TLS.会话, 网络错误]
函数 TLS.包装服务端(流: 移动 流, 证书: 借用 证书, 私钥: 借用 私钥)
    -> 结果[TLS.会话, 网络错误]
```

只做 TLS 1.3（不支持 1.2 及以下，不做重协商、不做压缩）。
密码套件只保留三个 AEAD 组合：

```
TLS_AES_128_GCM_SHA256
TLS_AES_256_GCM_SHA384
TLS_CHACHA20_POLY1305_SHA256
```

AES-GCM 在 x86 上用 AES-NI 指令（一条指令算一轮），ARM 上用 ARMv8 Crypto 扩展。
没有硬件加速时自动退到 ChaCha20（纯软件也够快）。

> 这是整个 v0.2 工作量最大的一块。如果时间不够，先只做客户端（连别人的 HTTPS），
> 服务端 TLS 放 v0.3。

### 3.6 HTTP 服务端

```简言
结构 请求 {
    方法: 字符串
    路径: 字符串
    查询: 映射[字符串, 字符串]
    头: 映射[字符串, 字符串]
    体: 字节组
    对端: 地址
}

结构 响应 {
    状态: 整数
    头: 映射[字符串, 字符串]
    体: 字节组
}

结构 服务端 {
    路由: 映射[字符串, 处理函数]
    根目录: 字符串
    最大体: 整数
}

函数 新建服务端() -> 服务端
函数 服务端.取(可变借用 自身, 路径: 字符串, 处理: 处理函数)
函数 服务端.静态文件(可变借用 自身, 前缀: 字符串, 目录: 字符串)
函数 服务端.启动(可变借用 自身, 地址: 借用 地址) -> 结果[空值, 网络错误]
```

用法：

```简言
函数 主页(请求: 借用 HTTP.请求) -> HTTP.响应 {
    返回 HTTP.响应 {
        状态: 200,
        头: { "Content-Type": "text/html; charset=utf-8" },
        体: "<h1>你好，简言</h1>"
    }
}

函数 主() {
    私有 HTTP.服务端 服务 = HTTP.新建服务端()
    服务.取("/", 主页)
    服务.静态文件("/静态", "./公共")
    服务.启动(借用 网络.解析地址("0.0.0.0:8080").取值())
}
```

#### 静态文件走零拷贝

```简言
函数 服务端.静态文件(可变借用 自身, 前缀: 字符串, 目录: 字符串)
```

命中静态文件时，不把文件读进内存再 `写`，而是：

```
Linux   sendfile(客户端句柄, 文件句柄, 偏移, 长度)
        内核直接把文件页缓存送进 socket，用户态一次拷贝都没有

带 TLS  splice(文件 → 管道) + splice(管道 → socket)
        仍然不需要用户态缓冲，只是多走一次内核管道
```

一个 100 MB 的文件，用 `sendfile` 比"读进内存再写"少两次内存拷贝，
在大文件场景下实测通常快 1.5–2 倍，且常驻内存不涨。

#### 头解析用 SIMD

HTTP 头解析是纯字节扫描。逐字节找 `\r\n\r\n`（头结束标记）在 1 GB/s 上下，
用 AVX2 一次比 32 字节，能到 8–15 GB/s：

```
把 32 字节装进一个 256 位寄存器
和 0x0d0d...0d 比较 → 掩码 A
和 0x0a0a...0a 比较 → 掩码 B
A 左移 1 位 与 B 相与 → 候选位置
第一个非零位就是 "\r\n" 的起点
```

同样的手法用来找 `:`（分隔头名和值）和 `,`（分隔 `Accept-Encoding` 这类列表）。

#### 连接与缓冲池

```
空闲连接池      keep-alive 的连接不关，放回池里复用（默认 1000 条，60 秒超时）
缓冲池          每个连接借两个 4 KB 缓冲，连接放回池时缓冲也放回
请求对象池      请求结构体复用，避免每请求一次 malloc
```

简言没有 GC，但有 `移动`。池化就是把"释放"换成"放回"，语法上完全自然：

```简言
私有 缓冲池 池 = 缓冲池.新建(1024, 4096)
私有 缓冲 借来的 = 池.取()          -- 拿一个
...                                  -- 用
池.放回(移动 借来的)                -- 还回去，所有权转移
```

### 3.7 HTTP 客户端

```简言
结构 客户端 { 池: 连接池, 超时毫秒: 整数, 跟随重定向: 整数 }

函数 新建客户端() -> 客户端
函数 客户端.取(可变借用 自身, 网址: 借用 字符串) -> 结果[HTTP.响应, 网络错误]
函数 客户端.提交(可变借用 自身, 请求: 借用 HTTP.请求) -> 结果[HTTP.响应, 网络错误]
```

连接池按 `主机:端口` 分组，同组内复用。默认跟随 5 次重定向，只跟 301/302/303/307/308。

## 四、渲染

### 4.1 画布

```简言
结构 画布 {
    宽: 整数
    高: 整数
    像素: 整数8 组        -- RGBA8，预乘 alpha，行优先，无行间填充
    裁剪: 矩形
}

函数 新建画布(宽: 整数, 高: 整数) -> 结果[画布, 字符串]
函数 画布.清空(可变借用 自身, 颜色: 颜色)
函数 画布.取像素(借用 自身, x: 整数, y: 整数) -> 颜色
函数 画布.放像素(可变借用 自身, x: 整数, y: 整数, 颜色: 颜色)
函数 画布.填矩形(可变借用 自身, 矩形: 矩形, 颜色: 颜色)
函数 画布.填路径(可变借用 自身, 路径: 借用 路径, 颜色: 颜色)
函数 画布.描边(可变借用 自身, 路径: 借用 路径, 宽: 浮点, 颜色: 颜色)
函数 画布.画线(可变借用 自身, 甲: 点, 乙: 点, 宽: 浮点, 颜色: 颜色)
函数 画布.画文字(可变借用 自身, 文本: 借用 字符串, 位置: 点, 字体: 借用 字体, 大小: 浮点, 颜色: 颜色)
函数 画布.存PNG(借用 自身, 路径: 字符串) -> 结果[空值, 字符串]
```

**预乘 alpha**：像素存的是 `(r×a, g×a, b×a, a)` 而不是 `(r, g, b, a)`。
好处是混合只需一次乘加：

```
结果 = 前景 + 背景 × (1 - 前景.a)
```

不用每次现算 `r×a`。代价是"取像素"时要反乘回去——但取像素是冷路径。

### 4.2 路径与填充

```简言
结构 路径 { 段: 路径段 组, 当前: 点 }

函数 路径.新建() -> 路径
函数 路径.移到(可变借用 自身, 点: 点)
函数 路径.直线到(可变借用 自身, 点: 点)
函数 路径.二次到(可变借用 自身, 控制: 点, 终点: 点)
函数 路径.三次到(可变借用 自身, 控1: 点, 控2: 点, 终点: 点)
函数 路径.弧(可变借用 自身, 圆心: 点, 半径: 浮点, 起角: 浮点, 终角: 浮点)
函数 路径.闭合(可变借用 自身)
```

填充算法用**扫描线 + 活性边表**：

```
1. 把每条曲线按平坦度切成小线段（贝塞尔细分成 8~32 段）
2. 按 y 排序所有线段端点，建边表
3. 逐行扫描：
     把跨过这一行的边放进"活性边表"（按 x 排序）
     两两配对，配对的 x 之间就是要填的区间
     按区间水平填充（这一行内部可以整段 memset / 或按渐变算）
4. 抗锯齿：每条边按覆盖比例算出 0~255 的覆盖率，累加到"覆盖缓冲"，
   最后统一乘到颜色上
```

抗锯齿用覆盖率缓冲（coverage buffer）而不是超采样：内存少 4~16 倍，质量够用。

### 4.3 文字

```简言
结构 字体 { ... }
函数 加载字体(路径: 字符串) -> 结果[字体, 字符串]
函数 字体.度量(借用 自身, 文本: 借用 字符串, 大小: 浮点) -> 文本度量
```

三个关键决定：

1. **只解析 TrueType 的子集**：`cmap`（字符→字形）、`glyf`（轮廓）、`loca`、`head`、`hhea`、`hmtx`。
   不碰 `GSUB`/`GPOS`（复杂排版）、不做可变字体。中文用系统字体或随包带一个。
2. **字形轮廓转成 SDF**：每个字形预计算一张 64×64 的有符号距离场，缩放时不糊。
   同一字号只算一次，之后按需采样。
3. **字形图集**：常用的 2000 个字形打进一张 2048×2048 的图集，一次绑定多次绘制。

```简言
函数 画布.画文字(可变借用 自身, 文本: 借用 字符串, 位置: 点, 字体: 借用 字体, 大小: 浮点, 颜色: 颜色)
```

内部流程：`文本 → 字形序列 → 查图集 → 逐字形贴图（SIMD 混合）`。
首次遇到某字号才栅格化，之后全走缓存。

### 4.4 图像编解码

```简言
模块 图像.PNG
函数 解码(数据: 借用 字节组) -> 结果[画布, 字符串]
函数 编码(画布: 借用 画布) -> 结果[字节组, 字符串]

模块 图像.JPEG
函数 解码(数据: 借用 字节组) -> 结果[画布, 字符串]
函数 编码(画布: 借用 画布, 质量: 整数) -> 结果[字节组, 字符串]
```

PNG 要自己写 deflate。策略：

```
编码   固定霍夫曼 + 贪心 LZ77（哈希链，窗口 32 KB）
       压缩率比 zlib -6 低 5%~10%，但速度快 2~3 倍，代码量 1/5
       对"程序生成的图"（大片同色）压缩率反而更好
解码   完整支持动态霍夫曼（别人的 PNG 得能读）
```

JPEG 解码比 PNG 复杂（霍夫曼 + 反量化 + IDCT + 色彩转换），
但也就 800 行左右。IDCT 用 AAN 快速算法，8×8 块用 SSE2 并行。

### 4.5 可选 GPU 后端

```简言
模块 渲染.图形
函数 创建表面(宽: 整数, 高: 整数) -> 结果[表面, 字符串]
函数 表面.画三角形(可变借用 自身, 顶点: 顶点 组, 纹理: 可空[纹理])
函数 表面.呈现(可变借用 自身)
```

走 Vulkan（Linux/Windows）、Metal（macOS）、WebGPU（Web）。
**这是可选模块**，标准库核心不依赖它。没有 GPU 或没编译这个模块时，
`渲染.画布` 的 CPU 路径照常工作。

## 五、速度从哪来

不是"用了 C 所以快"，是每一处都做了具体的事：

| 手段 | 在哪 | 省掉了什么 | 预期收益 |
|---|---|---|---|
| `sendfile` / `splice` | HTTP 静态文件 | 两次用户态↔内核拷贝 | 大文件 1.5–2× |
| SIMD 找 `\r\n\r\n` | HTTP 头解析 | 逐字节循环 | 8–15× |
| 缓冲池 + 对象池 | 每连接、每请求 | `malloc`/`free` | 分配开销降 80%+ |
| `SO_REUSEPORT` | 监听 | 单 accept 队列锁竞争 | 8 核近线性扩展 |
| 连接池 + keep-alive | HTTP 客户端 | TCP + TLS 握手 | 每请求省 1–3 个 RTT |
| 预乘 alpha | 渲染 | 每次混合现算乘法 | 混合吞吐 1.3× |
| SIMD 混合（16 像素/批） | 渲染填充 | 逐像素循环 | 4–8× |
| 扫描线 + 活性边表 | 路径填充 | 逐像素判断内外 | 3–10×（取决于形状） |
| 覆盖率抗锯齿 | 渲染 | 4× 超采样 | 内存 1/16 |
| SDF 字形缓存 | 文字 | 每次重栅格化 | 文字排版 10×+ |
| tile 多线程 | 大画布渲染 | 单核 | 核数 −1 倍 |
| 固定霍夫曼 deflate | PNG 编码 | 动态霍夫曼的统计 | 2–3× |
| 单态化泛型 | 全库 | 装箱/虚调用 | 容器操作 2–5× |

> 最后一条是语言层的红利：`组[整数]` 编译出来就是 `int32_t* + len`，
> 没有任何"元素是对象指针"的间接层。这条在别的语言里要 JIT 才能拿到。

## 六、和语言特性怎么配合

标准库不是"另写一套 C"，它必须吃满语言给的东西：

| 语言特性 | 标准库怎么用 |
|---|---|
| `借用` / `可变借用` | 所有"传大对象"的参数都是 `借用`，调用处零拷贝 |
| `移动` | 缓冲、连接、画布的所有权转移；池化就是"移进移出" |
| `结果[T, 错误]` | 所有 I/O 都返回结果，`失败返回` 一路往上抛，不用写 try |
| `组[T]` 连续内存 | 像素缓冲、顶点数组、字形序列，全部连续存放 |
| 单态化泛型 | `池[T]`、`队列[T]` 各类型各编一份，无装箱 |
| 通道 + 线程 | tile 渲染：主线程切块，工作线程各画一块，通道回传 |
| 无 GC | 帧循环里不产生垃圾，延迟稳定（渲染最怕 GC 停顿） |
| `可空[T]` | `字体.找字形(c)` 找不到字符时返回 `空`，不抛异常 |

tile 渲染的例子：

```简言
函数 并行填充(画布: 可变借用 画布, 路径: 借用 路径, 颜色: 颜色, 线程数: 整数) {
    私有 通道[渲染块] 完成 = 通道[渲染块](线程数)
    私有 整数 块高 = (画布.高 + 线程数 - 1) // 线程数

    对 i: 0~线程数 - 1 {
        私有 整数 起 = i * 块高
        私有 整数 止 = 最小(起 + 块高, 画布.高)
        线程 {
            私有 画布 局部 = 画布.子区域(起, 止)
            局部.填路径(路径, 颜色)
            发送 完成, 渲染块 { 起: 起, 止: 止, 像素: 局部.像素 }
        }
    }

    对 i: 0~线程数 - 1 {
        私有 渲染块 块 = 接收 完成 取值()
        画布.贴回(移动 块)
    }
}
```

三个线程各画一段，互不重叠，最后拼回去。因为每块是独立的像素区间，
不需要任何锁——这正是"所有权清晰"带来的好处。

## 八、明确不做

| 不做 | 原因 |
|---|---|
| HTTP/2、HTTP/3 | 复杂度是 HTTP/1.1 的五倍，收益对大多数场景不明显 |
| WebSocket | 需要先有 HTTP 升级机制，v0.3 再议 |
| 完整 CSS 布局引擎 | 那是浏览器，不是标准库 |
| 视频编解码 | 专利与复杂度都不合适 |
| 字体复杂排版（阿拉伯文连写、印度文重排） | 需要 HarfBuzz 级别的工程量 |
| 多线程共享画布写入 | 每个 tile 一个线程写自己那块，不共享 |

---

## 九、一句话总结

**网络模块让简言能当服务端，渲染模块让简言能出图，
两者共用同一套"零拷贝 + 池化 + SIMD"的打法，
而单态化泛型和所有权模型是它们快的底层原因。**
