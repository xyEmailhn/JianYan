# 简言 · 后端 v0.5：C 参考后端

> **v0.6 补记**（见第 11 节）：模块级 `常量` 与 `新建 类型{...}` 已实现；
> 海报重画了一遍——上一版的山被误认成太阳光柱。

> 前四棒（词法、语法、语义、IR）加起来一万五千行，却从没有一个 `.jy` 文件被真正执行过。
> 这一棒把它接通：**IR → C → 机器码**，`简编译 例子.jy -o 例子 && ./例子`。

---

## 1. 为什么不直接出 x86-64

原本的计划是「指令选择 + 寄存器分配 → ELF」。真动手时改了主意，理由很具体：

**第一次跑崩了，你分不清是谁的错。**

IR 里可能藏着一堆没人发现的 bug（这一轮就挖出七个，见第 6 节）。如果同时再叠上指令选择的 bug、寄存器分配的 bug，一个段错误可能查一下午只挪动一行。

出 C 有四个好处：

| 好处 | 说明 |
|---|---|
| 指令选择和寄存器分配先不碰 | 交给 gcc，这两块是后端最难的部分 |
| 生成的 C 能读 | IR 错了，肉眼能看出来是哪一条指令错 |
| 立刻能跑真实程序 | 把 IR 的 bug 一次性全逼出来 |
| 结构定下来 | 换成 x86-64 只是把「写 C 语句」换成「发机器码」 |

所以这个后端叫**参考后端**：它同时是后端的规格说明书，和将来原生后端的对照组。两边跑同一批测试，输出必须逐字节相同。

## 2. 映射规则

整套后端只有三条规则：

```
每个 IR 值     →  一个 C 局部变量  v<N>
每个基本块     →  一个 C 标签      L<N>
每个变量槽     →  也是一个普通 C 变量，载/存 就是赋值
```

一条 IR 指令的例子：

```
%t3 = 加 %t1, %t2 : 整数        →    v3 = v1 + v2;
条件跳 %t5 则 L2 否则 L3          →    if (v5) goto L2; else goto L3;
```

**块之间完全靠 `goto`。** 不分析控制流、不重排块、不合并块——因为 IR 里块的创建顺序和执行顺序不一致（`while` 循环的出口块可能在循环体之前创建），按顺序拼会错，加跳转永远不会错。

**值不复用。** 每条指令一个变量，一个函数动辄几百个局部变量。看着浪费，但 gcc -O2 的寄存器分配正是干这个的：它做完活跃变量分析，这些变量会消失到只剩几个寄存器。

我们省下的每一行，都是原生后端将来要补的一行。这是有意的欠债。

## 3. 内嵌运行时

生成的 `.c` 是自包含的：运行时被原样拼在文件开头，不链接任何库（除了 libc/libm）。

| 类型 | C 表示 | 为什么这样 |
|---|---|---|
| `字符串` | `struct { const char *p; int64_t n; }` | UTF-8 字节串 + 显式长度。可以有 `\0`，不是 NUL 结尾 |
| `T 组` | `struct { char *p; int64_t n, 容; int 元宽; }` | 字节数组 + 元素宽度。生成代码按元素类型强转指针 |
| `映射[K,V]` | `struct { char *p; int64_t n, 容; int 键宽, 值宽, 键类; }` | 有序数组 + 线性查找 |
| `结果[T,E]` | `struct { int 成; char *p; int 宽; }` | 载荷类型不固定，用 `void*` + 宽度 |
| `通道[T]` | `struct { char *p; int64_t n, 容, 头; int 宽; }` | 环形缓冲 |
| `T 组` 的迭代器 | `struct { 简组 g; int64_t i; }` | 遍历开始/遍历下一个 协议的载体 |

几处取舍值得记：

**组为什么用「字节数组 + 元素宽度」而不是宏生成每种类型的数组？**
一个 `简组` 能装整数、结构体、字符串，靠 `元宽` 区分。代价是生成代码里到处是 `((球 *)g.p)[i]` 这样的强转，但类型安全由编译期检查保证，运行时不会错。

**映射为什么不是哈希表？**
有序数组 + 线性查找，`n` 通常很小。省掉哈希函数、扩容、冲突链三块代码，生成的程序也小。真需要 O(1) 时换成哈希表，接口不变。

**结果为什么用 `void*` 载荷？**
`成功(学生)` 和 `失败(字符串)` 的载荷类型不同，C 里没法用同一个静态类型装下。malloc 一份拷贝，取用时按目标类型 `sizeof` 拷回来。

**迭代器为什么单独处理？**
`遍历开始` 的结果类型在 IR 里是「未知」，但 C 里必须声明成 `简遍`。后端先扫一遍指令，把这类值标出来。

## 4. 借用怎么变成指针

这是整轮修改里最核心的一处。

语义层的 `借用` / `可变借用` 在 C 里没有对应物。第一版直接按值传，结果：

```
$ ./排序
排序前：[42, 7, 19, 3, 88, 56, 21, 9]
排序后：[42, 7, 19, 3, 88, 56, 21, 9]      ← 一个都没动
```

因为 `冒泡(数)` 拿到的是副本。修法是三处配合：

| 位置 | 改动 |
|---|---|
| 函数签名 | `参数是借用` → `T *v3` |
| 函数体 | 全局指针表标记后，`值名()` 遇到借用参数输出 `(*v3)` |
| 调用点 | 对应的实参写成 `&v_a` |
| IR 层 | 借用实参不要 `载`，直接用变量槽 |

最后一条是关键。IR 的 `降名字` 默认产出 `%t = 载 %a`（读一份副本），对借用参数必须绕开：

```c
if (形参是借用(被调声明, i) && 实参是名字) {
    int 槽 = 槽找(...);
    实[数] = 槽;           /* 直接给槽号，不载 */
}
```

同样的坑在**结构体字段赋值**上又出现了一次：

```简言
私有 点 p = {1.5, 2.5}
p.x = 9.0        -- IR 里成了：%t2 = 载 %p; 存字段 %t2.x
```

改的是副本的字段，`p` 一点没变。修法一样：`存字段`/`存下标`/`调用方法` 的对象如果是变量名，直接用槽号。

## 5. 指令覆盖

后端实现了 IR 的全部指令（含并发），但有三个地方是**降级**而非等价：

| 指令 | 处理 | 影响 |
|---|---|---|
| `移动`/`复制`/`借用`/`可变借用` | 无操作，直接透传 | 所有权在编译期已检查完，运行时不需要动作 |
| `线程 { }` 块 | IR 层已内联成顺序执行 | 没有真并发；通道是单线程环形缓冲 |
| `可空[T]` | 退化成 `T`，零值表示空 | `可空[整数]` 分不清「0」和「没有」 |

第三条是当前最大的语义漏洞。IR 用「元素 == 空」判断遍历结束，所以**整数数组里不能有 0**——有 0 就提前停。这是 IR 层的设计问题，不是后端的，下一轮该改成「索引 < 长度」。

## 6. 踩过的七个坑

全都是「看起来是调参问题，实际是逻辑错误」。

| # | 现象 | 真因 |
|---|---|---|
| 1 | 打印字符串带引号 | IR 的常量文含源码引号，没剥 |
| 2 | 剥了引号后出现半个汉字 | 长度没跟着减 2，多读了两个字节 |
| 3 | 打印输出 `%1234` | 运行时里的 `%lld` 被 `snprintf` 当成格式符吃掉了 |
| 4 | 结构体字段赋值不生效 | `载` 出了副本，改的是副本的字段 |
| 5 | 排序一个都没动 | 借用参数按值传，改的是副本（见第 4 节） |
| 6 | 字符串数组遍历死循环 | 空值哨兵写成了字面词「空」，字符串永远比不相等 |
| 7 | 中文长度返回 6 而不是 2 | `#` 返回了字节数，该返回字符数 |

第 6 个最典型：IR 里 `常量("空")` 对整数是零值，对字符串却是三个字节的「空」字。生成 C 时按类型分派才修好。

**这些 bug 在前四棒里全都存在，只是一直没跑过，所以没人知道。**

## 8. 现在能写什么

已经验证可用：

```简言
结构 点 { x: 浮点, y: 浮点 }
枚举 形状 { 圆(半径: 浮点)  矩(宽: 浮点, 高: 浮点)  点 }

函数 面积(s: 借用 形状) -> 浮点 {
    匹配 s {
        例 形状.圆(半径): { 返回 3.14159 * 半径 * 半径 }
        例 形状.矩(宽, 高): { 返回 宽 * 高 }
        例 形状.点: { 返回 0.0 }
    }
}

函数 最大[T: 可比较](甲: T, 乙: T) -> T {
    如果 甲 >> 乙 就 { 返回 甲 }
    返回 乙
}
```

- 函数、递归、泛型（单态化）、闭包（无捕获）
- `如果/否则如果/否则`、`当`、`对 在`、`匹配`
- 结构体（`新建 点{...}` 显式构造 + 按目标类型构造 + 字段读写）
- 枚举 + 模式匹配 + 字段解构
- 组：追加、插入、删除、弹出、包含、排序、反转、复制
- 映射：取、插入、删除、包含、键组、值组
- 字符串：长度、取、包含、查找、切分、替换、大小写、去空白、首尾判断
- `结果`：成功/失败，`是成功`/`取值`/`错误值`
- 通道：建、发送、接收、关

还能用（v0.6 补上的两项）：

- **模块级 `常量`**：编译期折成字面量，运行时不存在。支持字面量、四则、位运算、比较、
  字符串拼接，以及常量引用常量；非常量初值会给出明确错误，不再生成 `v-1`
- **`新建 类型{...}`**：带名字的结构体字面量，表达式位置也能写

v0.7 补上的一层（第三方库，见第 12 节）：

- **`图`**：`新建图(w, h)` / `读图(路径)` / `图.存(路径)` / `图.取` / `图.设` /
  `图.缩放` / `图.写字` / `图.量字` / `图.宽` / `图.高`
  读写 PNG/JPG/BMP/TGA，以及 SVG（保真度有限，见 `第三方/说明.md`）
- **数学 16 个**：`开方 正弦 余弦 正切 反正弦 反余弦 反正切 指数 对数 对数10
  幂 最小 最大 向下取整 向上取整 绝对值 四舍五入`，直通 libm
- **用户定义可以顶掉内置**：写自己的 `开方` 不会跟内置撞车，后端会自动让路

还不能用：

- 真并发（`线程` 块被内联）
- 接口方法的 `自身` 字段访问
- 闭包捕获外层变量
- 图片的内存回收（`简_图_放` 有，但语言层没有对应的 `释放`，图活到进程结束）

## 9. 下一步

后端已经定型，接下来两条路可以并行：

**A. 原生后端。** 把 `写指令()` 里的 `fprintf` 换成发机器码。指令选择用「模板匹配」（IR 每条指令对应一段固定机器码），寄存器分配先用朴素的线性扫描。IR 和测试都不用动。

**B. 补语言特性。** `新建` 关键字、真并发、闭包捕获——这三个都在语义/IR 层，和后端无关。

v0.6 已经把 B 里的 `新建` 和模块级常量做掉了，剩下的是真并发与闭包。

**接下来的顺序**：先把并发做真（`线程` 块现在被内联成顺序执行，通道因此不需要锁），
再做原生后端。并发放前面，是因为它会逼着 IR 长出"共享状态"这个概念，
而那正是后端做寄存器分配时最需要知道的事。

## 10. 补记：画图、动画与五个新坑

这一轮往两个方向试了语言的"出图"能力：

- **静帧**：`示例/光线.jy`（365 行）出 640×400；
- **平面**：`示例/绘图.jy`（390 行）直接吐 1200×750 的 SVG，不需要任何绘图库；
- **动画**：`示例/动画.jy`（337 行）把相机绕场景转一圈，60 帧拼成 3 秒转台。

三次都栽了跟头，记下来。

### 第 1 坑：阴影没了，球就浮起来了

第一版渲染出来的三个球像贴纸浮在半空。原因不在光照参数，在阴影公式：

```简言
-- 错的：把开方后的判别式当垂距
私有 浮点 d = 开方(判别)
如果 d << 球们[i].半径 就 {
    私有 浮点 k = 1.0 - d / 球们[i].半径
    透 = 透 * (1.0 - 0.88 * k * k)
}
```

`判别 = b² - c` 展开是 `r² - 垂距²`，开方得到的是**半弦长**，不是垂距。
于是球心正上方那条光线（最该全黑的）算出来 `k = 0`，一点遮挡都没有；
反倒是掠射光线算成了半黑。整片阴影被抹平，球自然"飘"着。

正确写法是拿半弦长本身当遮挡比例：正中穿过 ≈ 1，擦边 ≈ 0，中间连续过渡。

### 第 2 坑：环境光加白色，红球变粉球

```简言
先：色 = 底 * 漫反射 + 环境光        -- 环境光是白色，直接加
后：色 = 底 * (漫反射 + 环境光)      -- 环境光也得乘材质颜色
```

天光照在漆面上，反射出来的是漆的颜色，不是白色。加白等于给每个像素掺了一份灰，
颜色全被冲淡——这跟"调饱和度"是两件事，改参数改不回来。

### 第 3 坑：模块级常量生成了 `v-1`

```简言
常量 浮点 地 = -1.0     -- 语义检查通过，gcc 报 'v' undeclared
```

后端给变量分配 C 名字的规则是 `v<槽号>`。函数内的槽号从 0 开始，
模块级常量不在任何函数里，槽号是 -1，于是名字变成了 `v-1`。
语义层认得这个符号，后端没为它生成定义——**一个只在"真的编译一次"时才暴露的洞**。
当时只能写字面量绕开。

**v0.6 已修**：常量本来就该在编译期消失，所以不做成 C 的全局量，而是在 IR 层直接折成字面量——
`常量 整数 宽 = 640` 之后所有 `宽` 都变成 `640`，运行时根本不存在这个符号，零开销。
常量引用常量也能折（顺着符号表回去再折一遍，带 32 层深度闸）。
折不动的（比如 `常量 三 原点 = 造(0,0,0)`）现在会明确报错，并告诉你改成局部量——
比生成一份"看着像编译过了"的垃圾强得多。

### 第 4 坑：SVG 的路径填到了画框底

远山用 `山脊(...) + " L 1200 750 L 0 750 Z"` 收尾，本意是"填到现在这条线为止"。
结果三层山一路填到画框底，把整片海盖住了，船看起来停在半山腰。
改成 `L 1200 472 L 0 472 Z`（收到地平线）就对了。

这不是语言的错，但很典型：**矢量图里"闭合路径"的每一条边都在画面里，写错一条就是一块遮罩。**

### 第 5 坑：bash 不认中文变量名

出图脚本里写了 `临时=$(mktemp -d)`，bash 直接把 `临时=...` 当成命令去执行，
报 `No such file or directory`。语言本身能写中文，shell 不能。脚本里统一用英文变量名。

### 这一轮的结论

- 一门语言"能出图"，跟"能出好看的图"之间隔着：色彩空间（线性 vs sRGB）、
  色调映射（ACES 近似）、阴影的物理正确性、以及**接触阴影**这一项。
  前三个是数学，最后一个是"东西到底有没有坐在地上"的直觉。
- 2D 走 SVG 这条路几乎没有成本：不用画布、不用状态机，会打印字符串就会画图。
- 动画也没有新东西：把相机转起来，剩下的交给循环和 ffmpeg。

一键复现：`cd 后端 && bash 出图.sh`。

## 11. v0.6：补两个关键字、重画一张海报

### 11.1 模块级常量：编译期消失

上面第 3 坑的修法。两处改动：

- `折叠()` 增加 `节_名字` 分支：常量引用常量时，顺着符号表回去折它的初值；
- `降名字()` 遇到 `符_常量` 先试折叠，折得动就发一条 `常量` 指令，折不动就报错退出。

顺带把字符串拼接的折叠改对了：原先直接拼两段原文，`"简" .. "言"` 拼出 `"简""言"`。
C 恰好能过（相邻字面量自动连接），但后端的 `写字面量` 只剥最外一层引号，
屏幕上就真会多两个引号。现在先各剥一层再拼，拼完补一层。

### 11.2 `新建`：给结构体字面量一个显式的头

`点{1, 2}` 在语句开头会被拆成"名字 点 + 代码块 `{1, 2}`"。
以前只能在声明右边写 `点 p = {1, 2}`，靠左边的类型反推；表达式位置一律写不出来。

```简言
返回 新建 点{ x: 1.0, y: 2.0 }         -- 以前：语法错误
组.追加(新建 点{ 0.0, 0.0 })            -- 以前：语法错误
```

实现分四层：词法加关键字、语法产出 `节_结构字面量`、语义查字段、IR 按声明顺序排好字段值。

后端这一环有个小决定：**用指定初始化器，不用位置式**。

```c
v2 = (点){.x = v0, .y = v1};          /* 现在 */
v2 = (点){v0, v1};                     /* 以前 */
```

理由是"少给字段"这件事：位置式漏一个，后面全错位；指定式只认名字，缺的 C 自己清零。
顺带生成的 C 也更好读。

### 11.3 第 6 坑：把没返回值的函数当参数用

```简言
打印("<path d=\"")
打印(山峰(宽, 432.0, 104.0, 7, 17, 478.0))    -- 山峰 什么都不返回
打印("\" fill=\"#54395c\"/>")
```

后端老老实实把"空值"当参数打印，gcc 里那是一块没初始化的栈上垃圾，输出一个 `0`，
正好接在路径坐标后面：`L 1260 4320`。**cairosvg 读到这个点，直接死在解析里。**

查了很久才想到去看生成的 C —— 它长得完全正常，只是多了一行 `printf("%lld", v374)`。

修法不只是改这一处，而是在语义层拦住：调用实参的类型是空值、而且这个实参本身是个调用，
就报"这个调用没有返回值，不能当参数用"。这类错**只能靠编译器拦**，
因为生成的东西"看起来是对的"。

### 11.4 第 7 坑：山被画成了一团雾

用户的原话：「你没说这是山，我还以为是太阳光。」

三处叠加：

| 问题 | 原因 | 改法 |
|---|---|---|
| 看不出是山 | 峰太矮（振幅 36）、太缓（9 段铺满 1200 宽，一段 130 像素）、还被二次曲线削圆 | 振幅 92、峰数 9 但**每三座一个主峰**，峰顶用折线，肩 → 顶 → 下切 → 谷四笔 |
| 像三张透明纸 | 远山用 `opacity 0.62` 叠在天空上 | 改成不透明的实色，颜色本身就是"被大气洗过"的结果 |
| 太阳浮在山上 | 山脊是一条贯通的等高线，太阳要么全露要么全遮 | 加 `垭口(x)`：太阳左右 190 像素内把振幅压到 20%，太阳正好落在山口 |

还有一笔很便宜但很管用：**给最远那层描一条 1.2 像素的脊线**（`#ffcfae`，透明度 0.24）。
它把"这是山的轮廓"直接告诉眼睛，比堆颜色快得多。三层都描就假了，只留最远那层。

### 11.5 第 8 坑：倒影排成了一座塔

上一版 72 行，每行独立撒四段，四段的横坐标各自随机。行距用 `t*t`，
于是前二十行全挤在地平线上一两个像素里，叠成一根死亮的竖条；
每行的位置又对不上，连起来就是一座斜塔。

改法：

- 行距改成 `t*0.55 + t*t*0.45`，前段有线性成分，行距从 1.9 平滑长到 5.9；
- 每行**只画一条主光斑**，宽度随距离扩展，中心固定在太阳正下方；
- 两侧碎光从主光斑往两边推，不另起随机坐标；
- 约两成的行干脆不画（概率随距离上升到四成）——水面的反光本来就是断断续续的；
- 再加一层"山影"：山脚往下 62 像素的暗色渐变。少了这一条，山就是"站"在水上。

### 11.6 这一轮的数字

| 指标 | 数值 |
|---|---|
| 海报 SVG | 19 KB（旧版 12 KB，多了三层山和碎光） |
| 测试 | **8** 个用例（新增 常量、新建） |
| 后端 | 2022 行 |

一句话总结：**"像不像"这件事，靠的是轮廓和接触，不是颜色。**
山要有尖、有主次、有山口；倒影要有断裂、有宽度变化、有山脚的暗。
这些都不是"调参数"能补的，得改生成它的那段代码。

## 12. v0.7：把第三方 C 库接进来

这一轮没有写新语法，做的是一件更朴素的事：**别再自己造轮子了**。

在此之前，简言的运行时只有字符串、数组、映射这些"语言语义必须有"的东西。
凡是要跟外界打交道的能力——读一张 PNG、写一个 JPG、在图上写一行中文——
一样都没有。光线追踪的输出是 PPM，还得靠 ImageMagick 转；海报是 SVG，
还得靠浏览器或 cairosvg 转。**这条链子上，简言只负责前半截。**

### 12.1 拿了什么

| 库 | 做了什么 | 代码量 |
|---|---|---|
| `stb_image` | 读 PNG/JPG/BMP/TGA/GIF/PSD/HDR，统一转 RGBA8 | 27 万行 |
| `stb_image_write` | 写 PNG/JPG/BMP/TGA | 8 万行 |
| `stb_truetype` | 字体光栅化，中文没问题 | 20 万行 |
| `nanosvg` + `nanosvgrast` | 解析并栅格化 SVG | 12 万行 |

一行 C 都没重写。四十几万行成熟的、被无数项目用过的代码，直接变成语言的一部分。

### 12.2 关键决定：不要把库塞进生成的 C

`stb_image.h` 展开实现后 27 万行。如果每个 `.jy` 都带一遍，编译时间从 30 ms
涨到一秒多——而绝大多数程序根本不碰图片。

所以切成两半：

```
第三方/运行库.c  --make-->  第三方/lib简言图.a    (321 KB)
                                  ↑ 链接
生成的 .c 里只有 6 行 extern 声明
```

不碰图片的程序，那 321 KB 连进都不进二进制。这就是普通编译器的做法
（`cc1` 生成目标文件，`libc` 单独存在），只是简言把它压缩成了"一个 .a 文件"。

`简编译` 从 `/proc/self/exe` 找到自己的目录，依次试 `../第三方/`、`./`、
`./第三方/`。找不到就不链接——纯计算程序照样编，用到 `图` 时才在链接阶段报错，
错误信息里带着解法。

### 12.3 `图` 是什么类型

一个新的内置类型，C 侧是：

```c
typedef struct { int64_t 宽, 高; unsigned char *像素; } 简图;
```

**它是句柄，不是值。** 赋值和传参只搬这 24 个字节，两个变量指向同一块像素。
这跟字符串 `简字{p, n}` 是同一种做法，但有一个重要区别：

> 字符串不可变，所以共享没风险；图片可变，共享就有别名问题。

明确的选择是**让图片共享**，理由：

- 图片动辄几 MB，`私有 图 乙 = 甲` 悄悄拷一份，写起来轻松、跑起来灾难；
- 需要独立副本时显式写 `甲.缩放(宽, 高)`（那本来就要分配新内存）；
- 跟 C 生态里所有图像库的直觉一致（`stbi_load` 返回的就是裸指针）。

这条写进了内置方法的注释里，不是靠用户猜。

### 12.4 数学：一行 C 换 8.5 倍

原先 `示例/光线.jy` 里有个手写的开方：

```简言
函数 开方(x: 浮点) -> 浮点 {
    私有 浮点 猜 = x
    私有 整数 i = 0
    当 i << 32 就 { 猜 = (猜 + x / 猜) * 0.5; i = i + 1 }
    返回 猜
}
```

32 次牛顿迭代。删掉它，用内置的（直通 libm 的 `sqrt`）：

| | 640×400 × 2×2 超采样 |
|---|---|
| 手写牛顿迭代 32 次 | **0.85 秒** |
| libm `sqrt` | **0.10 秒** |

**8.5 倍**，而且输出逐字节一致（`cmp` 过）。

这就是"引第三方库"最直白的样子：不是加功能，是把一段自己写得很累、
别人写得很好的代码换掉。

接进来的数学函数一共 16 个：`开方 正弦 余弦 正切 反正弦 反余弦 反正切
指数 对数 对数10 幂 最小 最大 向下取整 向上取整 绝对值`，外加 `四舍五入`
（返回整数）。角度一律弧度。

### 12.5 第 9 坑：用户函数被内置抢了名字

加完数学函数，`make 测试` 一下挂了三个：`数组`、`泛型`、`光线`。

原因都写着 `重复定义了`——这些示例里本来就有叫 `最大`、`最小`、`开方` 的函数。

第一层修法：语义层给内置符号打标记，`占位` 时发现旧的是内置就让位。

改完再跑，还是挂。但错误变了：`fmax` 参数不够。

**真正的坑在第二层**：后端按**名字**展开内置函数，从来不检查这个名字是不是
用户自己定义的。语义层已经把符号换成了用户的，后端还在 `if (名字 == "开方") printf("sqrt")`。

> 这是最难查的一类 bug：两层各自都对，合起来行为不同。
> 源码里明明调的是自己的函数，生成的 C 里是 libm 的——两个都能跑，结果不一样。

修法是后端在展开前先问一句 `找函数(名字)`，找到了就让路。现在这条规则是：

> **用户定义永远优先于编译器自带。** 内置只是"没有用户版本时的默认实现"。

### 12.6 第 10 坑：`简果` 的载荷读到隔壁去了

`结果[T, E]` 的载荷是一块 `char *`，宽度按**存进去的那一头**算：

```c
简_果造(1, &成功值, sizeof(成功值))   /* 键宽，比如 图 = 24 字节 */
简_果造(0, &错误值, sizeof(错误值))   /* 值宽，比如 字符串 = 16 字节 */
```

取的时候按**另一头**拷：

```c
memcpy(&_r, g.p, sizeof(_r))          /* 要是 sizeof(图)，24 字节 */
```

于是 `读图()` 失败时，那 16 字节的字符串被当成 24 字节拷出去——
**多读的 8 字节是堆上相邻的内容**。

这个 bug 在 `结果[整数, 字符串]` 这种"两头一样宽"的场景里永远不出现，
一直等到 `结果[图, 字符串]`（24 vs 16）才露头。

修法：载荷固定 128 字节 `calloc`（多余部分保证是 0），取用时按
`min(载荷宽, 目标宽)` 拷。多占 112 字节，换掉一整类"结果偶尔是随机数"的悬案。

### 12.7 第 11 坑：路径不是 NUL 结尾的

`stbi_load("…")` 要 C 字符串，而简言的 `简字{p, n}` **不保证结尾有 0**——
`切分` 出来的、`取` 出来的都是原串的切片，后面紧跟着别的字节。

直接传 `.p` 会发生什么？stb 顺着缓冲区往下读，打开一个名字长得离谱的文件，
或者干脆 `ENOENT`，而源文件里看着完全正常。

修法是加一个 `简_路径()`：拷一份、补 0、用完 free。所有收路径的地方都过它。

### 12.9 别人拿到，能不能编

vendor 进仓库的唯一理由，就是"别人 clone 下来直接能编"。这一条不验证，
前面所有工作都只是本机能跑。所以最后一件事是**在干净目录里从零编一遍**。

做法是把远程仓库里的 109 个文件逐个复制到一个空目录（不带 `.git`、
不带任何 `.o` / `.a`），然后 `make`：

```bash
# 远程 blob 哈希 vs 本地文件，逐个比
gh api "repos/.../git/trees/main?recursive=1" \
  --jq '.tree[] | select(.type=="blob") | .path + " " + .sha' > 远程树.txt
while read -r 路径 哈希; do
  [ "$(git hash-object "$路径")" = "$哈希" ] || echo "异 $路径"
done < 远程树.txt

# 再把那 109 个文件铺到空目录，从零构建
cd /tmp/纯净构建/后端 && make && make 测试
```

结果：

| 检查项 | 结果 |
|---|---|
| 远程 109 个文件 vs 本地 | **109 相同，0 不同**（`git hash-object` 逐字节） |
| 空目录复制后的 `.o` / `.a` 数量 | **0**（源码干净，没有混进产物） |
| `make` | **6.97 秒**跑通，其中第三方库 3.5 秒 |
| `make 测试` | **10 通过，0 失败** |
| 重新生成的光线 / 封面 / 三张滤镜 | 与仓库内版本 **sha256 完全一致** |

最后一行值得单说：五张图的哈希一致，意味着整条链路——stb 解码、
字体栅格化、双线性缩放、PNG 编码——都是**确定性**的，没有藏时间戳、
没有随机种子、没有"这次跑出来跟上次不一样"。这在以后做回归对比时是底线，
否则"改了之后画面变没变"根本无从判断。

顺便，`第三方/*.o` 和 `第三方/*.a` 在 `.gitignore` 里，源码进仓库、
产物不进——13 MB 的仓库里，`动画.gif` 和 `动画.mp4` 占了 3.1 MB，
其余大头是源码。

### 12.10 一句话

一门语言"能不能画图"，跟"画得好不好"，中间隔着的不是语法，是**库**。

这一轮做的事情说穿了很朴素：承认 PNG 编解码不该自己写，然后把
二十年积累的东西搬进来，让 `.jy` 从"只能吐文本"变成"能读能写图片"。

代价是仓库多了 67 万行别人的代码。收益是从此不用在每一张图上，
都要先想办法把中间格式转出去。
