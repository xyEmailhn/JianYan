## 一、算术运算符补充与位运算（定稿）

本轮新增三种算术运算，并要求位运算改用符号。下面一起定。

### 1.1 算术运算符（更新）

| 运算 | 符号 | 示例 | 结果 | 说明 |
|---|---|---|---|---|
| 加 | `+` | `3 + 2` | 5 | |
| 减 | `-` | `3 - 2` | 1 | |
| 乘 | `*` | `3 * 2` | 6 | |
| 除 | `/` | `7 / 2` | 3.5 | 结果总是浮点 |
| 整除 | `//` | `7 // 2` | 3 | 只取整数商 |
| 取余 | `%` | `7 % 2` | 1 | 余数，符号随被除数 |
| 乘方 | `^` | `2 ^ 10` | 1024 | 右结合 |

规则：

- `/` 一律返回 `浮点`，即使两边都是整数。这样不会出现 C 的“整数相除悄悄丢精度”，要整数商就明确写 `//`。
- `//` 只用于 `整数`，向零取整：`7 // 2 = 3`，`-7 // 2 = -3`。
- `%` 用于 `整数` 与 `浮点`，结果符号跟随被除数（C 风格）：`-7 % 3 = -1`。恒有 `甲 == (甲 // 乙) * 乙 + 甲 % 乙`。
- `^` 右结合，优先级高于一元负号：`-2 ^ 2` 等于 `-(2 ^ 2)` 即 `-4`；`2 ^ 3 ^ 2` 等于 `2 ^ 9` 即 `512`。
- 除零：能被编译器发现就编译报错；否则运行时终止并打印位置。

> 注意：`//` 在本语言是**整除运算符**，不是注释。注释只有 `--` 和 `--[[ ]]`。

### 1.2 位运算符号（新增设计）

设计原则一句话：**与 C 冲突就重复一次，不冲突就直接沿用。**

| 运算 | C 符号 | 本语言 | 冲突原因 | 记忆法 |
|---|---|---|---|---|
| 按位与 | `&` | `&` | 无冲突 | 原样 |
| 按位或 | `\|` | `\|` | 无冲突 | 原样 |
| 按位异或 | `^` | `^^` | `^` 已是乘方 | 加一个 |
| 按位取反 | `~` | `~~` | `~` 已是范围 | 加一个 |
| 左移 | `<<` | `<<<` | `<<` 已是小于 | 加一个 |
| 右移 | `>>` | `>>>` | `>>` 已是大于 | 加一个 |

记法：**“单符号管算术和比较，双写一位就是按位”**。写过 C 的人几乎不用重新学。

示例：

```
整数 a = 5 & 3          -- 1
整数 b = 5 | 3          -- 7
整数 c = 5 ^^ 3         -- 6
整数 d = ~~5            -- -6
整数 e = 5 <<< 2        -- 20
整数 f = 5 >>> 1        -- 2

-- 取低 4 位
整数 低四位 = a & 0b1111
```

规则：

- 位运算两边必须是 `整数`，结果 `整数`。
- 移位位数必须是非负 `整数`；负数、超位宽均编译错误。
- 右移为算术右移（高位补符号位）。
- 暂不支持复合赋值（`&=` `<<<=` 等）。
- 词法按最长匹配：`~~` `^^` `<<<` `>>>` 是整体符号；要写“范围接一元”时用空格，如 `1~ ~~5`。

### 1.3 运算符优先级（全表，已重排）

| 级 | 运算符 | 结合 | 说明 |
|---|---|---|---|
| 1 | `()` `[]` `.` `->` | 左 | 后缀、成员访问 |
| 2 | `^` | 右 | 乘方，最高（高于一元负号） |
| 3 | `非` `!` `#` `~~` `-`(一元) `+`(一元) | 右 | 一元 |
| 4 | `*` `/` `//` `%` | 左 | 乘除整除取余 |
| 5 | `+` `-` | 左 | 加减 |
| 6 | `<<<` `>>>` | 左 | 移位 |
| 7 | `<<` `>>` `<=` `>=` | 左 | 大小比较 |
| 8 | `==` `!=` | 左 | 相等比较 |
| 9 | `&` | 左 | 按位与 |
| 10 | `^^` | 左 | 按位异或 |
| 11 | `\|` | 左 | 按位或 |
| 12 | `与` | 左 | 逻辑与（短路，仅布尔） |
| 13 | `或` | 左 | 逻辑或（短路，仅布尔） |
| 14 | `..` | 左 | 字符串拼接（最低，仅次赋值） |
| 15 | `=` | 右 | 赋值（仅简单赋值，无复合赋值） |

> 说明：第 58 轮 EBNF 把 `..` 放在“比较之下、加法之上”，与第 60 轮建议表放在最低不一致。这里统一为**最低（赋值之上）**，因为拼接不参与数值运算，放低更安全。

### 1.4 EBNF 增量（表达式层完整替换）

```ebnf
表达式        = 赋值表达式 ;
赋值表达式    = 拼接表达式 [ "=" 赋值表达式 ] ;
拼接表达式    = 或表达式 { ".." 或表达式 } ;
或表达式      = 与表达式 { "或" 与表达式 } ;
与表达式      = 位或表达式 { "与" 位或表达式 } ;
位或表达式    = 位异或表达式 { "|" 位异或表达式 } ;
位异或表达式  = 位与表达式 { "^^" 位与表达式 } ;
位与表达式    = 相等表达式 { "&" 相等表达式 } ;
相等表达式    = 比较表达式 { ( "==" | "!=" ) 比较表达式 } ;
比较表达式    = 移位表达式 { ( "<<" | ">>" | "<=" | ">=" ) 移位表达式 } ;
移位表达式    = 加法表达式 { ( "<<<" | ">>>" ) 加法表达式 } ;
加法表达式    = 乘法表达式 { ( "+" | "-" ) 乘法表达式 } ;
乘法表达式    = 一元表达式 { ( "*" | "/" | "//" | "%" ) 一元表达式 } ;
一元表达式    = ( "非" | "!" | "#" | "~~" | "-" | "+" ) 一元表达式 | 幂表达式 ;
幂表达式      = 后缀表达式 [ "^" 幂表达式 ] ;
后缀表达式    = 基本表达式 { 后缀 } ;
```

### 1.5 复合赋值（已定：不支持）

结论：**只保留 `=`，不提供 `+= -= *= /=` 这类复合赋值。**

理由：

| 理由 | 说明 |
|---|---|
| 与初衷冲突 | 目标是"让看不懂 C 的人也能读"，`x += 1` 正是 C 的符号噪音，`x = x + 1` 一眼可读 |
| 符号会失控 | 本轮已新增 `// ^ ^^ ~~ <<< >>>`，复合后会出现 `//=` `^=` `^^=` `<<<=` `>>>=`，其中 `^=` 与 `^^=` 几乎无法肉眼区分，`<<<=` 更是没法看 |
| 已被注释挡死 | `--` 是注释，`x--` 无法成立，说明本语言整体不走 C 的紧凑写法，复合赋值同理 |
| 零性能损失 | 编译器会把 `x = x + 1` 优化成与 `+=` 相同的机器码 |
| 少一类语法 | 编译器少一套规则，错误信息更清楚 |

作为对比，若支持则需新增的全部符号：

| 运算 | 复合写法 |
|---|---|
| `+` | `+=` |
| `-` | `-=` |
| `*` | `*=` |
| `/` | `/=` |
| `//` | `//=` |
| `%` | `%=` |
| `^` | `^=` |
| `&` | `&=` |
| `\|` | `\|=` |
| `^^` | `^^=` |
| `<<<` | `<<<=` |
| `>>>` | `>>>=` |
| `..` | `..=` |

写法对比：

```
-- 本语言：只用简单赋值
计数 = 计数 + 1
总和 = 总和 + 项
名字 = 名字 .. "!"

-- 若支持复合赋值，会变成
计数 += 1
总和 += 项
名字 ..= "!"
```

> 如果以后改主意，建议只开 4 个算术的 `+= -= *= /=`，其余一律不开；但那样会出现"为什么 `%=` 没有"的不一致，所以不值得半开。

## 二、泛型

### 2.1 设计原则

- **单态化**：编译期为每组实际类型生成专用代码，零运行时开销（与 Rust/C++ 一致）。
- 类型参数用**大写字母**惯例（`T` `U` `K` `V`），也允许中文标识符。
- 约束用**接口**表达，不引入新语法。

### 2.2 泛型函数

```
函数 最大[T: 可比较](甲: T, 乙: T) -> T {
    如果 甲 >> 乙 就 {
        返回 甲
    }
    返回 乙
}

函数 首[T](项: 数组[T]) -> 可空[T] {
    如果 #项 == 0 就 {
        返回 空
    }
    返回 项[0]
}
```

- `[T]`：类型参数列表，多个用 `,` 分隔：`[K, V]`。
- `[T: 可比较]`：约束 `T` 必须实现 `可比较` 接口。
- 多个约束：`[T: 可比较 与 可打印]`。

### 2.3 泛型结构

```
结构 对[A, B] {
    甲: A
    乙: B
}

结构 栈[T] {
    数据: 数组[T]
}

函数 main() -> 整数 {
    私有 对[整数, 字符串] p = { 1, "一" }
    私有 栈[整数] s = { {} }
    返回 0
}
```

- 构造时靠目标类型推导元素类型：`{ 1, "一" }`。
- 显式写类型参数：`对[整数, 字符串]{ 1, "一" }`。

### 2.4 泛型接口与实现

```
接口 容器[T] {
    函数 添加(项: T)
    函数 取(索引: 整数) -> 可空[T]
    函数 大小() -> 整数
}

实现 栈[T] 为 容器[T] {
    函数 添加(项: T) {
        数据.追加(项)
    }
    函数 取(索引: 整数) -> 可空[T] {
        如果 索引 << 0 或 索引 >= #数据 就 {
            返回 空
        }
        返回 数据[索引]
    }
    函数 大小() -> 整数 {
        返回 #数据
    }
}
```

### 2.5 泛型 + 借用

```
函数 打印全部[T: 可打印](项: 借用 数组[T]) {
    对 元素 在 项 {
        元素.打印()
    }
}
```

### 2.6 明确不做（v0.1）

| 特性 | 决定 |
|---|---|
| 类型特化 | 不做 |
| 关联类型 | 不做 |
| 高阶类型（泛型套泛型参数） | 不做 |
| 变协变/逆变标注 | 不做，按值语义处理 |

### 2.7 需要你定

| 问题 | 选项 | 建议 |
|---|---|---|
| 类型参数写法 | A：`[T]` 单字母；B：中文名 `[类型]`；C：都允许 | C，惯例用单字母 |
| 约束语法 | A：`[T: 接口]`；B：`[T 为 接口]` | A |
| 多约束连接 | A：`与`；B：`+` | A |
| 泛型结构构造 | A：靠推导 `{1, "a"}`；B：必须写 `对[整数,字符串]{...}` | A，复杂时再显式 |

## 三、接口进阶

### 3.1 默认方法

接口可以带函数体，实现者可覆盖也可继承：

```
接口 可打印 {
    函数 打印() -> 字符串

    函数 打印行() {
        io.打印行(打印())
    }
}

实现 点 为 可打印 {
    函数 打印() -> 字符串 {
        返回 "(" .. 字符串(x) .. ", " .. 字符串(y) .. ")"
    }
    -- 打印行 直接继承默认实现
}
```

### 3.2 接口继承

```
接口 可比较 {
    函数 比较(其他: 借用 自身) -> 整数
}

接口 可排序 继承 可比较 {
    函数 排序() 
}

实现 点 为 可排序 {
    函数 比较(其他: 借用 点) -> 整数 { ... }
    函数 排序() { ... }
}
```

- `自身`：接口方法中代表实现类型的占位类型。
- 接口不能有字段；需要状态时用 getter 函数。

### 3.3 多接口实现

```
接口 可打印 { 函数 打印() -> 字符串 }
接口 可比较 { 函数 比较(其他: 借用 自身) -> 整数 }

实现 点 为 可打印, 可比较 {
    函数 打印() -> 字符串 { 返回 "点" }
    函数 比较(其他: 借用 点) -> 整数 { 返回 0 }
}
```

### 3.4 静态分发优先

- 泛型约束 `[T: 可打印]` 走**单态化**，编译期确定调用，零开销。
- 动态分发（虚表）v0.1 不默认开放，需要时写 `动态[接口]`，后续再定。
- 理由：保持"性能不差"的初衷，避免隐式虚调用拖慢热路径。

### 3.5 需要你定

| 问题 | 选项 | 建议 |
|---|---|---|
| 默认方法 | A：支持；B：不支持 | A |
| 接口继承关键字 | A：`继承`；B：`为` | A |
| `自身` 类型 | A：用 `自身`；B：用 `Self` | A |
| 动态分发 | A：v0.1 不做；B：提供 `动态[接口]` | A，先静态 |
| 接口能否有常量 | A：可以；B：不可以 | A，允许常量 |

## 四、函数值与闭包

### 4.1 函数类型（已定）

```
函数(整数, 整数) -> 整数
函数() -> 空值
函数(字符串)
```

### 4.2 函数作为参数与返回值

```
函数 应用(值: 整数, 变换: 函数(整数) -> 整数) -> 整数 {
    返回 变换(值)
}

函数 加倍(x: 整数) -> 整数 = x * 2

函数 main() -> 整数 {
    私有 整数 r = 应用(5, 加倍)     -- 10
    返回 0
}
```

### 4.3 匿名函数

```
私有 函数(整数) -> 整数 平方 = 函数(x: 整数) -> 整数 {
    返回 x * x
}

-- 表达式体简写
私有 函数(整数) -> 整数 三倍 = 函数(x: 整数) -> 整数 = x * 3
```

- 统一用 `函数(参数) -> 类型 { 块 }`，不引入 `|x|` 之类符号，保持可读。
- 参数类型可省略，由目标函数类型推导：`函数(x) -> 整数 = x * 3`。

### 4.4 闭包捕获

```
函数 计数工厂() -> 函数() -> 整数 {
    私有 整数 计数 = 0
    返回 函数() -> 整数 {
        计数 = 计数 + 1
        返回 计数
    }
}
```

捕获规则：

| 场景 | 默认行为 |
|---|---|
| 只读使用外部变量 | 按 `借用` 捕获 |
| 修改外部变量 | 按 `可变借用` 捕获，要求外层变量可变且无其他借用 |
| 需要把外部值带进闭包长期持有 | 显式写 `移动` 前缀 |

```
私有 字符串 名字 = "张三"
私有 函数() -> 字符串 取 = 移动 函数() -> 字符串 {
    返回 名字        -- 名字 所有权移入闭包，外部不可再用
}
```

### 4.5 与线程的关系

- `线程 { ... }` 块内不能借用外部变量（已定）。
- 闭包要跨线程，必须 `移动` 捕获，满足"移动或复制"规则。

### 4.6 需要你定

| 问题 | 选项 | 建议 |
|---|---|---|
| 匿名函数关键字 | A：`函数`；B：`函`；C：`lambda` | A |
| 参数类型省略 | A：允许推导；B：必须写 | A |
| 捕获默认 | A：借用优先，需持有时 `移动`；B：一律移动 | A |
| 闭包能否递归 | A：不能，需命名函数；B：支持 `自身` 引用 | A |

## 五、模块、可见性与包管理

### 5.1 现状与冲突

已定：`模块` 声明、`引入`、`导出`、顶层声明即全局跨模块可读写、局部必须 `私有`。

存在一处冗余：既然"顶层即公开"，`导出 标识符` 就重复了。建议这样收口：

| 语法 | 含义 |
|---|---|
| 顶层声明 | 默认**公开**，其他模块可访问 |
| `私有 函数/结构/...` | 仅本模块可见（与局部变量 `私有` 同一关键字，语义一致） |
| `导出` | 保留，仅用于**重导出**别的模块符号（`导出 数学.向量`） |

### 5.2 引入的三种写法

```
引入 std.io                          -- 整模块，用 io.打印 调用
引入 std.io 为 输出                  -- 别名
引入 std.io{打印, 读取行}            -- 选择性引入，直接用 打印(...)
引入 数学.向量 为 向量               -- 子模块
```

- 模块路径用 `.` 分隔，对应目录层级。
- 禁止循环依赖，编译器报错并给出环路径。

### 5.3 项目结构

```
我的项目/
  包.toml
  源/
    主.简
    数学/
      向量.简
    测试/
      向量_测试.简
```

`包.toml`：

```toml
名称 = "我的项目"
版本 = "0.1.0"
作者 = ["张三"]
入口 = "源/主.简"

[依赖]
绘图 = "1.2.0"
网络 = "0.3"
```

### 5.4 包管理命令

## 七、执行模型与工具链

### 7.1 编译流水线

```
源码(.简)
  → 词法分析（Token）
  → 语法分析（AST）
  → 语义分析（类型检查 / 借用检查 / 穷尽检查 / 可见性检查）
  → 中间表示（IR）
  → 优化（常量折叠 / 内联 / 死代码消除）
  → 后端（解释 / 字节码 / 原生）
```

### 7.2 后端路线（分阶段，先跑通再提速）

| 阶段 | 后端 | 目的 | 性能 |
|---|---|---|---|
| v0.1 | 树遍历解释器 | 最快验证语法与语义 | 慢，仅供开发 |
| v0.2 | 字节码 VM + IR 优化 | 可用的日常运行 | 中 |
| v1.0 | LLVM 原生编译 | 正式发布，接近 C | 高 |

- 内存释放：语义分析后**编译期插入释放点**，等价手动 `释放`，无 GC 停顿。
- 借用检查：纯编译期，运行时不带任何检查开销。
- 单态化泛型：编译期展开，无虚表、无装箱。

解释器慢不影响最终性能，它只是开发期工具；正式版走 LLVM。

### 7.3 代码风格规范（格式化器强制）

| 项目 | 规则 |
|---|---|
| 缩进 | 4 个空格 |
| 块 | `{` 与语句同行，`}` 单独一行 |
| 运算符 | 二元运算符两侧各一个空格 |
| 逗号 | 后跟一个空格 |
| 空行 | 函数/结构之间空一行 |
| 行宽 | 建议 100 字符 |

## 十、与 C 互操作（FFI）

### 10.1 前提

指针"暂不设计"，所以 FFI 只能先支持**基本类型 + 不透明句柄**，不做裸指针解引用。

### 10.2 外部函数声明

```
外部 函数 系统打印(格式: 字符串) -> 整数

函数 main() -> 整数 {
    不安全 {
        系统打印("你好\n")
    }
    返回 0
}
```

- `外部 函数`：声明一个 C ABI 函数，不做函数体。
- 调用外部函数必须包在 `不安全 { ... }` 中，显式标注风险。
- 外部函数名默认按原样链接；需要改名用 `外部 函数 打印 为 "printf"`。

### 10.3 不透明句柄

```
外部 类型 文件句柄

外部 函数 打开(路径: 字符串) -> 可空[文件句柄]
外部 函数 关闭(句柄: 文件句柄) -> 整数
```

- `外部 类型` 是不透明类型，只能传递，不能解引用、不能运算。
- 等指针模型设计完成后再开放更多能力。

### 10.4 类型映射

| 简言 | C |
|---|---|
| `整数` | `int64_t`（平台相关，见下） |
| `浮点` | `double` |
| `布尔值` | `int`（0/1） |
| `字符串` | `const char*`（只读传入） |
| `外部 类型 X` | `void*` |

> 整数位宽需要单独定：是固定 64 位，还是按平台 `int`？建议**固定 64 位**，可移植性更好，和 C 交互时显式转换。

### 10.5 需要你定

| 问题 | 选项 | 建议 |
|---|---|---|
| 外部函数 | A：`外部 函数`；B：`外部` 修饰普通函数 | A |
| 不安全块 | A：必须包；B：不强制 | A |
| 整数位宽 | A：固定 64 位；B：平台相关；C：提供 `整数32/整数64` | C，默认 64 |
| 外部类型 | A：支持不透明句柄；B：暂不支持 | A |
| C 头文件自动生成绑定 | A：v0.3 做；B：不做 | A |

## 十二、待你拍板的清单（按优先级）

**P0 会卡住编译器的：**

1. 泛型约束语法：`[T: 接口]` 你的选择
2. 整数位宽：固定 64 位还是提供 `整数32/整数64`
3. 顶层默认可见性：公开 + `私有` 收窄
4. 标准库函数命名：中文
5. 匿名函数写法：`函数(x) -> 整数 { ... }`

**已定（本轮确认）：** `/` 一律返回浮点；位运算符号 `^^ ~~ <<< >>>`；不支持复合赋值 `+=` 等。

6. `%` 负数取余符号随被除数（C 风格，建议是）

8. 闭包捕获默认：借用优先
9. 配置文件：`包.toml`
10. 测试语法：`测试 "名" {}`
11. 宏参数占位：`$名`

12. 动态分发 `动态[接口]`
