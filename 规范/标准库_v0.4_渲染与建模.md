# 简言标准库 v0.4 · 渲染与建模（可运行版）

> v0.3 把渲染**设计**出来了：2D 的变换栈、裁剪、渐变、布尔路径，3D 的光栅管线、阴影、骨骼。
> 但那一版只有设计，没有一行能跑。
>
> v0.4 换了个目标：**让 AI 写二十行字，就能出一张能用的图和一份能用的模型。**
> 所以这一版交付的不是接口表，是一个真能跑的渲染器 `简渲`：
> 读一个场景文件，出 PNG，顺便把同一个场景导出成 `.obj` / `.glb`。

---

## 一、这一版改了什么

| | v0.3 | v0.4 |
|---|---|---|
| 形态 | 接口设计 | **可执行的参考实现**（C99，无依赖） |
| 几何 | 三角形网格 + 光栅 | **符号距离场 + 光线追踪**，一句话组合形状 |
| 光照 | 平行光阴影贴图 | **面光源 + 软阴影 + 环境光遮蔽 + 反射/折射** |
| 输出 | 设计里有 PNG | 自己写 PNG 编码（LZ77 + 固定哈夫曼），不链接 zlib |
| 模型 | 只能读 OBJ/GLB | **能写**：距离场 → 三角网格 → `.obj` / `.glb` |
| 面向谁 | 会写代码的人 | **AI**：场景文件是自然语言级别的短句 |

一句话：v0.3 回答"渲染应该有什么"，v0.4 回答"渲染怎么写出来、怎么让 AI 用得上"。

## 二、四条原则

前三条沿用，第四条是这一版新加的。

| 原则 | 在渲染里具体指什么 |
|---|---|
| **零依赖** | 数学、噪声、PNG、OBJ、GLB 全部自己写；只链接 `libm` 和 `libpthread` |
| **零拷贝** | 像素只有一份 HDR 缓冲，成像时就地转 8 位；网格顶点直接进 VBO 格式的二进制 |
| **错误不外抛** | 场景写错一行只警告、跳过，不中止整张图 |
| **默认值即审美** | 所有参数都有"好看"的默认值，AI 只写差异 |

第四条值得展开。

### 默认值即审美

一个渲染器难用，往往不是功能少，而是**默认值难看**：默认黑背景、默认硬阴影、默认 16 采样噪点满屏。
AI 不知道该怎么调，人也懒得调，最后出来一张"程序员美术"。

所以这一版把审美写进默认值：

| 参数 | 默认 | 为什么 |
|---|---|---|
| 材质 | 白瓷（粗糙 0.24） | 白瓷能同时显示明暗、高光、环境色，最适合当"什么都没说" |
| 相机 | 按所有物体的包围盒自动取景 | AI 只写物体，不该还要算机位 |
| 天空 | 天顶蓝 / 地平白 / 地面灰三段渐变 | 比纯色背景多一层空气感，比 HDR 贴图省 40 MB |
| 曝光 | 1.0 + ACES 曲线 | 高光滚降，不会一过曝就死白 |
| 泛光 | 0.05 | 一点点就够，多了像劣质滤镜 |
| 暗角 | 0.20 | 把视线压向中心 |
| 采样 | 128 | 4 核约两分钟一张 900×560，噪点基本看不见 |
| 环境光 | 0.8 倍天空 | 有环境光才有"缝隙里的暗"，纯直射光会很假 |

这七条合起来，**一个只写了三行物体的场景，出来也是一张能发朋友圈的图**。

## 三、场景文件：空格版函数调用

场景文件不是 JSON，不是 YAML，不是自定义 DSL。它就是**去掉括号和冒号的简言函数调用**：

```简言
球(位置: (0, 0.8, 0), 半径: 0.8, 材质: "金")
```

写成：

```
球 (0, 0.8, 0) 0.8 材质 金
```

三条规矩：

1. **键可以省**。`球 位置 (0,0,0) 半径 0.5` 和 `球 (0,0,0) 0.5` 等价。
2. **键可以换序**。参数按名字找，不按位置。
3. **一行一个东西**。删一行不影响别的行，改一行不会连锁报错。

### 为什么不用 JSON

```json
{ "type": "sphere", "position": [0, 0.8, 0], "radius": 0.8, "material": "gold" }
```

- 三个引号、两个方括号、一个冒号、一个逗号——AI 少写一个就整份文件报错；
- 嵌套一层（`"light": { "type": "area", ... }`）就没人愿意手写了；
- 注释还得靠约定。

场景文件里，上面那行是：

```
球 (0, 0.8, 0) 0.8 材质 金
```

少了 60% 的字符，而且**读出来就是一句话**。这对 AI 很重要：它生成的是 token，越短越不容易错。

### 为什么不用 YAML

YAML 的缩进是语义。AI 少打两个空格，`光` 就变成了 `球` 的子节点，报错还看不懂。

### 支持的命令

```
尺寸 900 560                  分辨率
采样 128                      每像素样本数
曝光 1.0                      整体亮度
泛光 0.06 暗角 0.25 颗粒 0.006  后处理
天空 天顶 (…) 地平 (…) 地面 (…) 强度 0.8
雾 密度 0.007 颜色 (…)
输出 成品.png

相机 位置 (…) 看向 (…) 视场 34 光圈 0.035 焦距 4.3

材质 名字 颜色 (…) 粗糙 0.3 金属 0 透射 0 折射率 1.5 纹理 木纹 尺度 1 发光 (…)

球     位置 半径 材质
盒     位置 大小 圆角 材质
圆柱   位置 半径 高 圆角 材质
圆环   位置 半径 管径 材质
胶囊   位置 半径 高 材质
平面   位置 法线 材质
地面   位置 材质                    （= 法线朝上的平面）

光 面   位置 大小 看向 强度 颜色
光 球   位置 半径 强度 颜色
光 太阳 方向 角度 强度 颜色

差 目标 / 交 目标 / 并 目标 / 平滑并 目标 0.1    几何布尔运算
名字 甲                                          给物体起名，供布尔引用
导出 模型.obj                                     顺便导出网格
```

数字可以带小数点，也可以不带。颜色可以写 `(0.9, 0.4, 0.3)`、`#E0664A`，或者直接写材质名（取它的基色）。

### 布尔运算：AI 造复杂形状的关键

一个物体 = 一棵形状树。第二行可以拿第一行的名字做减、交、并：

```
圆柱 (0, 0.5, 0) 半径 0.4 高 0.5 材质 白瓷 名字 筒
圆柱 (0, 0.6, 0) 半径 0.3 高 0.6 材质 白瓷 差 筒        -- 掏空
盒   (0, 0.35, 0) 大小 (0.5, 0.1, 0.05) 材质 白瓷 差 筒  -- 开槽
球   (0, 1.05, 0) 半径 0.2 材质 白瓷 平滑并 筒 0.08      -- 顶部圆角过渡
```

四行出来一个带槽的空心杯。用三角形写，这是几百行顶点数据。

**平滑并**（`平滑并 目标 k`）是最有用的一个：它在两个形状交界处自动长出半径 `k` 的圆角。
真实产品没有绝对锐利的边，加 0.02~0.08 的平滑并，质感立刻从"塑料玩具"变成"工业设计"。

## 四、几何：为什么用距离场，不用三角形

v0.3 设计的是三角形光栅管线：裁剪 → 透视除法 → 背面剔除 → 扫描线 → 深度测试 → 透视校正。
这一版实现时换了路线，理由要说清楚。

### 距离场是什么

每个形状不存顶点，存一个函数：**给我一个点，告诉我它到表面有多远**（里面为负）。

```
球     距(p) = |p - 球心| - 半径
盒     距(p) = |max(|p-c| - 半, 0)| + min(max(...), 0) - 圆角
并集   min(a, b)
差集   max(a, -b)
交集   max(a, b)
平滑并 mix(a, b, k)                    ← 交界处自动圆角
```

### 五条理由

| | 三角形 | 距离场 |
|---|---|---|
| 球要多少数据 | 512 顶点 / 1024 面 | 4 个数 |
| 圆角 | 手工倒角或细分建模 | 减一个数 |
| 开孔、挖槽 | 布尔建模器（几万行） | `max(a, -b)` |
| 法线 | 顶点法线平均，硬边要拆点 | 梯度，天然光滑 |
| 软阴影 | 阴影贴图 + PCF | 距离场直接估半影 |
| 环境光遮蔽 | SSAO（噪声大） | 沿法线探 6 次 |
| 反射/折射 | 另一个渲染目标 | 再发一条射线 |
| 代码量 | 约 1200 行 | 约 400 行 |
| 速度 | 快 | **慢 3~10 倍** |

最后一行是代价，不掩饰。

**为什么还是选它**：这一版的目标是"AI 二十行出一个模型"。
让 AI 生成三角形数据是不可能的（它会编出不存在的顶点索引）；让 AI 写 `球 差 盒 平滑并 0.05` 是可能的。
速度用多线程和采样数补：4 核、128 采样、900×560，两分钟一张，够用。

**三角形管线不做吗**：做，但排在后面。等后端能编译简言、能加载 GLB 之后，
静态网格走光栅、程序化形状走距离场，两条路并存。这一版先把"能出图"这件事做实。

### 球追踪

求交不解方程，一步步走：每步把"当前位置到最近表面的距离"当作安全步长。

```c
float t = 0.0015;
for (int i = 0; i < 160; i++) {
    float d = 场距(p + 向 * t);
    if (d < 阈值) return t;          // 到表面了
    t += max(d * 0.9, 阈值);
}
```

因为距离是**保守下界**，跨这么大绝不会穿模。平均 30 步收敛，比盲目细步快一个数量级。

**内部求交**要单独处理：从玻璃内部出发时距离场是负的，普通球追踪会在起点就"命中"，
结果是折射进玻璃后一路递归到深度上限、返回黑色（这个 bug 我踩了）。
内部改用 `-距离` 当步长——它正好是"到内壁还有多远"。

## 五、光照：四条线

一个像素的颜色 = 直接光 + 环境 + 反射 + 折射 + 自发光 + 雾。

### 5.1 直接光：面光源 + 软阴影

每个光源每个样本采一个点，判可见，累加漫反射和 GGX 高光。

面光源的价值在于**软阴影**：光源越大，半影越宽。产品图的柔光箱就是这个原理。
点光源出来的阴影边缘像刀切，一眼假。

阴影不用阴影贴图，用距离场的半影估计：

```c
可 = min(可, k * 距离 / 已走距离);
```

`距离/已走距离` 就是"遮挡物离这条射线有多近"，天然给出半影渐变。**软阴影几乎是白送的。**

### 5.2 环境光：天空渐变 × AO

天空是一个三段渐变（天顶 / 地平 / 地面），当一个大光源用。

环境光遮蔽（AO）沿法线往外探 6 次，看周围有多挤：

```c
for (i = 0; i < 6; i++) {
    h = 0.02 + 0.20 * i / 5;
    累 += (h - 场距(p + n * h)) * 权;
}
return 1 - 4.6 * 累;
```

墙角、缝隙、物体接触面会自然变暗。**这是"落地感"的唯一来源**——没有 AO，球看起来是浮在桌面上的贴纸。

### 5.3 反射：按粗糙度分两条路

- 粗糙度 < 0.5、或者金属、或者玻璃：**追一条反射线**，方向按粗糙度抖动（磨砂金属）。
- 其他：用天空近似，不追线。

为什么分：模糊反射的方差极大，32 个样本压不住，画面会像撒了盐。
粗糙表面用天空近似，视觉上几乎没差别，噪点直接归零。

菲涅尔也不能照抄公式。真实公式在掠射角趋近 1（全反射），但那是对**光学平面**说的；
粗糙表面的微观朝向随机，掠射角的"全反射"被平均掉了。不修这一步，地面在远处会变成一面镜子，看着像水面。

### 5.4 折射：玻璃

Fresnel 决定这一条射线是反射还是折射，随机选，多次采样平均。

两个坑：

1. **折射率要分进出**：空气→玻璃用 `1/n`，玻璃→空气用 `n`。弄反会全反射，玻璃球变成黑球。
2. **内部要走内部求交**：见上一节。

玻璃内部按 Beer-Lambert 吸收一点红光，厚处偏青——这是"体感"的来源。

### 5.5 灯是几何，但不在画面里显形

反射线打到面光源，要能看见柔光箱的方形高光——金属球没有这个就是死灰。

但主视线直接看到灯时，要**穿过去**：否则画面里挂一块白板。

规则：`深 == 0`（主视线）忽略灯，`深 > 0`（反射/折射）把灯当发光体。

## 六、速度从哪来

这一版做了十件事，按收益排序：

| # | 手段 | 效果 |
|---|---|---|
| 1 | **多线程行带分块** | 4 核 ≈ 3.8×（块大小 = 高/(线程×4)，负载均衡） |
| 2 | **球追踪大步长** | 平均 30 步，比固定细步快 8× |
| 3 | **粗糙度分流**（>0.5 不追反射） | 噪点降一个数量级，同时省 20~30% 时间 |
| 4 | **光源采样（NEE）** 而不是等路径撞灯 | 方差降 10×，同样采样数干净得多 |
| 5 | **距离场软阴影** 而不是阴影贴图 | 省一遍渲染 + 省 16 MB 显存 |
| 6 | **早停**：`t > 400` 直接算天空 | 天空像素省 160 步 |
| 7 | **bloom 降采样 4×** | 后处理从 O(像素×核) 降到 1/16 |
| 8 | **位运算哈希噪声** | 不用采样纹理，无 cache miss |
| 9 | **PNG 用 Paeth 自适应过滤** | 比固定 Sub 小 15%，解码还快 |
| 10 | **`-ffast-math` + `-march=native`** | 向量化，1.3× |

### 实测

900×560 / 128 采样 / 4 核（AMD EPYC，容器限额 4 核）：

| 场景 | 物体数 | 时间 |
|---|---|---|
| 静物（3 球 + 台面 + 3 灯） | 5 | ~2 分 10 秒 |
| 小岛（10 个物体 + 水面镜面） | 10 | ~3 分 40 秒 |
| 材质（4 球 + 玻璃折射） | 5 | ~2 分 30 秒 |
| 几何（7 物体 + 太阳） | 7 | ~1 分 50 秒 |

320×200 / 16 采样预览：**0.7 秒**。调构图时用这个，别等两分钟。

模型导出（96 精度）：**0.4 秒**，15.5 万三角形。

二进制体积：**约 90 KB**（`-O3 -s` 动态链接），musl 静态约 110 KB。

## 七、成像：从 HDR 到 PNG

顺序不能换：

```
HDR 缓冲
  ↓ 泛光：提亮部 → 1/4 分辨率 → 两次高斯 → 叠回
  ↓ 曝光
  ↓ 暗角
  ↓ ACES 色调映射        ← 高光滚降，不过曝
  ↓ sRGB 伽马
  ↓ 颗粒（确定性哈希，同一坐标两次渲染一致）
8 位 RGB
```

**为什么在色调映射之后做泛光会毁图**：亮部已经被压到 1.0，泛光提取不到东西，只会让画面整体发灰。

**为什么用 ACES 不用 Reinhard**：Reinhard 把高光压得太狠，金属高光会变成一片糊；
ACES 保留了高光的"白里透色"，这是电影调色的基础。

### PNG 编码

自己写，不链接 zlib：

```
像素 → 每行试 5 种过滤器选最优（None/Sub/Up/Average/Paeth）
     → LZ77（32 KB 窗口，哈希链，最多 48 步）
     → 固定哈夫曼
     → zlib 包装（0x78 0x01 + adler32）
     → IHDR / IDAT / IEND
```

固定哈夫曼比动态哈夫曼少 200 行代码，压缩率差 5%。对渲染图（大片平滑渐变）几乎看不出来。

900×560 的图，PNG 约 400~700 KB。

## 八、建模：从距离场到三角网格

渲染是 3D → 2D；导出是反方向：距离场 → 三角网格。

用 **marching tetrahedra**，不用 marching cubes：

- cubes 要一张 256 项的大表，抄错一项就破面；
- tetrahedra 只有 6 种剖分，交点连法可以现算，代码短一半，不会破面。

```
空间切成立方体 → 每个立方体拆 6 个四面体 →
四面体四角的内外号不同就说明表面穿过它 →
在穿过的边上线性插值出交点 → 连成三角形
```

三个细节：

1. **导出时要摘掉平面**。平面把整个下半空间都算作实体，留着它，水面以下的岩石全被挖掉，模型只剩一张薄片。
2. **顶点要去重**。同一个格子里的 6 个四面体共享边，不去重顶点数是三倍，文件大三倍。用一个 24 项的局部小表就能解决。
3. **朝向要统一**。三角形法线要和距离场梯度同向，否则模型在 Blender 里是"里外翻的"。

导出两种格式：

| | 用途 | 大小 |
|---|---|---|
| `.obj` + `.mtl` | Blender / C4D / 任何建模软件 | 大（文本） |
| `.glb` | Three.js / Unity / 网页 | 小（二进制） |

```sh
./简渲 示例/小岛.scene -模型 出图/小岛
# 导出 188665 顶点 / 155612 三角形 → 出图/小岛.obj、出图/小岛.glb
```

同一个场景文件，**出图**和**出模型**两条出口。这就是"AI 做一个 3D 模型"的完整闭环：
写场景 → 看预览 → 改两行 → 导出 GLB → 拖进引擎。

## 九、简言里的写法

场景文件是给"还没有编译器"的阶段用的。等后端做完，同一套能力在简言里长这样：

```简言
引入 std.渲染

函数 主() -> 结果[空, 渲染.错误] {
    私有 渲染.场景 台 = 渲染.场景.新建()
    台.尺寸(900, 560)
    台.采样(128)
    台.天空.三段(天顶: 颜色(0.30, 0.50, 0.84), 地平: 颜色(0.80, 0.87, 0.95), 强度: 0.8)

    台.球(位置: {0.0, 0.85, 0.0}, 半径: 0.85, 材质: 渲染.材质.白瓷)
    台.球(位置: {-1.3, 0.45, 0.7}, 半径: 0.45, 材质: 渲染.材质.珊瑚)
    台.平面(位置: {0.0, 0.0, 0.0}, 材质: 渲染.材质.木)

    台.光.面(位置: {2.4, 3.2, 2.0}, 大小: {1.4, 1.0},
              看向: {0.0, 0.8, 0.0}, 强度: 24.0, 颜色: 颜色(1.0, 0.97, 0.92))

    私有 渲染.图 成 = 渲染.快照(台)?
    成.存PNG("成品.png")?
    返回 成功(空)
}
```

一行版（场景参数全用默认值，只给差异）：

```简言
渲染.快照("场景.scene")?.存PNG("成品.png")?
```

导出模型：

```简言
私有 三维.网格 模 = 渲染.提取网格(台, 精度: 96)?
三维.存GLB("模型.glb", 模)?
```

**为什么参数名和场景文件一模一样**：一份 API，两种写法。
`位置`、`半径`、`材质`、`强度`——场景文件里叫什么，代码里就叫什么。
AI 学会了场景文件，就学会了 API；反过来也一样。

## 十、四个配方

`渲染/示例/` 下有四个场景，每个二十行左右，覆盖四种典型需求。

### 10.1 静物（产品图）

``` 
-- 产品静物：无缝背景 + 三个材质对比
尺寸 900 560
采样 128
天空 天顶 (0.44,0.53,0.66) 地平 (0.88,0.86,0.84) 地面 (0.58,0.55,0.53) 强度 0.55

相机 位置 (0.85, 1.55, 4.60) 看向 (0, 0.72, 0) 视场 33

盒 (0, -0.12, 0) 大小 (5.0, 0.12, 5.0) 圆角 0.05 材质 哑光白 名字 台面
盒 (0, 3.00, -1.90) 大小 (7.0, 5.00, 0.35) 圆角 0.35 材质 哑光白 平滑并 台面 2.60

圆柱 (0, 0.42, 0) 半径 0.46 高 0.42 圆角 0.02 材质 大理石 名字 柱
球 (0, 1.32, 0) 半径 0.60 材质 白瓷
球 (1.02, 0.26, 0.42) 半径 0.26 材质 金
球 (-0.92, 0.24, 0.55) 半径 0.24 材质 墨黑

光 面 (1.9, 2.7, 1.9) 大小 (1.4, 1.8) 看向 (0, 0.9, 0) 强度 26 颜色 (1.0,0.96,0.90)
光 面 (-2.4, 1.7, 1.1) 大小 (0.7, 1.8) 看向 (0, 0.8, 0) 强度 3.0 颜色 (0.74,0.84,1.0)
```

要学的三个点：

- **无缝背景** = 台面和背墙用 `平滑并 2.6` 缝起来，墙脚长出 2.6 的圆角；
- **主光 + 补光 + 轮廓光** 三层：主光 26（右后）、补光 3（左侧冷调）、轮廓光 7（背后，把主体从背景里"抠"出来）；
- **三个物体三个材质**：白瓷（漫反射为主）、金（纯反射）、墨黑（吃光），一眼看出材质差异。

### 10.2 小岛（程序化建模）

```
盒   (0, 0.02, 0) 大小 (1.10, 0.14, 0.92) 圆角 0.22 材质 草地 名字 岛
球   (0, -0.62, 0) 半径 0.95 材质 岩石 平滑并 岛 0.25
圆柱 (-0.42, 0.50, -0.06) 半径 0.155 高 0.34 材质 白瓷 名字 塔
圆柱 (-0.42, 0.86, -0.06) 半径 0.20 高 0.035 材质 红漆
球   (-0.42, 1.10, -0.06) 半径 0.11 材质 荧光
平面 (0, 0, 0) 材质 水面
```

要学的三个点：

- **平滑并造岛**：盒子 + 球，`平滑并 0.25`，岛底自然过渡成礁石；
- **水面是金属材质**：`水面` 不是透射材质，是金属度 0.92 + 粗糙 0.03，反射天空；再加 `波纹` 法线扰动，倒影碎成粼光；
- **同一个场景能导出模型**：`-模型` 直接出 GLB。

### 10.3 材质（玻璃与金属）

四种材质同台：玻璃（透射 1.0）、铬（金属 1.0 + 粗糙 0.02）、金、磨砂玻璃（透射 1.0 + 粗糙 0.18）。

要学的点：**浅色背景 + 深色台面**。玻璃需要背景有内容才看得见折射；深色台面托住金属的暗部。

### 10.4 几何（粉彩插画）

等距视角 + 低饱和配色 + 大面光。要点：

- **长焦远机位**（视场 28，距离 5）压缩透视，接近正交；
- **颜色饱和度压到 0.6 左右**，太纯会像塑料玩具；
- **阴影要软**：太阳角度 4.5°，半影明显。

## 十一、AI 怎么用它

这一版是照着"AI 写、AI 改"的流程设计的。

### 流程

```
1. AI 读需求 → 写 20 行 .scene
2. 简渲 -预览        （320×200，0.7 秒）
3. 看一眼构图对不对
4. 改一两行（机位 / 光强 / 材质）
5. 简渲 正式出图      （128 采样，两分钟）
6. 要模型就 -模型
```

第 2 步是关键：**0.7 秒的预览**让"改一行看一眼"成为可能。等两分钟再看，就没法迭代了。

### AI 容易犯的四个错，工具要接住

| AI 常犯 | 工具怎么办 |
|---|---|
| 参数名拼错 | 未知键当位置参数，不报错 |
| 材质名不存在 | 警告 + 退回白瓷，继续渲 |
| 布尔目标名字打错 | 警告 + 忽略这一行，其他照渲 |
| 忘了写相机 | 按包围盒自动取景 |

原则：**一行错不该毁掉整张图**。这一点和词法器"出一次错跳到行尾"是同一个思路。

### 常用改法

| 想要 | 改哪里 |
|---|---|
| 更亮 | `曝光` +0.15 |
| 更"高级" | 降低环境光、加大主光与补光比例 |
| 更柔和 | 加大面光尺寸（阴影变软） |
| 主体更突出 | 加一盏背后的轮廓光 |
| 背景更干净 | `雾 密度` 降到 0.003，或换纯色天空 |
| 材质更真 | 加 `圆角 0.02`，所有锐边都该有一点圆角 |
| 镜头感 | `光圈 0.03 焦距 <到主体距离>` |

## 十二、明确不做

诚实列清楚，免得后面反复解释。

| 不做 | 原因 |
|---|---|
| 路径追踪全局光照 | 噪点大、收敛慢，产品图要的是干净不是物理全对 |
| 体积云 / 烟 | 需要参与介质积分，代码翻倍，收益有限 |
| 骨骼动画 | v0.3 设计了，这一版没实现（没有蒙皮矩阵，也没有动画采样） |
| 贴图加载（PNG/JPG 作为材质） | 要写解码器，先让程序化纹理顶上 |
| 三角形网格渲染 | 只做导出，不做输入。静态网格走光栅是下一版的事 |
| GPU 后端 | 先保证"没有显卡也能出图" |
| 运动模糊 / 景深散景形状 | 有景深，但没有六边形散景；产品图用不上 |
| 色彩管理（ICC） | 只做 sRGB，不做广色域 |
