# 简言标准库 v0.3 · 渲染（3D 与增强 2D）

> v0.2 的渲染只到"能画线、能填色、能写字"。
> v0.3 要它能做两件真事：**画三维场景**，和**把二维当画布一样自由操作**。

---

## 一、这一版改了什么

v0.2 的 2D 是一支笔：`移到`、`画到`、`填充`。够画图表，不够做界面。

v0.3 的 2D 变成一个**可组合的绘图系统**：

- 有变换栈，能整体缩放旋转；
- 有裁剪栈，能在圆角里画东西；
- 有渐变、图案、混合模式；
- 描边能调宽度、端点、拐角、虚线；
- 路径能求并、交、差；
- 有图层和组透明度；
- 文字能排版（字距、行距、对齐、换行）。

3D 则是新加的一整层，从数学类型一直到软件光栅化管线，**不依赖 GPU 也能跑**，
有 GPU 时自动走 GPU。

---

## 二、仍然守那三条铁律

| 铁律 | 在渲染里具体指什么 |
|---|---|
| **零依赖** | PNG/JPEG/TrueType/GLB 全部自己解；不链接 libpng、freetype、Assimp |
| **零拷贝** | 画布像素只有一份；纹理解码后直接进采样器；顶点缓冲直接喂光栅器 |
| **错误不外抛** | `图像.读文件` 返回 `结果[图像, 图像错误]`；模型缺字段给默认值 + 警告，不崩 |

## 四、2D：把操作空间撑开

### 4.1 变换：从 2×3 到 3×3

v0.2 只有平移、缩放、旋转，因为仿射变换 2×3 就够。v0.3 换成 3×3 齐次矩阵，
多出来的一行不是摆设——它让**变换可以嵌套、可以求逆、可以组合**，
后面的裁剪、命中测试、渐变坐标系全都靠它。

```简言
私有 渲染.变换 笔 = 渲染.变换.单位()

笔.平移(100.0, 50.0)
笔.旋转(角度: 30.0)
笔.缩放(2.0, 2.0)

画布.设变换(笔)
画布.画矩形(0.0, 0.0, 40.0, 20.0)
```

栈式写法，和所有绘图 API 一样：

```简言
画布.压入变换()
画布.平移(200.0, 100.0)
画布.旋转(0.5)
画布.画文字("旋转的文字", 0.0, 0.0)
画布.弹出变换()
```

**逆矩阵**是白送的：`笔.求逆()`。命中测试要用它——鼠标坐标在屏幕空间，
图形在自己的局部空间，得把鼠标"反变换"回去。

### 4.2 裁剪：不只是矩形

```简言
画布.压入裁剪(矩形: { 0.0, 0.0, 320.0, 200.0 })
画布.画整张图(大图)
画布.弹出裁剪()

// 圆角裁剪，做卡片最常用
画布.压入圆角裁剪(矩形: 卡片框, 半径: 12.0, 抗锯齿: 真)
画布.画图片(头像, 0.0, 0.0)
画布.弹出裁剪()

// 按任意路径裁剪（文字镂空、异形窗口）
画布.压入路径裁剪(星形路径)
画布.画渐变背景()
画布.弹出裁剪()
```

裁剪是**求交**的：叠三层裁剪，实际生效的是三个区域的交集。实现上把裁剪区
表示成"扫描线上的区间表"，每加一层就做一次区间求交，画的时候只往区间里写像素。

### 4.3 填充：颜色之外的三种

```简言
// 线性渐变
私有 渲染.渐变 晚霞 = 渲染.渐变.线性(
    起点: { 0.0, 0.0 }, 终点: { 0.0, 300.0 },
    色标: {
        { 0.00, 渲染.颜色(255, 94, 98) },
        { 0.55, 渲染.颜色(255, 195, 113) },
        { 1.00, 渲染.颜色(87, 60, 200) }
    })
画布.填充路径(天空路径, 晚霞)

// 径向渐变（球体高光、聚光灯）
私有 渲染.渐变 光晕 = 渲染.渐变.径向(
    中心: { 160.0, 160.0 }, 半径: 120.0,
    色标: { { 0.0, 白 }, { 1.0, 透明 } })

// 锥形渐变（饼图、色轮）
私有 渲染.渐变 色轮 = 渲染.渐变.锥形(中心: 圆心, 起始角: 0.0, 色标: 彩虹)

// 图案填充（条纹、网格、贴图平铺）
私有 渲染.图案 条纹 = 渲染.图案(图: 小条纹图, 平铺: 真, 变换: 旋转45度)
```

渐变的色标支持 **预乘 alpha** 插值，这样从红到透明的过渡不会出现灰边
（非预乘插值会在中途混出脏颜色，这是最常见的渐变发灰原因）。

### 4.4 描边：一根线有八个参数

```简言
私有 渲染.描边 样式 = {
    宽度: 3.0,
    端点: 圆头,        // 平头 / 圆头 / 方头
    拐角: 圆角,        // 尖角 / 圆角 / 斜角
    斜接限制: 4.0,     // 尖角太长时自动降级成斜角
    虚线: { 6.0, 4.0 },
    虚线偏移: 0.0,
    对齐: 居中         // 内侧 / 居中 / 外侧
}
画布.描边路径(路径, 颜色, 样式)
```

描边的实现不是"把线画粗"，而是**把路径偏移成多边形再填充**：
每段线往两侧各推半个宽度，拐角处补一个扇形或斜切，最后合成一条闭合轮廓。
这样描边也支持渐变、图案、混合模式，和填充走同一条管线。

### 4.5 路径运算：并、交、差

这是"操作空间变大"最明显的一处——图形不再是死形状，而是可以互相运算的集合。

```简言
私有 渲染.路径 圆 = 渲染.路径.圆(中心, 半径: 80.0)
私有 渲染.路径 方 = 渲染.路径.矩形({ 0.0, 0.0, 120.0, 120.0 })

画布.填充路径(圆.并(方), 蓝)
画布.填充路径(圆.交(方), 红)
画布.填充路径(圆.差(方), 绿)      // 圆挖掉方
画布.填充路径(圆.异或(方), 紫)     // 只留不重叠的部分
```

实现用**扫描线 + 环绕数（winding number）**：把两条路径的所有边按 y 排序，
逐条扫描线求交点，按"进入/离开"事件重建区间，再决定每段属于并集还是差集。
一次扫描 O((n+m) log(n+m))，比逐像素判断快两个数量级。

同一套机制顺带解决了**自相交路径**的填充规则：`非零环绕` 和 `奇偶` 两种可选。

### 4.6 图层与组透明度

直接往画布上画半透明图形，重叠处会"叠加深"，这不是设计想要的效果。
组透明度必须先在离屏图层里合成，再整体贴回去：

```简言
画布.压入图层(不透明度: 0.5)
画布.画圆(甲, 红)
画布.画圆(乙, 红)        // 两个圆重叠处不会变深
画布.弹出图层()           // 这时才整体乘 0.5 贴回主画布
```

图层还是**局部坐标系**：`压入图层` 时可以给一个变换，图层内所有绘制都相对它。

离屏缓冲用池子管理，不是每次都 `malloc` 一张新的。池子按尺寸分档（64/128/256/512/1024），
同尺寸复用，避免频繁分配带来的抖动。

### 4.7 文字：从"画字"到"排版"

```简言
私有 渲染.字体 正文 = 渲染.字体.读文件("字体/思源黑体.ttf")?

私有 渲染.排版 段 = 正文.排版(
    文字: "简言是一门中文编程语言，关键字全是中文。",
    宽度: 480.0,
    字号: 16.0,
    行距: 1.6,
    对齐: 两端对齐,
    字距: 0.5)

画布.画排版(段, 40.0, 80.0)
```

排版做四件事：

1. **断行**：中文按字断，英文按词断，混排时优先在空格处断，标点不能放行首（避头尾）。
2. **字形缓存**：每个字号下每个字只栅格化一次，缓存在哈希表里。同一段文字第二次画，直接贴位图。
3. **SDF**：远距离缩放时用有向距离场字形，边缘仍然锐利（代价是极小的字会糊，所以小字号走位图）。
4. **子像素定位**：字形按 1/4 像素定位，横向滚动时文字不会"跳格"。

排版结果可以**测量**：

```简言
私有 渲染.尺寸 大小 = 段.测量()
打印(大小.宽)      // 实际占用宽度
打印(大小.行数)
私有 渲染.位置 第几个 = 段.定位(字符序号: 42)   // 第 42 个字在哪
私有 整数 第几个 = 段.命中(点: 鼠标位置)        // 鼠标点在哪个字上
```

### 4.8 图像与精灵

```简言
私有 图像.图像 图集 = 图像.读文件("图集.png")?

// 单张
画布.画图片(图集, 源矩形: { 0.0, 0.0, 64.0, 64.0 }, 目标矩形: { 100.0, 100.0, 128.0, 128.0 })

// 九宫格（按钮、面板拉伸不变形）
画布.画九宫格(面板图, 目标矩形, 边: { 8.0, 8.0, 8.0, 8.0 })

// 批量画一千个精灵（一次提交，一次遍历）
私有 渲染.精灵批 批 = 画布.开批(纹理: 图集, 容量: 1024)
对 粒子 在 粒子们 {
    批.加(位置: 粒子.位置, 源: 粒子.帧, 颜色: 粒子.颜色, 旋转: 粒子.角)
}
批.提交()
```

批处理的关键是**顶点只写一次**：所有精灵的四个顶点预先放在一个大数组里，
提交时一次性做变换和光栅化，避免每个精灵一次函数调用、一次状态切换。

### 4.9 命中测试

图形画出去了，还得知道"鼠标点到了谁"。变换是双向的，把点反变换回局部空间再判断：

```简言
如果 按钮路径.包含(点: 局部坐标) 就 { ... }

// 带描边的图形，可点区域要比填充区域大半个线宽
如果 按钮路径.包含(点: 局部坐标, 容差: 描边宽度 / 2.0) 就 { ... }
```

### 4.10 导出矢量图

画布能导出 PNG，也能导出 **SVG**——把画过的每条指令记下来，最后拼成 `<path>`。
这样同一份绘图代码既能上屏，也能出印刷稿。

```简言
画布.导出SVG("海报.svg")?
```

## 五、3D：从数学到像素

### 5.1 数学类型

```简言
私有 三维.向量 甲 = { 1.0, 2.0, 3.0 }
私有 三维.向量 乙 = { 4.0, 5.0, 6.0 }

打印(甲 + 乙)
打印(甲.点乘(乙))
打印(甲.叉乘(乙))
打印(甲.长度())
打印(甲.归一())

私有 三维.矩阵 模型 = 三维.矩阵.单位()
模型 = 模型.平移({ 0.0, 1.0, 0.0 })
模型 = 模型.旋转(轴: { 0.0, 1.0, 0.0 }, 角: 1.57)
模型 = 模型.缩放({ 2.0, 2.0, 2.0 })

私有 三维.矩阵 视图 = 相机.视图矩阵()
私有 三维.矩阵 投影 = 相机.投影矩阵()
私有 三维.矩阵 全 = 投影 * 视图 * 模型
```

矩阵是**列主序**（和 OpenGL、Vulkan 一致），乘法顺序从右往左读：
先模型，再视图，再投影。

四元数用于旋转插值：

```简言
私有 三维.四元数 朝向 = 三维.四元数.绕轴({ 0.0, 1.0, 0.0 }, 0.0)
朝向 = 朝向.球面插值(目标朝向, 比例: 0.1)   // 平滑转身，不会有万向锁
```

### 5.2 网格

顶点格式定死一种，避免运行时分叉：

```
位置: 3 × 浮点   (12 字节)
法线: 3 × 浮点   (12 字节)
切线: 4 × 浮点   (16 字节，w 存副切线方向)
UV:   2 × 浮点   (8 字节)
颜色: 4 × 无符号字节 (4 字节，顶点色)
总计 52 字节/顶点
```

索引用 32 位。一个网格可以有多个"图元组"，每组一个材质。

```简言
私有 三维.网格 立方 = 三维.网格.立方体(1.0)
私有 三维.网格 球 = 三维.网格.球体(半径: 1.0, 经线: 32, 纬线: 16)
私有 三维.网格 地面 = 三维.网格.平面(宽: 10.0, 深: 10.0, 细分: 8)
```

生成算法内置，不用外部工具也能搭场景。

### 5.3 相机

```简言
私有 三维.相机 眼 = 三维.相机.透视(
    视场角: 60.0, 宽高比: 16.0 / 9.0, 近平面: 0.1, 远平面: 1000.0)
眼.看向(位置: { 0.0, 2.0, 5.0 }, 目标: { 0.0, 0.0, 0.0 }, 上: { 0.0, 1.0, 0.0 })
```

正交相机给 2.5D 和 UI 用：

```简言
私有 三维.相机 平面相机 = 三维.相机.正交(左: -10.0, 右: 10.0, 下: -10.0, 上: 10.0)
```

### 5.4 软件光栅化管线

这是 3D 的核心：不靠 GPU，自己把三角形变成像素。

```
顶点着色（每个顶点一次）
   世界坐标 = 模型 × 位置
   视图坐标 = 视图 × 世界
   裁剪坐标 = 投影 × 视图坐标
        ↓
裁剪（近平面、视锥六个面）
   把跨过近平面的三角形切开，避免"近处物体消失"
        ↓
透视除法 + 视口变换
   NDC → 屏幕像素坐标
        ↓
背面剔除
   按三角形绕序判断朝向，朝后的直接丢
        ↓
三角形光栅化
   扫描线求交，得到覆盖的像素
   重心坐标插值：深度、UV、法线、顶点色
   透视校正：UV 除以 w 再插值，再乘回来（否则贴图会扭曲）
        ↓
深度测试
   z 比缓冲里的小才写，否则丢
        ↓
片元着色
   采样纹理、算法线、算光照
        ↓
写颜色（混合）
```

每一步都能单独关掉，方便排查：`光栅.设开关(背面剔除, 假)`。

**为什么自己写而不直接上 GPU**：简言要能在一台没有显卡驱动的服务器上跑出图，
要能在 CI 里生成截图，要能保证同样的输入在任何机器上出同样的像素。
GPU 是加速选项，不是前提。

### 5.5 深度与剔除

深度缓冲用 32 位浮点，和投影矩阵的深度范围一致。

```简言
光栅.清深度(1.0)
光栅.清颜色(渲染.颜色(20, 24, 32))
光栅.设深度测试(真)
光栅.设深度写入(真)
光栅.设剔除(背面)       // 无 / 正面 / 背面
光栅.设绕序(逆时针)
```

透明物体不能走深度写入，得单独一遍，从远到近排序：

```简言
场景.按距离排序(相机位置)          // 远的在前
光栅.设深度写入(假)
对 物体 在 透明物体们 { 画物体(物体) }
```

### 5.6 纹理

```简言
私有 三维.纹理 木纹 = 三维.纹理.读文件("木纹.png")?
木纹.设环绕(重复, 重复)
木纹.设过滤(线性, 线性Mipmap)
木纹.设各向异性(8.0)
```

采样三种模式：

| 模式 | 什么时候用 | 代价 |
|---|---|---|
| 最近邻 | 像素风、必须精确取色 | 最快 |
| 双线性 | 一般贴图 | 4 次取色 |
| 三线性 + mipmap | 远处不闪烁 | 8 次取色 + 两级混合 |

mipmap 在加载时生成，不是每次采样时算。各向异性过滤在斜视角（地面、路面）
能明显改善，但只在硬件后端开；软件后端提供 2× 的简化版。

### 5.7 光照

三档，按需选：

```简言
// 1. Lambert：只有漫反射，最便宜
材质.光照模型 = 兰伯特

// 2. Blinn-Phong：加高光，塑料感
材质.光照模型 = 布林冯
材质.高光强度 = 64.0

// 3. 简化 PBR：金属度 + 粗糙度，物理感
材质.光照模型 = 简化PBR
材质.金属度 = 0.0
材质.粗糙度 = 0.6
材质.基础色 = 渲染.颜色(200, 180, 160)
```

光源三种：

```简言
场景.加光(三维.平行光(方向: { -0.5, -1.0, -0.3 }, 颜色: 白, 强度: 3.0))
场景.加光(三维.点光(位置: 灯位置, 颜色: 暖黄, 强度: 20.0, 衰减半径: 12.0))
场景.加光(三维.聚光(位置: 车灯, 朝向: 前方, 内角: 20.0, 外角: 30.0))
```

光照在**线性空间**算，最后才转到 sRGB。直接在 sRGB 空间算，暗部会发灰、
高光会过曝，这是很多自制渲染器看起来"不对"的根因。

### 5.8 阴影

平行光阴影用阴影贴图：

```简言
私有 三维.阴影 影 = 三维.阴影.新建(尺寸: 2048)
影.从平行光(光, 场景包围盒)

// 第一遍：从光的角度渲染深度
影.渲染深度(场景, 光栅)

// 第二遍：正常渲染，采样阴影贴图
材质.阴影 = 影
```

阴影贴图的分辨率决定边缘清晰度。为了让近处清晰、远处不浪费，用**级联阴影**：
把视锥按距离切成 3 段，每段一张贴图，近处密度高。

自阴影产生的"条纹"（shadow acne）靠**深度偏移**解决：比较时加一个和法线
夹角相关的小偏置，而不是固定常数。

### 5.9 实例化与批处理

同一个网格画一万次（草、树、砖块），逐个画是浪费。实例化把"每个实例的
变换 + 颜色"放进一个数组，一次提交：

```简言
私有 三维.实例组 草 = 三维.实例组(网格: 草网格, 材质: 草材质, 容量: 20000)
对 i: 0 ~ 20000 {
    草.加(变换: 随机位置和旋转, 颜色: 随机深浅)
}
草.提交(光栅)
```

软件后端里，实例化的收益在于**顶点变换只算一次模板**——如果所有实例共享
同一个旋转，矩阵可以预乘；GPU 后端里收益更大，因为一次 draw call 就画完。

### 5.10 模型读取

支持两种格式，覆盖 95% 的场景：

- **OBJ**：纯文本，好解析，不带动画。适合快速验证。
- **GLB**：glTF 的二进制打包，带材质、贴图、骨骼、动画。适合正式资产。

```简言
私有 结果[三维.模型, 三维.模型错误] 读到的 = 三维.模型.读GLB("角色.glb")
匹配 读到的 {
    例 成功(模型): {
        场景.加(模型.根节点)
    }
    例 失败(原因): {
        打印("模型读不了：" .. 原因.说明)
    }
}
```

GLB 的解析要点：JSON 块描述结构，BIN 块存顶点和索引，两者共用缓冲区视图。
读取时**不复制**顶点数据，直接把 BIN 块的内存映射成数组用。

### 5.11 动画

```简言
私有 三维.动画 走路 = 模型.找动画("走路")?
走路.播放(循环: 真, 速度: 1.0)

// 每帧推进
走路.推进(帧间隔: 0.016)
私有 三维.矩阵 骨骼[64]
走路.取骨骼矩阵(骨骼)
光栅.设骨骼(骨骼)
```

插值三种：线性、阶梯、三次样条。旋转用四元数球面插值，不用欧拉角
（欧拉角插值会出现"绕远路"和万向锁）。

### 5.12 后处理

渲染到离屏纹理，再做一遍全屏处理：

```简言
私有 三维.目标 屏 = 三维.目标.新建(宽, 高, 带深度: 真)
光栅.设目标(屏)
场景.画(光栅)

三维.后处理.泛光(屏, 阈值: 1.0, 强度: 0.4)
三维.后处理.色调映射(屏, 方式: ACES)
三维.后处理.抗锯齿(屏, 方式: FXAA)
三维.后处理.贴回屏幕(屏, 主画布)
```

软件后处理每个像素多跑几遍，代价真实。所以默认只开色调映射（一次查表），
泛光和抗锯齿按需开。

### 5.13 GPU 后端

和 2D 共用一套接口：

```简言
匹配 渲染.GPU.探测() {
    例 有(设备): { 光栅.切到GPU(设备) }
    例 无:       { 打印("没有可用显卡，走软件光栅") }
}
```

切换后 API 不变，只是三角形、纹理、着色器搬到了显卡上。软件后端继续保留，
作为"永远能跑"的兜底。

### 2D

| 手段 | 省了什么 | 预期 |
|---|---|---|
| 扫描线 + 活跃边表 | 不做逐像素的奇偶判断 | 3–5× |
| 覆盖抗锯齿（不超采样） | 内存 1× 而不是 16× | 16× 内存 |
| 字形位图缓存 | 同一个字只栅格化一次 | 10× 以上 |
| 精灵批处理 | 顶点只写一次，状态不切换 | 4–8× |
| 图层池 | 不反复分配离屏缓冲 | 消除抖动 |
| 预乘 alpha 插值 | 少一次乘除，且不发灰 | 1.3× |
| SIMD 混合（AVX2 一次 8 像素） | 混合是纯算术，天然可向量化 | 4–6× |

### 3D

| 手段 | 省了什么 | 预期 |
|---|---|---|
| 背面剔除 | 一半三角形不进入光栅 | 2× |
| 视锥剔除 | 屏幕外的物体整批跳过 | 随场景而定 |
| 扫描线光栅 | 每像素只算一次重心坐标 | 基准 |
| 透视校正用倒数插值 | 每像素一次除法变成一次乘法 | 1.5× |
| SIMD 顶点变换（AVX2 一批 8 个） | 矩阵乘法向量化 | 4× |
| 深度预通道（可选） | 减少过度绘制 | 1.5–2× |
| 实例化 | 一次提交画一批 | 5× 以上 |
| 多线程分块光栅 | 屏幕切水平带，多核并行 | ≈ 核数 |

## 七、和语言特性怎么配合

**借用避免拷贝。** 画布、纹理、网格都是"大的东西"，传参一律 `借用`，
结构体字面量只在初始化时出现一次。

**没有 GC，帧循环不抖。** 每帧的临时对象（变换矩阵、顶点数组）从**帧分配器**拿，
一帧结束整块丢弃，不做逐对象回收。这是 60 帧稳定的前提。

**可空类型管资源。** 纹理、字体、模型读失败就是 `空`，不抛异常：

```简言
如果 字体 != 空 就 { 画布.画排版(字体.排版("你好"), 0.0, 0.0) }
```

**结果类型管 IO。** 读文件、解码、连 GPU 都返回 `结果`，失败原因带上下文
（哪个文件、第几个字节、期望什么）。

**并发画不同区域。** 画布可以切成互不重叠的带，每带一个线程。
简言的借用检查保证不会有两个线程同时写同一块像素——切分时按矩形借用。

## 九、明确不做

| 不做 | 为什么 |
|---|---|
| 完整的 PBR（IBL、预过滤环境贴图） | 收益在"照片级"，成本在"一整套离线工具"，不属于 v0.3 |
| 光线追踪 | 软件光追在 CPU 上跑不到交互帧率，等有 GPU 后端再说 |
| 视频编解码 | 是另一个领域，需要独立的一套标准实现 |
| 3D 物理引擎 | 属于游戏框架，不属于渲染 |
| 内置着色器语言 | 简言本身就是语言，再套一层 DSL 是重复 |
| 字体子集化工具链 | 只做运行时子集，导出工具交给外部 |

## 十、一句话总结

二维从"一支笔"变成"一套可组合的绘图系统"，三维从无到有、并且**不依赖显卡也能出图**。
两者共用同一块画布、同一套颜色与混合规则——所以 3D 场景上叠 2D 界面，
不需要两套坐标系、两次合成。
