# 简言 · 语义分析器说明

> 第三棒。词法把源码切成词，语法把词搭成树，语义分析回答一个更狠的问题：
> **这棵树讲不讲得通。**

---

## 一、它到底抓什么

语法分析器看到这四行，全都点头：

```简言
整数 甲 = "你好"
打印(乙)
甲 = 甲 + 1
返回 丙
```

结构完全合法——有类型、有名字、有等号、有值。可它们分别是：

| 代码 | 语义分析说的话 |
|---|---|
| `整数 甲 = "你好"` | 这里要 `整数`，给的是 `字符串`。简言不做隐式转换 |
| `打印(乙)` | 找不到 `乙`。是不是拼错了，或者忘了在这之前声明？ |
| `甲 = 甲 + 1` | 这一句本身没错，但如果 `甲` 之前被借出去了，就会在这里被拦下 |
| `返回 丙` | 这个函数没声明返回类型（等于返回空值），却返回了 `未知` |

**语法的错和语义的错，体验完全不同**：语法错是"我看不懂这句话"，人是知道自己在写什么的；
语义错是"我看懂了，但你算错了"，这时候编译器必须说清楚**哪里要什么、你给了什么、怎么改**。

所以这份分析器的每条报错都长这样：

```
[错误] 第 35 行 第 8 列：初值类型和声明的类型对不上：这里要 整数，给的是 字符串。
       简言不做隐式转换，字符串和数字之间要写 字符串(x) 或 整数(x)
```

不是"类型不匹配"，而是把**三个问题的答案**一起给出来。

---

## 二、为什么分两遍

```简言
函数 甲() { 乙() }

函数 乙() { 打印("hi") }
```

`甲` 里用了 `乙`，可 `乙` 写在后面。如果边读边查，读到 `甲` 那一行时 `乙` 还没进花名册。

所以：

```
第一遍（只登记，不看函数体）
    结构 学生      → 记下"有这么个类型"
    函数 查找      → 记下"有这么个函数"
    常量 最大人数  → 记下"有这么个常量"

第二遍（填类型）
    学生 的字段类型、查找 的参数和返回类型

第三遍（查函数体）
    逐个函数进去，查名字、查类型、查借用

中间还夹一步：记下"谁实现了谁"——
    实现 学生 为 可打印
因为第三遍会问"这个结构实现了那个接口吗"，实现表必须先填好。
```

这三步在 `sema.c` 里就是三个函数：`建花名册` → `检实现块` → `检函数体`。

> **为什么不是一遍？** 一遍也能做，但要在遇到"还没见到的名字"时挂起、等会儿再回填。
> 那套机制叫"符号解析补丁表"，写起来绕，读起来更绕。两遍扫描多走一次内存，
> 换来的是"代码顺序 = 逻辑顺序"，值得。

## 三、类型：一张证件照，只留一份

源码里的类型是一串文字：`映射[字符串, 整数 组]`。分析时把它变成结构：

```
种 = 映射
键 = (字符串)
值 = 组
     元素 = (整数)
```

同一张"证件照"只留一份，放在一个按签名哈希的池子里。**比较两个类型就是比较指针**，
不用递归比字符串——这是语义分析里最热的操作之一。

### 类型相容表

`可赋值(目标, 源)` 是这个函数的名字。它回答"源能不能直接放进目标里"：

| 目标 | 源 | 行不行 | 为什么 |
|---|---|---|---|
| `整数` | `整数` | ✅ | 同一种 |
| `浮点` | `整数` | ✅ | 整数放进浮点不丢东西 |
| `整数64` | `整数8` | ✅ | 小的放进大的 |
| `整数8` | `整数` | ❌ | 会悄悄丢数据，必须写 `整数8(x)` |
| `可空[整数]` | `整数` | ✅ | 自动包一层"有值" |
| `可空[整数]` | `空` | ✅ | 空是合法的可空值 |
| `整数` | `可空[整数]` | ❌ | 得先确认不为空 |
| `字符串` | `整数` | ❌ | 永远不隐式转换 |
| `任意` | 任何 | ✅ | FFI、内置函数用 |
| `T`（泛型参数） | 任何 | ✅ | 还不知道 T 是什么，先放行 |

最后一条很重要：泛型函数里 `T` 的具体类型还没定，如果这时候报错，`最大[T]` 这类
完全正确的代码会被冤枉。**宁可漏报，不可误报**——误报会让人不信任工具。

## 四、名字：一层一层往里找

```简言
函数 演示() {
    私有 整数 甲 = 1        ← 函数体这一层
    如果 真 就 {
        私有 整数 甲 = 2    ← 块这一层，遮住外面那个
        打印(甲)            ← 看到的是 2
    }
    打印(甲)                ← 看到的是 1
}
```

作用域是一串链，查名字从最里层往外走，找到就停。同一层里重名直接报错：

```
[错误] 第 58 行 第 8 列：`甲` 在这一层已经有一个同名的了。
       换个名字，或者把它放到别的 { } 里
```

### 一个特别的处理：方法体里的字段

```简言
实现 学生 为 可打印 {
    函数 打印() -> 字符串 {
        返回 名字 .. "（" .. 字符串(年龄) .. "岁"）   ← 名字、年龄 是谁？
    }
}
```

规范里定了这种写法：方法体里直接写字段名，相当于有个看不见的 `自身`。
语义分析在进方法时，把该结构的字段**当成普通变量登记进作用域**，
所以 `名字`、`年龄` 找得到，类型也对。

## 五、借用：一本只活一句的账

规则只有两条：

1. **同一时刻，要么很多人看，要么只有一个人改。**
2. **被别人看着/改着的时候，主人自己不能动它。**

实现方式很土但很有效：一个栈。

```
遇到 `借用 甲`      → 甲的"看客数" +1，栈里记一笔
遇到 `可变借用 甲`  → 检查没人看、没人改 → 标记"正在改"，栈里记一笔
一句结束            → 把这一句记的账全部回滚
```

于是这些都会被拦下：

```简言
私有 整数 结果值 = 两个借用(借用 王五, 可变借用 王五)
```
```
[错误] `王五` 正被别人借着看，不能同时可变借用。等那句用完再改
```

```简言
私有 学生 李四 = 移动 张三
打印(张三.名字)
```
```
[错误] `张三` 的值已经被移动走了（写 移动 或作为参数传走），这里不能再用。
       要保留就写 `复制 张三`
```

### 为什么"只活一句"

真正的借用检查器（比如 Rust 的 NLL）会算清楚"这个借用最后一次被用到是哪一行"。
那需要数据流分析，代码量是这里的三倍，报错信息也更难懂。

简言 v0.1 选的是**语句级借用**：够挡住"边遍历边删除""借出去又改"这类真会出事的写法，
又不会因为分析得不够精细而误伤。代价是有些合法代码会被要求多写一个 `复制`。

> 这条限制写进了规范，不是"以后再说"的欠账——它是明确的设计取舍。

## 六、可能为空的值：认得出 `如果 x != 空`

```简言
私有 可空[学生] 乙 = 空
打印(乙.名字)          ← 报错
```

```
[错误] 这是 可空[学生]，可能为空，不能直接取 `.名字`。
       先写 如果 它 != 空 就 { ... }，或者写 它.取值()
```

而这么写就放行：

```简言
如果 乙 != 空 就 {
    打印(乙.名字)      ← 这个块里，乙 已经确认有值
}
```

做法：检查 `如果` 时看条件是不是 `x != 空`，是的话把 `x` 标记成"已判空"，
检查完这个块再恢复。这叫**流敏感**——同一个变量，在不同位置有不同的"已知信息"。

只处理最常见的那一种（`!= 空` 的 then 分支）。`== 空` 的 else 分支、`或默认` 之后，
目前都不做推断——**少推断，少误报**。

## 七、枚举匹配必须穷尽

```简言
枚举 颜色 { 红  绿  蓝 }

匹配 c {
    例 颜色.红: { 返回 "红" }
}
```

```
[错误] `匹配` 没有处理 `绿、蓝`，也没写 默认。
       枚举必须穷尽，补上缺的分支，或者加一行 `默认: { ... }`
```

缺失的分支是**攒起来一次说完**的，不是报一个改一个。

顺便，模式里的绑定名也会被认出来并给上正确类型：

```简言
例 形状.圆(半径): { 返回 3.14159 * 半径 * 半径 }
                    ↑ 半径 是 浮点，从变体 圆 的字段类型推出来
```

## 八、接口：答应的事要做到

```简言
接口 打招呼 {
    函数 你好() -> 字符串
    函数 再见() -> 字符串
}

实现 学生 为 打招呼 {
    函数 你好() -> 字符串 { 返回 "你好" }
}
```

```
[错误] `打招呼` 这个接口要求有 `再见` 方法，但这里没写
```

签名也要对得上。接口里的 `自身` 在定义时还不知道将来是谁实现，所以被当成一个
"类型参数"——检查实现时，它跟任何具体类型都对得上：

```简言
接口 可比较 { 函数 比较(其他: 借用 自身) -> 整数 }

实现 学生 为 可比较 {
    函数 比较(其他: 借用 学生) -> 整数 { 返回 年龄 - 其他.年龄 }
    -- 自身 → 学生，对上了
}
```

## 十一、两份实现，互为验算

`sema.c` 和 `sema_参考实现.py` 是同一套规则的两遍写法：

| | C 版 | Python 版 |
|---|---|---|
| 类型 | 结构体 + 指针 + 去重池 | 元组，`==` 就是同构比较 |
| 分派 | `switch` 大函数 | `dict` 分派表 + 小方法 |
| 符号表 | 链式作用域 + 哈希桶 | `list[dict]` |
| 归零 | 手动 `free` | 垃圾回收 |

两版输出必须一致（行号列号除外，因为 Python 那棵语法树不带位置）：

```sh
make 对答案
# 两份实现输出完全一致
```

这是最便宜的正确性保证：一处逻辑写错，另一处几乎不可能跟着错成一样。

## 十二、已知边界（v0.1 明确不做）

| 不做 | 原因 | 什么时候做 |
|---|---|---|
| 精确的生命周期分析 | 要数据流分析，代码量三倍 | v0.2 |
| 隐式移动的完整追踪 | 容易误报，先只查显式 `移动` | v0.2 |
| 泛型实例化后的类型检查 | 单态化在下一棒（代码生成） | 下一棒 |
| 常量折叠与死代码 | 属优化，不属检查 | 优化阶段 |
| 跨模块类型检查 | 需要先定 `.jym` 接口文件格式 | 模块系统 |
