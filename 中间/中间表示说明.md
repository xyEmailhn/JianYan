# 简言 · 中间表示与单态化

> 语法树告诉你"这句话结构对不对"，语义分析告诉你"这句话讲不讲得通"。
> 但它们都还是**树**——树是给人看的，机器读不了。
>
> 这一层要把它摊平成一串指令，顺手把泛型展开、把能算的算完。

---

## 一、为什么要多这一层

最直接的做法是：拿到树，直接生成机器码。

问题在于，这是**一次跨两级台阶**：

```
语法树  ──────────────────────────►  机器码
        （中间少了整整一层）
```

一旦出错，你面对的是"程序跑飞了"，而不是"第 37 条指令的寄存器分配错了"。
所以真正的编译器都在中间架一层：

```
语法树  ──►  中间表示  ──►  机器码
              ↑
         优化都在这儿做
```

中间表示（IR）是**半成品**：

- 比树低：每个操作都明确了先后顺序和结果存放位置；
- 比机器码高：还认得出"这是加法""这是调用"，不绑死某个 CPU。

代价是多写一层代码。收益是后面所有优化、所有后端（x86、ARM、WASM）
都只跟这一层打交道，不用回头再理解语法树。

## 二、IR 长什么样

### 2.1 三层结构

```
函数  ──  一串基本块  ──  每个块里一串指令
```

一条指令长这样：

```
%t3 = 加 %t0, %t1 : 整数
 │      │   │    │    └── 结果类型
 │      │   │    └── 第二个操作数
 │      │   └── 第一个操作数
 │      └── 做什么
 └── 结果放哪
```

`%t3` 叫**值号**（value id）。所有操作数都是值号，没有"表达式"这个概念——
树里的嵌套结构已经被拉平了。

`2 * 3 + 1` 在树里是：

```
      +
     / \
    *   1
   / \
  2   3
```

在 IR 里是：

```
%t0 = 常量 2
%t1 = 常量 3
%t2 = 乘 %t0, %t1
%t3 = 常量 1
%t4 = 加 %t2, %t3
```

每一步只做一件事，结果有名字，顺序一目了然。这就是"三地址码"。

### 2.2 指令集

一共 50 来条，分五类：

| 类别 | 指令 | 说明 |
|---|---|---|
| 数据搬运 | `常量` `载` `存` `存字段` `存下标` `取字段` `取下标` | 值和内存之间搬 |
| 运算 | `加` `减` `乘` `除` `整除` `取余` `乘方` `位与` `位或` `位异或` `左移` `右移` `取反` `负` `非` | 纯算术，无副作用 |
| 比较 | `等于` `不等` `小于` `大于` `小于等` `大于等` | 结果一定是布尔 |
| 调用 | `调用` `调用方法` `转换` `取函数` | 会跳出去再回来 |
| 控制流 | `跳` `条件跳` `返回` | **只能出现在块的末尾** |
| 构造 | `构造组` `构造映射` `构造结构` `构造变体` `成功` `失败` | 造一个复合值 |
| 并发 | `发送` `接收` `建通道` `关通道` `等待` | 线程与通道 |
| 其它 | `遍历开始` `遍历下一个` `匹配变体` `解构变体` `长度` `丢弃` | 语法糖落地后的样子 |

指令里只有 `甲`、`乙`、`丙` 三个操作数位置。多参数的调用和构造另开一串
`多[8]`——因为把 `多参数` 硬塞进三个位置，读代码的人会疯。

### 2.3 为什么要有基本块

块不是"为了好看"。它是一条硬约束：

> **一个块一旦开始执行，就会一直执行到最后一条，中间不会跳走。**

这条约束带来两个好处：

1. **块内指令可以随便重排。** 没有跳转进来，也没有跳转出去，先后顺序只由数据依赖决定。后面做寄存器分配、指令调度，都靠这个前提。
2. **控制流图变简单。** 跳转只发生在块之间，图上的节点数从"指令数"降到"块数"，通常少一个数量级。

块的边界只有三种情况：函数入口、跳转目标、跳转指令的下一条。

## 三、值号与变量槽

IR 里没有"变量"，只有值号。但源码里有 `甲`、`乙`，它们得有个落脚点。

做法是**给每个变量分配一个固定值号**，叫它"槽"：

```
%甲 = 新槽
存 %甲, %t0        ← 甲 = 2
%t3 = 载 %甲       ← 读甲
```

打印时槽显示成 `%甲`，临时值显示成 `%t3`，一眼能分清。

### 3.1 分层

```
函数体
 ├ 甲、乙              第一层
 └ { 私有 整数 丙 }     第二层
    └ { 私有 整数 丁 }  第三层
```

出了 `}`，里面的槽就该消失。所以槽也分层——查名字从里往外，找到就停。
内层的 `甲` 会遮住外层的 `甲`，这正是人期待的行为。

### 3.2 为什么不做 SSA

学术界的主流做法是 SSA（静态单赋值）：每个值号只赋值一次，改值就造新号。
好处是数据流分析极其干净，坏处是要引入 `φ` 函数处理控制流汇合，
而且调试时看到的变量名会变成 `甲.1`、`甲.2`、`甲.3`。

v0.1 不做 SSA。原因是**这一版的目标是"能跑通、能读懂"**，不是"最优"。
允许一个槽被多次赋值，打印出来的 IR 更像人写的代码：

```
%i = 常量 0
L1:
  ...
  %t5 = 加 %i, %t2
  存 %i, %t5
  跳 L1
```

而不是：

```
%i.1 = 常量 0
L1:
  %i.2 = φ(%i.1, %i.3)
  ...
  %i.3 = 加 %i.2, %t2
  跳 L1
```

SSA 留到寄存器分配那一棒再引入——那时候需要它做精确的活跃变量分析。

## 四、常量折叠

`2 * 3 + 1` 写在源码里，没理由让机器在运行时算。

做法是**在生成指令之前，先试着把整棵子树算成一个数**：

```c
static 常量值 折叠(节点 *n)
{
    switch (n->种类) {
    case 节_整数:  return 有效常量(T整数, 读整数(n->文字, n->文字长), ...);
    case 节_二元: {
        常量值 a = 折叠(n->子[0]);
        常量值 b = 折叠(n->子[1]);
        if (!a.有效 || !b.有效) return 无效常量();   /* 有变量，算不了 */
        if (名同(n->文字, n->文字长, "+", 1)) ...
    }
    }
}
```

算得出来就直接产一条 `常量` 指令，整个子树不见了：

```
折叠前                      折叠后
%t0 = 常量 2                %t0 = 常量 1047
%t1 = 常量 3                返回 %t0
%t2 = 乘 %t0, %t1
%t3 = 常量 4
%t4 = 常量 5
%t5 = 乘 %t3, %t4
%t6 = 加 %t2, %t5
%t7 = 常量 6
%t8 = 常量 2
%t9 = 整除 %t7, %t8
%t10 = 减 %t6, %t9
%t11 = 常量 2
%t12 = 常量 10
%t13 = 乘方 %t11, %t12
%t14 = 加 %t10, %t13
返回 %t14
```

16 条指令变成 2 条。`make 比折叠` 可以把两边并排打出来看。

### 4.1 哪些能折，哪些不能

**能折**：整数、浮点、布尔、字符串字面量；四则、位运算、比较、逻辑；
字符串拼接（`"简" .. "言"` 直接接好）。

**不能折**：

- 带除零的：`1 / 0` 留给运行时，编译期不能炸；
- 带变量的：`甲 + 2`，甲的值编译时不知道；
- 带调用的：`长度("abc")` 理论上能折，但那需要知道标准库语义，不属于这一层；
- 浮点乘方：走 `pow`，结果依赖平台，折了反而可能不一致。

### 4.2 折叠顺序

先折子里，再折自己。这和"先算括号里"是同一个道理：

```c
常量值 a = 折叠(n->子[0]);   /* 先把左边折到底 */
常量值 b = 折叠(n->子[1]);   /* 再把右边折到底 */
/* 两边都是常量，才轮到自己 */
```

## 五、单态化：泛型怎么落地

### 5.1 问题

源码里泛型函数只有一份：

```简言
函数 最大[T: 可比较](甲: T, 乙: T) -> T {
    如果 甲 >> 乙 就 { 返回 甲 }
    返回 乙
}
```

但机器需要的是**每个具体类型一份代码**：

```
最大$整数(甲: 整数, 乙: 整数) -> 整数
最大$浮点(甲: 浮点, 乙: 浮点) -> 浮点
最大$字符串(甲: 字符串, 乙: 字符串) -> 字符串
```

因为"比较两个东西"这件事，对整数是比较指令，对字符串是逐字节比较，
对结构体可能是调用户定义的 `比较` 方法。**它们不是同一段机器码。**

### 5.2 做法：队列式展开

```
1. 先把所有"非泛型函数"翻译成 IR
2. 翻译过程中遇到泛型调用 → 推导出 T 是什么 → 给这个组合起个名字
3. 如果这个名字没生成过，塞进队列
4. 队列处理完之前，不断有新实例被塞进来（实例的函数体里可能又调用泛型）
```

代码里就是一个循环：

```c
for (int i = 0; i < 实例数; i++) {
    实例项 *t = &实例队[i];
    降函数(t->函数, t->名, strlen(t->名), t->实参, t->数, 1);
}
```

`实例数` 在循环里会变大，循环自己会跟上。这叫**工作队列**，是处理
"递归结构"最省心的写法——不用递归，不怕栈溢出。

### 5.3 怎么推导 T

拿形参类型和实参类型逐层比对：

```
形参: T         实参: 整数        → T = 整数
形参: 组[T]     实参: 组[浮点]    → T = 浮点
形参: 映射[K, V] 实参: 映射[字符串, 整数] → K = 字符串, V = 整数
```

代码就二十行：

```c
if (形->种 == 型_参数) {
    for (每个泛型名)
        if (名字对得上) {
            if (!绑[i]) { 绑[i] = 实; return 1; }      /* 第一次见到，记下来 */
            return 类型同构(绑[i], 实) ? 1 : 0;        /* 第二次见到，必须一致 */
        }
}
if (形->种 == 型_组 && 实->种 == 型_组)
    return 推导绑定(形->元素, 实->元素, ...);
```

"第二次见到必须一致"这条很重要：`函数 混合[T](甲: T, 乙: T)` 调用
`混合(1, "x")` 时，第一次推出 T=整数，第二次推出 T=字符串，冲突。
这时不能生成实例，应该报错——但语义分析已经拦住了，所以这里只返回 0。

### 5.4 实例名怎么起

```
最大              + $整数          → 最大$整数
映射[字符串, 整数] + $映射_字符串_整数
组[浮点]          + $组_浮点
```

`$` 是合法标识符字符但不可能是用户写的（词法分析器不认它作为标识符开头），
所以不会撞名。

### 5.5 代价

| 代价 | 具体 |
|---|---|
| 体积 | 每个类型组合一份代码。`最大` 用了 4 种类型，就是 4 份 |
| 编译时间 | 实例越多越慢，但只编译用到的 |
| 编译期信息 | 报错里的函数名带 `$整数` 后缀，比原名长 |

收益是**运行时零开销**：没有虚表、没有类型检查、没有装箱。泛型函数
编译出来和手写一份 `整数版最大` 完全一样。这是"用空间换速度"最划算的一笔。

### 5.6 为什么不做"一份代码 + 运行时类型信息"

那样每次取值都要查表、每次比较都要间接跳转。泛型就白写了——
用户写泛型是为了"不重复"，不是为了"慢一点"。

## 六、控制流怎么摊平

树里的 `如果` 是一个节点，IR 里没有"如果"，只有跳转。

### 6.1 如果

```简言
如果 甲 >> 乙 就 { 返回 甲 }
返回 乙
```

```
    %t0 = 载 %甲
    %t1 = 载 %乙
    %t2 = 大于 %t0, %t1
    条件跳 %t2 则 L1 否则 L2
L1:
    %t3 = 载 %甲
    返回 %t3
L2:
    %t4 = 载 %乙
    返回 %t4
```

三个块：条件块、真块、假块。`否则如果` 就是"假块里再放一个条件跳"，
层层套下去。最后一个 `否则` 或空块收尾。

### 6.2 循环

```简言
对 i: 1 ~ 10, 步长: 2 { 累加 = 累加 + i }
```

```
    %i = 常量 1
    %止 = 常量 10
    %步 = 常量 2
    跳 L1
L1:
    %c = 小于 %i, %止
    条件跳 %c 则 L2 否则 L4
L2:
    %t = 载 %累加
    %u = 加 %t, %i
    存 %累加, %u
    跳 L3
L3:
    %n = 加 %i, %步
    存 %i, %n
    跳 L1
L4:
```

四个块：**头**（判断）、**体**（干活）、**步**（推进）、**尾**（出去）。

为什么要单独一个"步"块？因为 `继续` 要跳到"推进"而不是"判断"——
先加步长再判断，否则 `继续` 会死循环。

`打断` 跳到**尾**。

### 6.3 匹配

```简言
匹配 形状 {
    例 圆(半径): { 返回 3.14159 * 半径 * 半径 }
    例 矩(宽, 高): { 返回 宽 * 高 }
    例 点: { 返回 0.0 }
}
```

```
    %v = 载 %形状
    %m1 = 匹配变体 %v, "圆"
    条件跳 %m1 则 L1 否则 L2
L1:
    %r = 取变体字段 %v.圆.半径
    ...算面积...
    返回 ...
L2:
    %m2 = 匹配变体 %v, "矩"
    条件跳 %m2 则 L3 否则 L4
L3:
    ...
L4:
    %m3 = 匹配变体 %v, "点"
    条件跳 %m3 则 L5 否则 L6
L5:
    返回 0.0
L6:
    返回 空
```

每个 `例` 是一次"比较 + 条件跳"，不匹配就往下走。这是**线性搜索**，
`n` 个变体最坏 `n` 次比较。

优化空间（留给下一棒）：变体编号是编译期已知的整数，可以生成**跳转表**，
一次间接跳转直达目标块，O(1) 而不是 O(n)。

### 6.4 短路逻辑

`甲 与 乙` 不能两条都算——甲是假的时候，乙可能根本不该执行
（比如 `指针 != 空 与 指针.取值() > 0`）。

所以 `与`/`或` 必须生成控制流，不能一条指令了事：

```
    %r = 常量 假
    %a = 载 %甲
    条件跳 %a 则 L1 否则 L2
L1:
    %b = 载 %乙
    存 %r, %b
    跳 L2
L2:
    ...用 %r...
```

用一个临时"槽"承接结果，两个分支都往它写。这不是最优（SSA 下可以用 φ），
但正确、好读。

## 七、借用与移动在 IR 里怎么办

语义分析已经查过借用规则，IR 里为什么还留着 `借用`、`可变借用`、`移动`、`复制`？

因为**它们对后端有用**：

| 指令 | 后端能做什么 |
|---|---|
| `借用 %x` | 传指针，不复制 |
| `可变借用 %x` | 传指针，标记可写 |
| `移动 %x` | 直接把所有权转过去，不复制，之后 `%x` 不再使用 |
| `复制 %x` | 生成一次深拷贝（数组、字符串、结构体） |

如果 IR 阶段就把它们抹掉，后端就分不清"这里是传值还是传引用"，
只能全部按传值处理——每次调用都复制一遍数组，性能直接崩。

所以这一层**保留语义标记**，等后端决定"指针还是值"。

v0.1 的 IR 不做借用检查的收尾（比如精确到基本块的活跃分析），
因为语义层已经按语句粒度查过了，重复查不会更准，只会更慢。

## 八、打印：为什么要能读

IR 是中间产物，但它**必须能被人看懂**。

理由是：出了问题，你只能看它。汇编太细，语法树太粗，IR 是唯一
"既能看出意图、又能对应到指令"的层级。

所以打印做了几件事：

1. **变量显示名字**：`%甲` 而不是 `%7`；
2. **类型跟在后面**：`%t3 = 加 %t0, %t1 : 整数`；
3. **按执行流排序**：块在链表里是按创建顺序排的，但打印时从入口块
   沿跳转走一遍，先打真正先执行的；走不到的标"不可达"；
4. **标签用 L 加数字**：`L3`，和汇编的习惯一致。

一个真实的例子：

```
函数 平均(借用 分数: 浮点 组) -> 浮点
L0:
    %t1 = 载 %分数
    %t2 = 长度 %t1 : 整数
    %t3 = 常量 0 : 整数
    %t4 = 等于 %t2, %t3 : 布尔值
    条件跳 %t4 则 L1 否则 L2
L1:
    %t5 = 常量 0.0 : 浮点
    返回 %t5
L2:
    跳 L3
L3:
    %t6 = 常量 0.0 : 浮点
    存 %和, %t6
    ...
```

对着源码能一行一行对上。这就是"能读"的标准。

## 十、v0.1 明确不做的五条

诚实列出来，免得误会：

1. **不做 SSA**。允许一个槽被多次赋值。原因见 3.2。
2. **不做死代码消除**。`如果 假 { ... }` 里的代码照样生成 IR，只是永不执行。
   语义层已经报了"永远为假"的提示，优化留给下一棒。
3. **不做公共子表达式消除**。`(甲 + 乙) * (甲 + 乙)` 会算两遍。
4. **不做寄存器分配**。IR 里是无限多的"值号"，映射到有限的寄存器是下一棒的事。
5. **不做借用收尾分析**。语义层按语句粒度查过了，这里不重复。

这五条都是**优化**，不是**正确性**。不做它们，程序照样跑对，只是慢一点。

---

## 十一、下一棒接什么

IR 有了，下一步是把它变成真正的机器码。要做的顺序：

1. **指令选择**：每条 IR 指令映射到一条或几条 x86-64 指令（或 ARM64）。
2. **寄存器分配**：值号 → 物理寄存器。溢出到栈。
3. **栈帧布局**：局部变量、参数、返回地址。
4. **调用约定**：参数怎么传（前 6 个走寄存器，其余走栈），返回值放哪。
5. **ELF 生成**：代码段、数据段、符号表、入口点。
6. **链接**：静态链接 musl，产出单个二进制。

到那时，`简中间` 就成了 `简编译`：输入 `.jy`，输出可执行文件。
