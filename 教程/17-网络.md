# 第 17 章 · 网络

> 两个句柄类型：`监听器` 等连接进来，`套接字` 是进来之后的那个连接。
> 再加一个 `HTTP取`，一句话抓网页。

## 17.1 完整代码

`教程/例子/16-网络.jy`：

```简言
模块 教程.网络

函数 主() -> 整数 {
    私有 结果[监听器, 字符串] 听 = 监听("0.0.0.0", 0)
    如果 听.是失败 就 {
        打印行("监听失败：" .. 听.错误值)
        返回 1
    }
    私有 监听器 器 = 听.取值()
    如果 器.端口() <= 0 就 {
        打印行("没拿到端口")
        返回 1
    }

    私有 通道[整数] 完成 = 通道[整数](1)

    线程 {
        私有 结果[套接字, 字符串] 配 = 连接("127.0.0.1", 器.端口())
        如果 配.是成功 就 {
            私有 套接字 客 = 配.取值()
            客.写("喂，服务端")
            打印行("客户端收到：" .. 客.读全部())
            客.关闭()
            发送 完成, 1
        } 否则 {
            打印行("客户端连不上：" .. 配.错误值)
            发送 完成, 0
        }
    }

    私有 结果[套接字, 字符串] 接 = 器.接受()
    如果 接.是成功 就 {
        私有 套接字 服 = 接.取值()
        私有 字符串 内容 = 服.读(64)
        打印行("服务端收到：" .. 内容)
        服.写("服务端回声：" .. 内容)
        服.关闭()
    } 否则 {
        打印行("接受失败：" .. 接.错误值)
    }
    器.关闭()

    私有 可空[整数] 收尾 = 接收 完成
    返回 0
}
```

运行结果（端口每次不同，所以不打印）：

```
服务端收到：喂，服务端
客户端收到：服务端回声：喂，服务端
```

## 17.2 三个动作：监听、连接、接受

| 角色 | 代码 | 说明 |
|---|---|---|
| 服务端 | `监听("0.0.0.0", 8080)` | 绑定并开始等。端口写 `0` 让内核挑一个空闲的 |
| 服务端 | `器.接受()` | **阻塞**，直到有人连进来 |
| 客户端 | `连接("127.0.0.1", 8080)` | 连上去，返回 `套接字` |

两者都返回 `结果[...]`，失败时 `.错误值` 是一句中文：

```
监听失败：端口被占用了
客户端连不上：连不上
```

`监听("0.0.0.0", 0)` 之后再 `器.端口()` 就能拿到内核分配的真实端口。
**服务端写 `0`、客户端去问端口**，是多进程测试里最省事的做法——不用猜哪个端口空着。

## 17.3 读和写

| 方法 | 返回 | 说明 |
|---|---|---|
| `客.读(n)` | 字符串 | 最多 n 字节。对端关了给空串 |
| `客.写(s)` | 整数 | 实际写了多少字节 |
| `客.读全部()` | 字符串 | 一直读到对端关闭 |
| `客.设超时(毫秒)` | — | 读写超时。`0` 表示不限 |
| `客.对端()` | 字符串 | `"127.0.0.1:54321"` |
| `客.关闭()` | — | 关掉这个连接 |

**`读(n)` 可能读不满。** TCP 是字节流，不是消息流：你发 100 字节，对端可能
分三次收到 40、40、20。所以"发一条消息、收一条消息"的协议必须自己定边界
（长度前缀、换行、或者像 HTTP 那样用 `Content-Length`）。

这个例子里两端都是本机、消息很短，一次就读完了。真写协议别赌这个。

**`读全部()` 会等到对端关闭**才返回。如果对端不关，就一直等。所以：

```简言
客.设超时(3000)          -- 3 秒没动静就断
私有 字符串 回 = 客.读全部()
```

超时之后 `读` 返回空串，`读全部` 返回已经读到的部分。这一版不区分
"对端关了"和"超时了"——都是空/短。要分开得再加一个查询方法。

## 17.4 一句话抓网页：`HTTP取`

```简言
私有 结果[字符串, 字符串] 回 = HTTP取("http://example.com/")
如果 回.是成功 就 {
    打印行(回.取值())
}
```

`HTTP取` 做四件事：拆网址 → `连接` → 发一个 `GET` 请求 → `读全部`。
返回的是**整个响应**，包括状态行和头：

```
HTTP/1.1 200 OK
Date: Sat, 21 Nov 2026 19:54:50 GMT
Content-Type: text/html; charset=utf-8
...
<!doctype html>
<html>...
```

想只拿正文，就找第一个空行切开：

```简言
函数 正文(响应: 借用 字符串) -> 字符串 {
    私有 字符串 组 段 = 响应.切分("\r\n\r\n")
    如果 #段 >> 1 就 { 返回 段[1] }
    返回 响应
}
```

限制写清楚：

- 只认 `http://`（明文）。`https://` 要 TLS，这一版没有；
- 只发 `HTTP/1.0`，所以对端回完就关，`读全部` 正好读到结尾；
- 不跟随重定向，不分块传输，不处理 gzip。

够抓静态页和调自己的接口，不够当浏览器。

## 17.5 服务端怎么写才不崩

最简单的服务端就是"接一个、处理、关掉"：

```简言
私有 结果[监听器, 字符串] 听 = 监听("0.0.0.0", 8080)
私有 监听器 器 = 听.取值()
循环 {
    私有 结果[套接字, 字符串] 接 = 器.接受()
    如果 接.是失败 就 { 打断 }
    私有 套接字 客 = 接.取值()
    私有 字符串 请求 = 客.读(4096)
    客.写("HTTP/1.0 200 OK\r\nContent-Length: 2\r\n\r\n好")
    客.关闭()
}
```

一次只服务一个人。要同时服务多个，就在 `接受` 之后开线程：

```简言
循环 {
    私有 结果[套接字, 字符串] 接 = 器.接受()
    如果 接.是失败 就 { 打断 }
    私有 套接字 客 = 接.取值()
    线程 {
        处理(客)
    }
}
```

注意 `客` 是句柄，线程里拿到的和外面是同一个连接，这没问题。
但**循环变量 `接` 每轮都是新变量**，所以不会有"上一个线程拿了下一个连接"的经典 bug。

## 17.6 这一版没做的

| 功能 | 现状 | 绕法 |
|---|---|---|
| TLS / HTTPS | 没有 | 只能 `http://`，或者在外面套一层反向代理 |
| UDP | 没有 | 用 TCP 或调外部程序 |
| DNS 缓存 | 没有，每次都问 | 对性能有要求的场景自己缓存 IP |
| IPv6 | `监听` 只绑 IPv4 | `连接` 走 `getaddrinfo`，IPv6 目标能连 |
| HTTP 服务端框架 | 没有 | 自己解析请求行和头，见 17.5 |
| 半关闭 | 没有 | 直接 `关闭` |

规范里的完整设计见 `规范/标准库_v0.2_网络与渲染.md` 第 3 节：
`网络.地址`、`网络.流`、`网络.监听`、`网络.数据报`、`网络.域名`、`网络.TLS`。
这一版把其中最常用的四个动作（连、听、收发、HTTP GET）先接上了，
名字平铺，没有命名空间。

## 17.7 常见错误

| 现象 | 原因 | 改法 |
|---|---|---|
| `监听失败：端口被占用了` | 上次的进程还没退干净 | 换端口，或者写 `0` 让内核挑 |
| `客户端连不上：连不上` | 服务端没起来 / 端口写错 | 先起服务端，端口从 `器.端口()` 拿 |
| `读` 一直不返回 | 对端没发数据也没关 | `设超时`，或者用 `读全部` 配 `关闭` |
| 收到半条消息 | TCP 是字节流，会拆包 | 自己定边界：长度前缀或换行 |
| 地址写 `localhost` 解析不了 | 容器里没有 hosts | 写 `127.0.0.1` |
