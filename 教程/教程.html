从零开始学简言

一门中文关键字的编译型语言。十六个章节，每章配一个跑得起来的例子。

一本从零开始的简言入门书。每章配一个能跑的例子，例子在 教程/例子/， 运行结果在 教程/期望/。bash 教程/跑.sh 会把所有例子编一遍、跑一遍、 和期望输出逐字节比对——书里写的每个结果，都是机器验过的。

这是什么语言

简言是一门中文关键字的编译型语言。它想解决两件事：

  1. 让没学过 C 的人也能读懂代码——关键字是中文，没有分号，块必须用 {} 包住；
  2. 编出来的程序要快——直接生成机器码，不打包解释器，速度和 C 在一个量级。

    打印行("你好，简言")
    返回 0
}

01 · 第一个程序

一个简言程序由三样东西组成：模块名、函数、语句。先把最小的那一个写对。

1.1 完整代码

文件 教程/例子/01-你好.jy：

-- 第一章：最小的程序。
-- `模块` 声明这个名字（只能写一次），`主` 是入口，返回值就是退出码。
模块 教程.你好

函数 主() -> 整数 {
    打印行("你好，简言")
    打印("1 + 2 = ")
    打印行(1 + 2)
    返回 0
}

输出：

你好，简言
1 + 2 = 3

1.2 一行一行拆

模块 教程.你好

  • 一个文件一个模块，模块 只能出现一次，而且必须在最前面（注释可以写在它前面）。
  • 名字用点分层：教程.你好 表示"教程"这个大类下的"你好"。
  • 模块名不能用关键字。 写 模块 教程.类型 会被拒绝，因为 类型 是保留字。 这条踩过好几次，报错长这样： 语法错误：这里需要一个名字（点号后面要跟名字），但 `类型` 是语言保留的关键字

函数 主() -> 整数

  • 主 是入口，必须有，返回 整数——这个整数就是进程退出码，0 表示成功。
  • -> 后面是返回类型。没有返回值就不写 ->。
  • 函数体必须用 {} 包住，没有分号，一行一句。

打印行(...) 和 打印(...)

函数 行为
打印行(x) 打印 x，再换行
打印(x) 只打印，不换行

两者都接受任意类型，数字会按十进制、浮点按 %g 风格、布尔打成 真/假。

打印("一共 ")
打印(3)
打印(" 个")
打印行("")

输出 一共 3 个。想拼成一整行，也可以用 .. 拼字符串，但两边必须都是字符串：

打印行("一共 " .. 字符串(3) .. " 个")

注释

-- 单行注释
--[[
   多行注释
]]

注释用两个减号，和 SQL 一样。因为 // 已经被"整除"占用了。

1.3 为什么入口叫 主 不叫 main

因为关键字、内置函数、标准库全是中文的。规则很统一：你能看见的名字都是中文， 只有运算符和标点是半角符号。学了这一条，后面所有名字都不用猜。

1.4 常见的第一天错误

你写的 报错 原因
函数 主() -> 整数 { 打印行("hi") } 提示"不是所有路都会返回" 少了 返回 0。有返回类型就必须每条路都返回
打印行("hi"); 语法错误，实际是 ; 简言没有分号
模块 你好 写在函数后面 语法错误 模块 必须在最前
打印行（"hi"） 语法错误 用了全角括号

最后一条值得单独说：全角符号一律不认。中文输入法很容易打出全角的 （）、，、"， 报错位置会指向一个看起来很正常的字符。看到"这里应该写 ("却明明有括号，先检查全半角。

1.5 小结

概念 写法
模块声明 模块 名字，文件开头，一次
入口 函数 主() -> 整数 { ... 返回 0 }
打印 打印(x) / 打印行(x)
注释 -- 或 --[[ ]]
分号 没有
符号 全半角

2.2 基本类型只有这几种

类型 是什么 例子
整数 64 位有符号，-2⁶³ ~ 2⁶³-1 42、-7、0x1F
浮点 64 位 IEEE754（就是 C 的 double） 3.14、1e9
布尔值 只有 真 / 假 真
字符串 UTF-8 序列，不可变，长度按字符算 "你好"、[[原样文本]]
空值 只有 空 一个值 空

这里没有"整数32/64"的选择焦虑：整数 就是 64 位。规范里还留着 整数8/16/32 的 名字，这一版只在类型表里登记，转换函数还没接，用不上。

2.3 声明：四种写法

常量 整数 一年天数 = 365          -- 编译期算完，此后不可改
整数 全局计数 = 0                 -- 顶层变量，默认公开
私有 整数 局部 = 1                -- 函数里必须写 私有
令 推导 = 42                      -- 让编译器看右边猜类型
不可变 整数 只读 = 10             -- 可改但不许改
修饰 作用 用在哪
常量 编译期求值，不占运行时空间 顶层
私有 仅本模块可见 / 函数局部变量 顶层或函数内
不可变 只读，赋值会报错 任意
令 类型推导，省掉写类型 有初值时

三条容易踩的规则：

  1. 函数里的变量必须写 私有。 漏了会报"找不到 xxx"，因为编译器会把它当成 对已有变量的赋值，而不是新声明。
  2. 令 不能用在函数参数和返回值上。 那两处必须写类型，不然调用方没法检查。
  3. 常量 必须能在编译期算完。 不能读文件、不能调用户函数。

2.4 类型转换：都得写出来

私有 整数 取整 = 整数(3.99)      -- 3，向零截断
私有 整数 负数 = 整数(-3.99)     -- -3，不是 -4
私有 浮点 变浮点 = 浮点(7)        -- 7
私有 字符串 文本 = 字符串(42)     -- "42"

四条规矩：

转换 行为
整数(x) 丢掉小数部分，向零。-3.99 → -3
浮点(x) 精确转换（整数范围内无损）
字符串(x) 十进制文字，浮点按 %g 风格
字符串 → 数字 不用 整数(s)，用 s.转整数()，它返回 结果，失败有原因

为什么字符串转数字要用方法？因为 "abc" 转不了整数，整数("abc") 只能崩溃或者 返回个 0，两种都不好。转整数() 把"转不了"变成一种正常返回值，调用方必须处理。

2.5 字面量

私有 整数 十六 = 0x1F        -- 31
私有 整数 二进制 = 0b1010     -- 10
私有 整数 带下划线 = 1_000_000
私有 浮点 科学 = 1e9
私有 字符串 单行 = "第一行\n第二行"
私有 字符串 原样 = [[
    这里面的 \n 就是两个字符，不转义
]]

[[ ... ]] 是原样字符串，写路径、正则、多行文本时不用一路转义。

2.6 命名

  • 中文、英文、数字、下划线都行，不能以数字开头。
  • 区分大小写。
  • 不能和关键字重名：类型、结果、匹配、接口、复制、空、循环 这些都不行。 连模块名也不行（模块 教程.类型 会被拒绝）。

关键字全是中文，所以写代码时有个天然的好处：看到中文词先怀疑它是不是关键字。 报错说"xxx 是语言保留的关键字"时，换个名字就好。

3.2 四则运算和三种"除法感"

写法 结果 说明
7 / 2 3.5 总是浮点，哪怕两边都是整数
7 // 2 3 整除，向零截断（和 C 一致）
-7 // 2 -3 是 -3 不是 -4，因为向零截断
7 % 3 1 余数，符号跟着被除数
-7 % 3 -1

/ 的设计是有意的。C 里 7/2 得 3，Python 3 里得 3.5，两门语言的人互相看得一头雾水。 简言选了后者：/ 就是数学除法，要整除就明写 //。语义层看到两个整数用 / 还会提示一句"想整除写 //"。

% 只能用于整数。浮点要取余得自己写 甲 - 向下取整(甲 / 乙) * 乙。

3.3 乘方

^ 是乘方，不是异或（异或是 ^^）。右结合，优先级高于一元负号：

打印行(2 ^ 10)    -- 1024
打印行(2 ^ 3 ^ 2) -- 2^(3^2) = 512，不是 (2^3)^2
打印行(-2 ^ 2)    -- -4，即 -(2^2)
打印行(9 ^ 0.5)   -- 3.0，指数可以是浮点

3.4 比较：尖尖朝里是"小于"

这是全语言最容易看错的一处：

写法 含义
a << b a 小于 b
a >> b a 大于 b
a <= b 小于等于
a >= b 大于等于
a == b / a != b 等于 / 不等于

为什么不用 < >？因为 << >> 已经被"远小于/远大于"的视觉习惯占了， 干脆一双一对：<< >> 是比较，<<< >>> 才是移位。

打印行(3 << 5)    -- 真
打印行(3 <<< 5)   -- 24（3 左移 5 位）

3.5 逻辑：与、或、非，短路的

如果 年龄 >= 18 与 有证件 就 { ... }
如果 是周末 或 是节假日 就 { ... }
如果 非 找到 就 { ... }
  • 与 或 只接受布尔值，短路：与 左边假就不看右边，或 左边真就不看右边。
  • 非 是一元，可以写 非 x，也可以写 !x。

短路不只是省事，它是写安全代码的基础：

如果 #组 >> 0 与 组[0] >> 10 就 { ... }   -- 前一半假，后一半根本不算，不会越界

5.2 如果

如果 条件 就 {
    ...
} 否则如果 另一个条件 就 {
    ...
} 否则 {
    ...
}

三条硬规则：

  1. 就 不能省，否则如果 后面也要 就。
  2. 否则 后面不写 就，直接 {。
  3. 条件必须是 布尔值。如果 1 就 编不过——C 那边"非零即真"的习惯在这里行不通。

否则如果 写得再多也不会嵌套成悬崖，因为每个分支都平铺在同一个缩进上。 真需要嵌套就老实缩进，或者把它拆成一个函数：

函数 评级(分: 整数) -> 字符串 {
    如果 分 >= 90 就 { 返回 "优秀" }
    如果 分 >= 60 就 { 返回 "及格" }
    返回 "不及格"
}

这种"早返回"的写法通常比 否则如果 链更好读：每条规则一行，从上往下命中即走。

5.3 当（while）

当 i <= 100 就 {
    和 = 和 + i
    i = i + 1
}

当 和 如果 长得一样，区别只有"回到开头再判一次"。

5.4 对（for）

三种形态：

对 i: 1~10 { ... }                  -- 闭区间，1 到 10 都走
对 i: 0~n, 步长: 2 { ... }          -- 从 0 开始，每次加 2
对 x 在 组 { ... }                  -- 遍历组里的每个元素

注意范围用的是 ~ 不是 ..。.. 是字符串拼接，两个数字写 1..10 会报 ".. 只能拼字符串"。

对 x 在 组 的 x 是元素本身（如果元素是字符串、结构这类"有所有权"的值， 语义层会提示你写 借用 x，因为它默认按值搬走）。

5.5 循环（无限循环）

循环 {
    如果 该走了 就 { 打断 }
}

循环 { } 等价于 当 真 就 { }。用途是"出口在中间"的场景：

私有 整数 已处理 = 0
循环 {
    如果 已处理 >= 总量 就 { 打断 }
    处理(已处理)
    已处理 = 已处理 + 1
}

5.6 打断与继续

语句 作用
打断 跳出最近一层循环
继续 跳过本轮剩下的，进入下一轮

它们只作用于循环，写在循环外会报错：

[错误] `打断` 只能写在循环里，这里不在任何循环中

嵌套循环里 打断 只跳一层。要跳两层，用一个布尔标志：

私有 布尔值 该停 = 假
对 i: 1~9 {
    如果 该停 就 { 打断 }
    对 j: 1~9 {
        如果 i * j >> 40 就 {
            该停 = 真
            打断
        }
    }
}

5.7 条件里不要写赋值

简言没有"赋值表达式"，如果 x = 5 就 是语法错误。这是好事：C 里 if (x = 5) 和 if (x == 5) 打错一个字符就可能查一整天。

6.3 借用：不复制，只读

函数 求和(xs: 借用 整数 组) -> 整数 { ... }

为什么要写 借用？因为组、字符串、结构这些类型默认按值传递——传进去就搬走了， 调用方手里那个变量就没了。借用 说"我只是看看，不拿走"。

调用处也要写 借用，这是刻意的：看到 借用 数 就知道这行不会改 数。

函数 平均(xs: 借用 整数 组) -> 浮点 {

    对 x 在 xs { 和 = 和 + x }
    返回 浮点(和) / 浮点(#xs)
}

同一条规矩也用在结构上：

函数 平移(p: 可变借用 点, dx: 浮点, dy: 浮点) {

    p.y = p.y + dy
}

大整数 小数 复制指针（它们不可变，安全） 大数运算
图 声音 复制句柄（共享同一份数据） 媒体

可变借用 T 借出去改 就地修改

最后一条是规范里的语义：不加修饰地传组/结构，所有权就交出去了。这一版 只提示、不强制，会看到：

提示是给你看的，不是给编译器看的。养成习惯：大块数据一律 借用， 既清楚又不复制，比记住"这一版拦不拦"省心。

7.6 为什么 取 返回可空

库存.取("西瓜")          -- 可空[整数]，可能是 空
库存.取("西瓜").取值      -- 空的时候直接崩
库存.取("西瓜").或默认(0) -- 空的给 0

如果 取 直接返回值，就只有两条路：崩，或者返回一个假的 0。前者太狠，后者 会让你把"没有"当成"数量是 0"。返回 可空 把这件事摆到台面上，你必须选一种处理方式。

如果 库存.取("西瓜") != 空 就 { ... } 之后，块里可以直接 .取值， 编译器知道这里已经确认有值了。

08 · 结构与方法

结构是"几个字段捆在一起"，方法是"挂在结构上的函数"。方法体里直接写字段名， 不用写 自身.——这是简言比别的语言省事的一处。

8.1 完整代码

教程/例子/08-结构.jy：

8.2 声明结构

结构 账户 {
    户名: 字符串
    余额: 整数
}

字段一行一个，不写逗号。 写 { 户名: 字符串, 余额: 整数 } 会报 "这里需要一个名字（字段名），实际是 ,"。这是为了让字段定义和变量声明长得一样。

字段类型必须写。字段可以是任何类型，包括别的结构、组、映射：

结构 矩形 {
    左下: 点
    右上: 点
}

8.3 构造

三种写法，按场景选：

私有 账户 a = { "张三", 100 }                    -- 按字段顺序
私有 账户 b = 新建 账户{ "张三", 100 }            -- 显式类型名 + 顺序
私有 账户 c = 新建 账户{ 余额: 100, 户名: "张三" } -- 写字段名，顺序随便
场景 推荐写法
声明的同时初始化 账户 a = { ... }（靠左边类型推断）
当表达式用：返回、实参、组元素 新建 账户{ ... }
字段多或容易混 新建 账户{ 字段: 值, ... }

在表达式位置一定要写 新建。 裸写 账户{ ... } 会被当成"名字 + 代码块"， 因为花括号在简言里有两个身份。这是硬规则，不是风格建议。

没写的字段自动清零（0、""、假、空）。

8.4 方法与"看不见的自身"

方法写在 实现 类型 为 接口 { ... } 块里：

实现 账户 为 可存取 {
    函数 存(n: 整数) {
        余额 = 余额 + n       -- 余额 就是 自身.余额
    }
}

三件事值得说清楚：

一、接口要先声明。 接口 可存取 { 函数 存(n: 整数) ... } 只写签名， 不写函数体。实现 账户 为 可存取 表示"账户 满足 可存取"。

二、方法体里字段就是普通变量。 编译器给每个方法偷偷加了第 0 个参数 自身， 类型是结构本身；余额 被改写成 自身.余额。所以你在方法里写 余额 = 余额 + n 就等于改这个对象。

三、改字段的方法，自身自动是 可变借用。 不用手写。上例的 存 改了 余额， 编译器就把 自身 定为可变借用，调用 a.存(50) 改的真是 a。

只有读的方法，自身 就是普通借用：

函数 余额文本() -> 字符串 {
    返回 户名 .. " 有 " .. 字符串(余额) .. " 元"
}

8.5 调用

打印行(a.余额文本())
a.存(50)
如果 a.取(30) 就 { ... }

调用时对象自动当第一个实参传，你只写自己声明的那些参数。

方法不会自动链式返回自身。 a.存(50) 没有返回值（返回类型是空）， 所以不能写 a.存(50).存(20)。要连续调用就分两行。

8.6 什么时候该用结构

信号 说明
三个以上值总是一起出现 x, y, w, h 到处传，该合成一个 矩形
函数返回多个值 用结构包，别用全局变量
有一组操作只对某类数据有意义 把数据和方法放一起

反过来说，两个字段的小东西不必都做成结构。点 有 x y 是值得的， 一对整数 通常不值得。

8.7 常见错误

现象 原因
这里需要一个名字（字段名），实际是 , 字段之间加了逗号
这里需要一个表达式，实际是 自身 这一版 自身 还不能当表达式用，方法里直接写字段名
找不到接口 形状 实现 写在 接口 前面了，接口必须先声明

09 · 枚举与匹配

枚举不是"几个常量换名字"，它能给每个变体带上不同的数据。 配合 匹配，一条分支处理一种情况，漏一种编译器就报错。

9.1 完整代码

教程/例子/09-枚举.jy：

模块 教程.形状

枚举 形状 {
    圆(半径: 浮点)
    矩形(宽: 浮点, 高: 浮点)
    点
}

函数 面积(s: 借用 形状) -> 浮点 {
    匹配 s {
        例 形状.圆(半径): { 返回 3.14159 * 半径 * 半径 }
        例 形状.矩形(宽, 高): { 返回 宽 * 高 }
        例 形状.点: { 返回 0.0 }
    }
}

函数 描述(s: 借用 形状) -> 字符串 {
    匹配 s {
        例 形状.圆(半径): { 返回 "圆 r=" .. 字符串(半径) }
        例 形状.矩形(宽, 高): { 返回 "矩形 " .. 字符串(宽) .. "×" .. 字符串(高) }

9.2 声明

枚举 形状 {
    圆(半径: 浮点)
    矩形(宽: 浮点, 高: 浮点)
    点
}
部分 说明
变体名 大写开头更常见，但语言不强制
带数据的变体 名字(字段: 类型, ...)，字段类型写全
不带数据的变体 光写名字
一行一个 同结构，不写逗号

同一个枚举里各变体的数据可以完全不同。 这是它比"一堆整数常量"强的地方： 圆 有一个半径，矩形 有两个，点 什么都没有，但在类型系统里它们都是 形状。

9.3 构造

私有 形状 甲 = 形状.圆(2.0)
私有 形状 乙 = 形状.矩形(3.0, 4.0)
私有 形状 丙 = 形状.点

带数据的变体像函数调用，不带数据的变体就是一个值。前缀 形状. 不能省， 省了会报"找不到 圆"。

如果有一个变体实在没法穷尽（比如以后还会加），可以用 默认 兜底：

匹配 s {
    例 形状.圆(半径): { 返回 半径 }
    默认: { 返回 0.0 }
}

加了 默认 就等于放弃穷尽检查——以后新增变体会静悄悄落进 默认。 除非真有必要，宁可写全。

9.4 匹配

匹配 s {
    例 形状.圆(半径): { ... }
    例 形状.矩形(宽, 高): { ... }
    例 形状.点: { ... }
}

三条规则：

  1. 必须写全。漏掉一个变体会报错：匹配 没有处理 点，也没写 默认。枚举必须穷尽。
  2. 括号里是绑定。圆(半径) 把这个变体带的那个值绑到局部变量 半径 上， 块里直接用。不想要名字可以写 _。
  3. 每个 例 冒号后面必须跟着 {}，哪怕只有一句。

匹配 是语句，不是表达式：它不"返回"值。要在分支里给结果，就在分支里 返回， 或者给外层变量赋值：

私有 浮点 结果 = 0.0
匹配 s {
    例 形状.圆(半径): { 结果 = 3.14159 * 半径 * 半径 }
    例 形状.矩形(宽, 高): { 结果 = 宽 * 高 }
    例 形状.点: { 结果 = 0.0 }
}

9.5 为什么不用 if 判断

-- 不推荐：类型关系埋在条件里，加一个变体就要改三处
如果 是圆(s) 就 { ... } 否则 如果 是矩形(s) 就 { ... }

-- 推荐：一处列全，漏了编译器提醒
匹配 s {
    例 形状.圆(半径): { ... }
    例 形状.矩形(宽, 高): { ... }
    例 形状.点: { ... }
}

真正的好处是加变体的时候。三个月后你给 形状 加了个 三角形， 所有 匹配 它的地方会立刻编译失败，一处一处补。如果是 if 链，漏掉的地方 会安静地走 否则 分支，错在运行时。

9.6 借用还是复制

枚举通常比机器字大（要装下最大的那个变体），所以传参一般写 借用：

函数 面积(s: 借用 形状) -> 浮点

匹配 s 时 s 是借来的，绑定出来的 半径、宽 也都是借来的视图， 只读没问题。要拿走里面的数据（比如把 圆 的半径取出来存起来）， 就把它赋给一个新变量，语义层会提示你该怎么写。

9.7 这一版的限制

匹配 目前只支持枚举变体这一种模式。规范里的字面量和范围分支 （例 0:、例 1~9:）还没接，写了会得到一条 C 编译错误。用整数分情况时， 这一版请写 如果 ... 否则如果 ...。

9.8 小结

想干什么 写法
定义 枚举 名 { 变体(字段: 类型) ... }
构造 名.变体(值, ...)
分情况 匹配 x { 例 名.变体(绑定): { } }
兜底 枚举不需要兜底——写全就行
穷尽检查 编译器自动做

10 · 泛型

泛型就是"类型先空着，用的时候填"。简言的实现方式是单态化：每个具体类型 各生成一份代码，运行时没有任何额外开销——但代价是二进制会变大。

10.1 完整代码

教程/例子/10-泛型.jy：

模块 教程.通用

函数 最大[T: 可比较](甲: T, 乙: T) -> T {
    如果 甲 >> 乙 就 { 返回 甲 }
    返回 乙
}

函数 三个最大[T: 可比较](甲: T, 乙: T, 丙: T) -> T {
    返回 最大(最大(甲, 乙), 丙)
}

函数 总和[T](xs: 借用 T 组) -> T {
    私有 T 和 = xs[0]
    私有 整数 i = 1
    当 i << #xs 就 {
        和 = 和 + xs[i]
        i = i + 1
    }
    返回 和
}

函数 主() -> 整数 {

函数 名字[T](x: T) -> T              -- 无约束

[T] 类型参数，习惯用大写单字母

约束只是"承诺"，这一版不做严格校验：写了 [T: 可比较] 但函数体里没比大小也能过； 反过来，没写约束却在函数体里比大小，也能过（单态化到具体类型时才真正检查）。 写上是好习惯——它是给人看的文档。

10.3 一份代码，多份产物

最大(3, 9)          -- 生成 最大$整数
最大(1.5, 2.5)      -- 生成 最大$浮点
最大("abc", "abd")  -- 生成 最大$字符串

三个调用，编译器生成三份独立的机器码。好处是运行时没有类型判断—— 调用 最大$整数 就是一条 cmp 加两条 jcc，和手写的没区别。 代价是代码体积随用到的类型数线性增长。

这就是"单态化"。C++ 的模板、Rust 的泛型都是这个路子。Java 的擦除和 Go 早期的 字典方案走的是另一条路：运行时查表，代码只有一份，但每次调用多一层间接。

10.4 泛型也能用在容器上

函数 总和[T](xs: 借用 T 组) -> T {
    私有 T 和 = xs[0]
    私有 整数 i = 1
    当 i << #xs 就 {
        和 = 和 + xs[i]
        i = i + 1
    }
    返回 和
}

T 组 就是"元素是 T 的组"。传 整数 组 生成一份，传 浮点 组 再生成一份。

注意这个函数用了 +，所以它只对"能相加"的类型成立。字符串不行（拼接要写 ..）， 结构也不行（没定义加法）。想要更通用的"归约"，就得把操作也传进来——这一版 函数值还不能当参数调用，所以先这样。

10.5 什么时候用泛型

场景 用不用
逻辑和类型无关，只是"装东西、比大小、遍历" 用
只有一两种类型会用 不用，直接写两个函数更清楚
需要在里面调用类型特有的方法 不用，泛型表达不了

一个实用的判断：如果函数体里出现了只属于某个类型的方法名，那它就不该是泛型的。

11.5 三种错误处理风格的取舍

风格 优点 缺点
崩溃（越界、除零） 简单，不放过 bug 线上跑着跑着挂掉
可空 逼你处理"没有" 没有原因，不知道为啥没有
结果 有原因，能往上抛 每层都要判，代码变长

简言的建议：

  • "没有"是正常情况 → 可空。例：查表、找下标、取 越界。
  • "失败"是异常情况，且调用方需要知道为什么 → 结果。例：读文件、解析文本。
  • 程序员写错了 → 让它崩。数组越界、除以零、.取值() 取到空，都直接终止。

13.4 句柄语义：赋值不复制

私有 图 甲 = 新建图(100, 100)
私有 图 乙 = 甲          -- 不是复制！乙 和 甲 是同一张图
乙.设(0, 0, 色(255, 0, 0))
打印行(甲.取(0, 0))     -- 也变了

为什么这样设计？一张 1200×750 的图是 3.6 MB。如果每次赋值都拷一份， 写起来轻松、跑起来灾难。所以赋值和传参只搬那个 24 字节的句柄。

声音一样：.放大(1.0) 是最省事的"复制一份"。

14 · 编译与性能

简言有两条后端：C 后端（IR → C → gcc）和原生后端（IR → x86-64 汇编 → 自己的汇编器 → ELF）。 原生后端连 as 和 ld 都不用，最后一步是自己写的。 两条路的产物都是机器码，输出逐字节一致。这一章讲怎么用、差在哪、为什么快。

14.1 示例程序

教程/例子/14-后端.jy：

模块 教程.后端

    私有 整数 计数 = 0
    私有 整数 i = 2
    当 i <= n 就 {
        私有 整数 j = 2
        私有 布尔值 是素 = 真
        当 j * j <= i 就 {
            如果 i % j == 0 就 {
                是素 = 假
                j = i
            }
            如果 是素 就 { j = j + 1 }
        }
        如果 是素 就 { 计数 = 计数 + 1 }

14.4 实测速度

同一批程序，三种产物，单位毫秒，各跑 3 次取最好（bash 后端/基准/跑.sh 可复现）：

用例 gcc -O2 栈机版 寄存器版 与 gcc
热循环 3 千万次 54 177 68 1.25×
混合 5 千万次（乘加掩码链） 68 176 68 1.00×
整除 3 千万次（%7 / //3） 31 123 46 1.48×
调用 5 千万次 81 224 75 0.92×
素数 40 万（两层循环 + idiv） 37 76 37 1.00×
斐波那契 fib(35) 11 88 45 3.75×

三件事值得说：

一、"栈机版"是上一代。 那时候每个 IR 值有一个固定栈槽，算一条加法是 载－算－存 三步。换成寄存器之后快到 2.6 倍——慢的根因不是"没优化"， 是"每条指令都在访问内存"。

二、调用那一项反超 gcc。 因为它把小函数全内联，代码膨胀反而拖慢了指令缓存。 简言不做内联，代码小，icache 友好。

三、斐波那契差 3.75 倍，但原因不在调用开销（看上一行就知道）。gcc 把 fib(n-1) + fib(n-2) 整个改写成了嵌套循环加累加器。那是"递归转循环"，另一件事， 这一版没做。

14.5 快在哪：四件事

一、值住在寄存器里。 活跃变量分析 + 线性扫描，11 个通用寄存器参与分配， 不够才溢出回栈。%rax %rcx %rdx 留作手边临时——除法要 rax:rdx、移位要 cl、 返回值在 rax，与其到处打补丁不如不分配。

二、载/存 就地化简。 IR 里变量读写是一对 mov，绝大多数是白搬的：

v = 载 x（v 只用一次）        → 那次使用直接用 x
v = 算...（v 只被 存 用一次）  → 让算式直接写进变量槽

和 = (和*31 + i) & mask 从 11 条指令变成 4 条。

三、指令选择。 加法走 lea（三地址、不碰标志位），小常数走立即数， 比较直接跟条件跳合起来（如果 a << b 从 4 条变 2 条），块尾落空不打 jmp。

四、除以常数换乘魔数。 idiv 一条二三十个周期，换成"取绝对值 → 无符号乘 → 取高 64 位 → 贴回符号"。

最关键的是编译期当场验：算完魔数拿一批样本（±1、±d、±2⁶²、随机数）跟真除法比， 验不过就退回 idiv。所以"魔数写错"最多让程序变慢，不会让它算错。

14.7 为什么坚持"逐字节一致"

测试.sh 末尾有一段原生对拍，规矩是：

  • 编不出来 → 记一个 ·，不算失败（覆盖还没做完，这是预期内的）
  • 编得出来 → 输出必须和 C 后端的期望文件逐字节一致，错一个字就失败

为什么这么定：能编但编错，比编不出来危险得多。后者你马上就知道； 前者要到某个数对不上才发现，而那时候你已经不知道是 IR 错了还是汇编错了。

16 · 并发

一个 线程 { ... } 就是一个真的新线程，不是"排个队等会儿跑"。 线程之间不共享变量，只共享通道——想递东西过去，就 发送。

16.1 完整代码

教程/例子/15-并发.jy：

-- 两个工人、两条线程，从同一个"活"通道领任务，把结果发到"果"通道。
-- 谁领到哪一件不固定，所以结果按件号归位再打印——
-- 并发程序只保证结果集合确定，不保证顺序。

模块 教程.并发

函数 工人(活: 通道[整数], 果: 通道[字符串]) -> 整数 {
    循环 {
        私有 可空[整数] 件 = 接收 活
        如果 件.有值 就 {
            私有 整数 值 = 件.取值()
            -- 一件成果拼成 "件号|文字"。件号写进去是为了让主线程能归位，
            -- 打印出来的是确定的那一半：谁做的看不出来，快的人会抢更多。
            发送 果, 字符串(值) .. "|" .. 字符串(值) .. " → " .. 字符串(值 * 2)
        } 否则 {
            返回 0
        }
    }
}

函数 主() -> 整数 {
    私有 通道[整数] 活 = 通道[整数](4)
    私有 通道[字符串] 果 = 通道[字符串](4)

    线程 { 工人(活, 果) }
    线程 { 工人(活, 果) }

    对 i: 1~4 {
        发送 活, i
    }
    关闭 活

    私有 映射[整数, 字符串] 收 = {}
    对 i: 1~4 {
        私有 可空[字符串] 条 = 接收 果
        如果 条.有值 就 {
            私有 字符串 组 段 = 条.取值().切分("|")
            收.插入(段[0].转整数().或默认(0), 段[1])
        }
    }
    打印行("两个工人抢 4 件活，结果按件号排好：")
    对 i: 1~4 {
        打印行(收.取(i).或默认("丢了"))
    }
    返回 0
}

具体哪件活落到哪个工人手里不固定，所以例子把结果按件号塞进映射、再按 1~4 打印。 并发程序只要结果集合确定，就不必关心谁先谁后——这条习惯能省掉大量调试。

16.2 通道是唯一的桥

线程之间不能共享局部变量。这不是限制，是设计：

私有 整数 计数 = 0
线程 {
    计数 = 计数 + 1      -- 报错：线程块里改不了外层的 计数
}

报错会直接告诉你怎么办：

线程块里改不了外层的 `计数`。线程体是独立函数，外层变量按值拷进来，改了外面看不到。
    想让它把结果带出去，就 `发送` 到通道里，外面 `接收`。

为什么按值拷？ 因为线程体是一个独立的函数，它有自己的栈。外层变量是按值传进去的 （字符串、组、映射、通道在 C 里都是"头 + 指针"，拷一份头等于共享同一块内存）。 如果允许写，你写的是副本，外面永远看不到——这种"写了等于没写"比报错难查得多， 所以编译器把这种情况当错误拦下来。

读外层变量是允许的，也很有用：

私有 整数 基数 = 100
线程 {
    发送 报, 基数 + 1      -- 可以，拷贝一份进去
}

16.3 通道满了会等，空了也会等

私有 通道[整数] 管 = 通道[整数](2)    -- 容量 2
操作 通道空 通道有货 通道满 已关闭
发送 管, x 直接放进 直接放进 阻塞等，直到有人取走 直接返回，什么也不做
接收 管 阻塞等，直到有人送来 取走一个 取走一个 立刻返回 空

这就是"生产者消费者"能自动调速的原因：生产者再快，也会被容量卡住； 消费者再慢，也不会让内存无限涨。

阻塞意味着死锁是可能的：

私有 通道[整数] 管 = 通道[整数](1)
发送 管, 1        -- 放了 1 个
发送 管, 2        -- 满了，主线程在这里永远等下去：没人接收

写并发程序时记住一条：谁发送，谁就要保证有人在接收（或者容量足够）。

16.4 关闭：告诉对方"没有更多了"

关闭 管

关闭之后：

  • 接收 管 立刻返回 空（不再等）——这是循环该收尾的信号；
  • 发送 管, x 静默丢弃（不报错、不崩）。

所以"读到一个通道直到没有"的标准写法是：

循环 {
    私有 可空[整数] 件 = 接收 管
    如果 件.有值 就 {
        -- 处理
    } 否则 {
        打断           -- 关了，而且已经读空
    }
}

关闭 只能由发送方调用。接收方去关，发送方会以为还能发。

16.5 主线程不能先走

线程 { } 开出来的线程是分离态（detached）：主线程不会等它。 主函数一返回，整个进程就退出了，还在跑的线程会被直接掐掉。

函数 主() -> 整数 {
    线程 {
        对 i: 1~1000000 { 算点东西() }
    }
    返回 0        -- 错：线程可能一个都没算完就走了
}

正确做法是等一个信号：

私有 通道[整数] 完成 = 通道[整数](1)
线程 {
    ...
    发送 完成, 1
}
私有 可空[整数] 收尾 = 接收 完成     -- 等到它说完了再往下走
返回 0

后端/测试/网络.jy 就是这么收尾的。

16.6 什么时候该用线程

场景 该不该开线程
一边算一边响应用户 该，典型的生产者消费者
多个互不相干的任务 该，结果用通道汇总
只是想让代码"看起来高级" 不该，顺序执行更快也更好查
共享一大块数据反复改 谨慎，先想清楚用通道传递而不是共享

这一版的线程没有优先级、没有线程池、没有 等待线程结束 的 API。 需要"等"就用通道发个完成信号——这反而逼着你想清楚数据从哪来到哪去。

16.7 一个常见错误的对照表

写法 结果
线程 { 计数 = 计数 + 1 } 编译错误：改不了外层变量
线程 { 发送 报, 基数 } 正确，基数 按值拷进去
主函数不等就 返回 线程被掐断，可能什么都没做
容量 1 的通道连发两次、无人接收 死锁（第二次发送永远等）
关闭 管 之后还 发送 静默丢弃，不报错
接收 不判断 有值 就 .取值() 读到空值时崩（和可空一样）

16.8 这一版没做的

  • 真并发安全的数据共享：没有锁、没有原子操作。要共享就用通道传，别共享。
  • 线程池 / 任务队列：每次 线程 { } 都是一个新 OS 线程，开销约 8 KB 栈起。
  • 取消：没有"让某个线程停下来"的办法，只能靠它自己读到关闭信号。

这三样都需要更底层的设计（内存模型、调度器、取消点），不是加几个函数能补的。 现在的边界很清楚：线程 + 通道够写生产者消费者，不够写共享内存的多线程数据结构。

17 · 网络

两个句柄类型：监听器 等连接进来，套接字 是进来之后的那个连接。 再加一个 HTTP取，一句话抓网页。

17.1 完整代码

教程/例子/16-网络.jy：

模块 教程.网络

函数 主() -> 整数 {
    私有 结果[监听器, 字符串] 听 = 监听("0.0.0.0", 0)
    如果 听.是失败 就 {

客户端收到：服务端回声：喂，服务端

17.2 三个动作：监听、连接、接受

角色 代码 说明
服务端 监听("0.0.0.0", 8080) 绑定并开始等。端口写 0 让内核挑一个空闲的
服务端 器.接受() 阻塞，直到有人连进来
客户端 连接("127.0.0.1", 8080) 连上去，返回 套接字

两者都返回 结果[...]，失败时 .错误值 是一句中文：

监听失败：端口被占用了
客户端连不上：连不上

监听("0.0.0.0", 0) 之后再 器.端口() 就能拿到内核分配的真实端口。 服务端写 0、客户端去问端口，是多进程测试里最省事的做法——不用猜哪个端口空着。

17.3 读和写

方法 返回 说明
客.读(n) 字符串 最多 n 字节。对端关了给空串
客.写(s) 整数 实际写了多少字节
客.读全部() 字符串 一直读到对端关闭
客.设超时(毫秒) — 读写超时。0 表示不限
客.对端() 字符串 "127.0.0.1:54321"
客.关闭() — 关掉这个连接

读(n) 可能读不满。 TCP 是字节流，不是消息流：你发 100 字节，对端可能 分三次收到 40、40、20。所以"发一条消息、收一条消息"的协议必须自己定边界 （长度前缀、换行、或者像 HTTP 那样用 Content-Length）。

这个例子里两端都是本机、消息很短，一次就读完了。真写协议别赌这个。

读全部() 会等到对端关闭才返回。如果对端不关，就一直等。所以：

客.设超时(3000)          -- 3 秒没动静就断
私有 字符串 回 = 客.读全部()

超时之后 读 返回空串，读全部 返回已经读到的部分。这一版不区分 "对端关了"和"超时了"——都是空/短。要分开得再加一个查询方法。

17.4 一句话抓网页：HTTP取

私有 结果[字符串, 字符串] 回 = HTTP取("http://example.com/")
如果 回.是成功 就 {
    打印行(回.取值())
}

HTTP取 做四件事：拆网址 → 连接 → 发一个 GET 请求 → 读全部。 返回的是整个响应，包括状态行和头：

HTTP/1.1 200 OK
Date: Sat, 21 Nov 2026 19:54:50 GMT
Content-Type: text/html; charset=utf-8
...
<!doctype html>
<html>...

想只拿正文，就找第一个空行切开：

函数 正文(响应: 借用 字符串) -> 字符串 {
    私有 字符串 组 段 = 响应.切分("\r\n\r\n")
    如果 #段 >> 1 就 { 返回 段[1] }
    返回 响应
}

限制写清楚：

  • 只认 http://（明文）。https:// 要 TLS，这一版没有；
  • 只发 HTTP/1.0，所以对端回完就关，读全部 正好读到结尾；
  • 不跟随重定向，不分块传输，不处理 gzip。

够抓静态页和调自己的接口，不够当浏览器。

17.5 服务端怎么写才不崩

最简单的服务端就是"接一个、处理、关掉"：

私有 结果[监听器, 字符串] 听 = 监听("0.0.0.0", 8080)
私有 监听器 器 = 听.取值()
循环 {
    私有 结果[套接字, 字符串] 接 = 器.接受()
    如果 接.是失败 就 { 打断 }
    私有 套接字 客 = 接.取值()
    私有 字符串 请求 = 客.读(4096)
    客.写("HTTP/1.0 200 OK\r\nContent-Length: 2\r\n\r\n好")
    客.关闭()
}

一次只服务一个人。要同时服务多个，就在 接受 之后开线程：

循环 {
    私有 结果[套接字, 字符串] 接 = 器.接受()
    如果 接.是失败 就 { 打断 }
    私有 套接字 客 = 接.取值()
    线程 {
        处理(客)
    }
}

注意 客 是句柄，线程里拿到的和外面是同一个连接，这没问题。 但循环变量 接 每轮都是新变量，所以不会有"上一个线程拿了下一个连接"的经典 bug。

15.8 排错的三个习惯

一、先看第一个错误。 后面的报错经常是第一个引起的连锁反应。修完第一个再编一次。

二、把范围缩到最小。 二十行的函数报错，删到五行还能复现，问题就在那五行里。

三、用 -c 看后端生成了什么。 语法语义都过了、C 编译却失败，说明是后端的问题：

./简编译 坏例子.jy -c /tmp/看.c
sed -n '/简言函数：主/,/^}/p' /tmp/看.c

生成的 C 相当直白——每个 IR 值一个变量，控制流用 goto。看懂它不难， 而且看一次就能明白"为什么这条语句生成了这样的代码"。

15.9 一句话

报错是编译器在替你干活。 简言的报错尽量写清"哪里错、为什么错、怎么改"， 遇到读不懂的，那多半是编译器的问题——记下来，去 规范/ 里补一条。

19 · 在手机上写简言

前十八章都在电脑上跑。这一章换个地方：把简言装进安卓手机。

为什么不是"交叉编译一下"

最直接的想法是把 简编译 交叉编译成 arm64 的可执行文件。这个想法会在三个地方撞墙：

想法 撞在哪
交叉编译 简编译 它最后一步是调 gcc 生成机器码，手机上没有 gcc
用原生后端 自出的 ELF 是 x86-64，改 arm64 等于重写指令选择
编成 .so，运行时 exec Android 10 起禁止 exec 应用私有目录

第三条最容易忽略：在 adb shell 里手动跑得好好的，装成 App 就 Permission denied。 这不是权限没申请，是系统策略。

所以手机上走的是解释执行：不生成机器码，按中间表示一条条算。 它与 CPU 无关，也就与 arm64 / x86 无关。

装上去

bash 手机/构建.sh          # 出一个 /workspace/简言.apk
adb install -r /workspace/简言.apk

APK 212 KB：7.6 KB 的编辑器界面、3.2 KB 的 dex、204 KB / 211 KB 的 .so。 里面是整个编译器前端加解释器——词法、语法、语义、IR 一条都没少， 所以手机上看到的报错和电脑上是同一句。

能写什么

打开 App，界面上是一个编辑框、一个运行按钮、一块输出。

模块 教程.统计

函数 主() -> 整数 {
    私有 整数 组 分 = {88, 92, 79, 95, 61}
    私有 整数 和 = 0
    对 x 在 分 {
        和 = 和 + x
    }
    打印行("总分 " .. 字符串(和))
    打印行("平均 " .. 字符串(浮点(和) / 浮点(#分)))
    返回 0
}

手机上支持的东西：

  • 整数（含 整数8/16/32 的位宽截断）、浮点、布尔、字符串
  • 组、映射、结构、枚举
  • 函数、递归、函数值
  • 字符串方法、数学函数、结果类型
  • 引入（同目录的相对路径）

不接的，遇到会明确告诉你：图片、声音、大数、线程、通道、网络。

三个看不见的坑

一、字符串常量的引号。 中间表示里存的常量是源码原文，带引号。 C 后端有个 写字面量 做反转义，解释器一开始没做，于是 打印行("你好") 输出 "你好"。两处必须逐字一致，否则同一个字符串在两边长度都不一样。

二、零值结构没有字段表。 私有 矩形 r 不写初值时，IR 给一条"常量 零值"。 解释器只把数值置零、没建字段表，后面 r.左下 = ... 就找不到落点。

三、APK 里没有 classes.dex。 d8 把 dex 写在 dex/ 子目录，构建脚本 cd 到工作目录后 zip classes.dex ——目录里没有这个文件。zip 只警告一声， APK 照样签了出来。能装，点了就闪退，构建阶段完全看不出来。

第三个的修法不是"小心一点"，是在签名前把内容念一遍：

unzip -l "$APK" classes.dex | grep -q classes.dex || exit 1

为什么值得有一个解释器

它不只是"手机上的玩具"。同一个程序，现在有三条执行路径：

C 后端（gcc -O2）  ==  原生后端（自出 ELF）  ==  解释器

三方输出逐字相同，才算这个程序"语义清楚"。任何一条路径算得不一样， 就说明某处有个没人写进规范的隐含假设。

手机/测试.sh 就是这么用的：22 个用例对拍，6 个"明确不支持"的边界检查， 再加一层执行链路自测（写文件 → fork → 读管道 → 崩溃隔离）。
