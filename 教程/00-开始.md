# 第 0 章 · 开始

> 十分钟内让你看到第一行输出。顺便把仓库里每个目录是干什么的说清楚。

## 0.1 需要什么

| 项 | 要求 | 为什么 |
|---|---|---|
| 系统 | Linux x86-64 | 原生后端出的是 x86-64 汇编 |
| 编译器 | `gcc` | C 后端要靠它收尾 |
| 构建 | `make` | 一键编 169 个第三方源文件 |
| 汇编与链接 | `as`、`ld` | 原生后端用，`gcc` 装了一般就有 |

不需要联网，`第三方/` 里已经有 libtommath、mpdecimal、dr_libs、stb 的源码。

## 0.2 编出编译器

```bash
cd 简言/后端
make
```

大约 12 秒，产出 `后端/简编译`（一个几 MB 的可执行文件）。它是自包含的：
词法、语法、语义、IR、两个后端全在一个文件里编出来。

```bash
ls -l 简编译
# -rwxr-xr-x 1 ... 简编译
```

## 0.3 跑第一个程序

```bash
./简编译 ../教程/例子/01-你好.jy -o /tmp/你好
/tmp/你好
```

```
你好，简言
1 + 2 = 3
```

`-o` 是输出文件名。不写 `-o` 就生成 `a.out`。

## 0.4 三条命令走完整个工具链

`简编译` 有三种"停在哪一步"的用法：

```bash
./简编译 程序.jy              # 默认：出可执行文件（走 C 后端）
./简编译 程序.jy -c 程序.c     # 只出 C 代码，不编
./简编译 程序.jy -n -o 程序    # 走原生后端：IR → 汇编 → as → ld
./简编译 程序.jy -S 程序.s     # 只出汇编，不汇编
```

同一个程序，三条路：

```
 程序.jy ──词法──语法──语义──IR──┬── C 后端 ──→ 程序.c ──gcc──→ 可执行
                                  ├── 原生后端 ──→ 程序.s ──as/ld──→ 可执行
                                  └── -S ──→ 程序.s（就到这儿）
```

## 0.5 仓库长什么样

| 目录 | 内容 |
|---|---|
| `规范/` | 语言规范、后端设计、踩过的坑。改语言之前先看这里 |
| `词法/` `语法/` `语义/` `中间/` | 编译器的四个阶段，各一个 `.c` |
| `后端/` | `简编译.c`（C 后端）+ `简汇编.c`（原生后端）+ 测试、示例、基准 |
| `第三方/` | 大数、音频、图像、字体库，以及把它们接进语言的胶水层 |
| `教程/` | 就是你正在读的这本 |
| `渲染/` | 光线追踪参考实现，用来验证"这语言能写正经程序" |

## 0.6 顺手跑一遍测试

```bash
cd 后端
bash 测试.sh
```

会看到类似：

```
✓ 基础
✓ 字符串
...
通过 20，失败 0
=== 原生后端对拍 ===
✓ 原生 原生
...
原生：过 5，错 0，跳过 15
```

规矩是：**C 后端编出来的输出必须和 `测试/期望/*.txt` 逐字节一致；
原生后端编得出来的，必须和 C 后端逐字节一致。** 编不出来不算失败（覆盖还没做完），
编出来却算错才算失败——因为后者更危险。

教程里的每个例子都进了同一套比对，脚本是 `教程/跑.sh`。
