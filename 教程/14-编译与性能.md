# 第 14 章 · 编译与性能

> 简言有两条后端：C 后端（IR → C → gcc）和原生后端（IR → x86-64 汇编 → as/ld）。
> 两条路的产物都是机器码，输出逐字节一致。这一章讲怎么用、差在哪、为什么快。

## 14.1 示例程序

`教程/例子/14-后端.jy`：

```简言
模块 教程.后端

函数 素数个数(n: 整数) -> 整数 {
    私有 整数 计数 = 0
    私有 整数 i = 2
    当 i <= n 就 {
        私有 整数 j = 2
        私有 布尔值 是素 = 真
        当 j * j <= i 就 {
            如果 i % j == 0 就 {
                是素 = 假
                j = i
            }
            如果 是素 就 { j = j + 1 }
        }
        如果 是素 就 { 计数 = 计数 + 1 }
        i = i + 1
    }
    返回 计数
}

函数 主() -> 整数 {
    打印("100 以内素数 ") 打印行(素数个数(100))
    打印("1000 以内素数 ") 打印行(素数个数(1000))
    打印("10000 以内素数 ") 打印行(素数个数(10000))
    返回 0
}
```

```
100 以内素数 25
1000 以内素数 168
10000 以内素数 1229
```

两条后端跑出来一模一样：

```bash
./简编译 例子/14-后端.jy -o /tmp/a        # C 后端
./简编译 例子/14-后端.jy -n -o /tmp/b     # 原生后端
diff <(/tmp/a) <(/tmp/b) && echo 一致
```

## 14.2 命令一览

```bash
简编译 程序.jy                  # C 后端，出 a.out
简编译 程序.jy -o 名字           # 指定输出名
简编译 程序.jy -c               # 只出 C 代码，打到 stdout
简编译 程序.jy -c 程序.c         # 只出 C 代码，写文件
简编译 程序.jy -n -o 名字        # 原生后端
简编译 程序.jy -S 程序.s         # 只出汇编
```

## 14.3 产物对比

同一个程序（`测试/原生.jy`）：

| | C 后端 | 原生后端 |
|---|---|---|
| 中间产物 | C 源码 | x86-64 汇编 |
| 谁收尾 | `gcc -O2` | `as` + `ld` |
| 运行时 | 内嵌 C 运行时，链 libc | 裸 `syscall`，不链任何库 |
| 体积 | 16144 字节 | **9272 字节** |
| 动态依赖 | libc | `not a dynamic executable` |

```bash
$ file /tmp/b && ldd /tmp/b
/tmp/b: ELF 64-bit LSB executable, x86-64, statically linked
        not a dynamic executable
```

原生版更小，不是因为优化得好，是因为它**什么都没有**：没有 libc 启动代码、
没有 stdio 缓冲、没有 `printf` 那一整套格式化引擎。

## 14.4 实测速度

同一批程序，三种产物，单位毫秒，各跑 3 次取最好（`bash 后端/基准/跑.sh` 可复现）：

| 用例 | gcc -O2 | 栈机版 | 寄存器版 | 与 gcc |
|---|---:|---:|---:|---:|
| 热循环 3 千万次 | 54 | 177 | **68** | 1.25× |
| 混合 5 千万次（乘加掩码链） | 68 | 176 | **68** | 1.00× |
| 整除 3 千万次（`%7` / `//3`） | 31 | 123 | **46** | 1.48× |
| 调用 5 千万次 | 81 | 224 | **75** | **0.92×** |
| 素数 40 万（两层循环 + idiv） | 37 | 76 | **37** | 1.00× |
| 斐波那契 fib(35) | 11 | 88 | **45** | 3.75× |

三件事值得说：

**一、"栈机版"是上一代。** 那时候每个 IR 值有一个固定栈槽，算一条加法是
`载－算－存` 三步。换成寄存器之后快到 2.6 倍——**慢的根因不是"没优化"，
是"每条指令都在访问内存"**。

**二、调用那一项反超 gcc。** 因为它把小函数全内联，代码膨胀反而拖慢了指令缓存。
简言不做内联，代码小，icache 友好。

**三、斐波那契差 3.75 倍**，但原因不在调用开销（看上一行就知道）。gcc 把
`fib(n-1) + fib(n-2)` 整个改写成了嵌套循环加累加器。那是"递归转循环"，另一件事，
这一版没做。

## 14.5 快在哪：四件事

**一、值住在寄存器里。** 活跃变量分析 + 线性扫描，11 个通用寄存器参与分配，
不够才溢出回栈。`%rax %rcx %rdx` 留作手边临时——除法要 `rax:rdx`、移位要 `cl`、
返回值在 `rax`，与其到处打补丁不如不分配。

**二、`载/存` 就地化简。** IR 里变量读写是一对 `mov`，绝大多数是白搬的：

```
v = 载 x（v 只用一次）        → 那次使用直接用 x
v = 算...（v 只被 存 用一次）  → 让算式直接写进变量槽
```

`和 = (和*31 + i) & mask` 从 11 条指令变成 4 条。

**三、指令选择。** 加法走 `lea`（三地址、不碰标志位），小常数走立即数，
比较直接跟条件跳合起来（`如果 a << b` 从 4 条变 2 条），块尾落空不打 `jmp`。

**四、除以常数换乘魔数。** `idiv` 一条二三十个周期，换成"取绝对值 → 无符号乘 →
取高 64 位 → 贴回符号"。

最关键的是**编译期当场验**：算完魔数拿一批样本（±1、±d、±2⁶²、随机数）跟真除法比，
验不过就退回 `idiv`。所以"魔数写错"最多让程序变慢，不会让它算错。

## 14.6 原生后端的边界

| 能力 | 原生后端 |
|---|---|
| 整数、比较、位运算、`//` `%` `^` | ✅ |
| 布尔、`与`/`或` 短路 | ✅ |
| 字符串常量、`#`、`..`、打印 | ✅ |
| `如果` / `当` / 递归 / 函数调用（≤6 个整型参数） | ✅ |
| 浮点 | ⬜ 需要 SSE + 自己写 `%g` |
| 组 / 映射 / 结构 / 枚举 / 结果 | ⬜ 需要堆上的对象布局 |
| 图 / 声音 / 大数 | ⬜ 需要第三方库的 ABI |

不支持的会**明确报错并指到指令**，不会悄悄算错：

```
原生后端还不支持：这类类型的实参
  函数：说
  指令：调用
```

## 14.7 为什么坚持"逐字节一致"

`测试.sh` 末尾有一段原生对拍，规矩是：

- 编不出来 → 记一个 `·`，**不算失败**（覆盖还没做完，这是预期内的）
- 编得出来 → 输出必须和 C 后端的期望文件**逐字节一致**，错一个字就失败

为什么这么定：**能编但编错，比编不出来危险得多**。后者你马上就知道；
前者要到某个数对不上才发现，而那时候你已经不知道是 IR 错了还是汇编错了。

|---|---|

| 看汇编 | `简编译 a.jy -S a.s` |
| 走原生后端 | `简编译 a.jy -n -o a` |
| 跑基准 | `bash 后端/基准/跑.sh` |
