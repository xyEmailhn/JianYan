# 19 在手机上写简言

前十八章都在电脑上跑。这一章换个地方：把简言装进安卓手机。

## 为什么不是"交叉编译一下"

最直接的想法是把 `简编译` 交叉编译成 arm64 的可执行文件。这个想法会在三个地方撞墙：

| 想法 | 撞在哪 |
|---|---|
| 交叉编译 `简编译` | 它最后一步是调 `gcc` 生成机器码，手机上没有 gcc |
| 用原生后端 | 自出的 ELF 是 x86-64，改 arm64 等于重写指令选择 |
| 编成 .so，运行时 exec | Android 10 起禁止 exec 应用私有目录 |

第三条最容易忽略：在 `adb shell` 里手动跑得好好的，装成 App 就 `Permission denied`。
这不是权限没申请，是系统策略。

所以手机上走的是**解释执行**：不生成机器码，按中间表示一条条算。
它与 CPU 无关，也就与 arm64 / x86 无关。

## 装上去

```bash
bash 手机/构建.sh          # 出一个 /workspace/简言.apk
adb install -r /workspace/简言.apk
```

APK 112 KB：7.6 KB 的编辑器界面、3.2 KB 的 dex、209 KB 的 .so。
里面是整个编译器前端加解释器——**词法、语法、语义、IR 一条都没少**，
所以手机上看到的报错和电脑上是同一句。

## 能写什么

打开 App，界面上是一个编辑框、一个运行按钮、一块输出。

```简言
模块 教程.统计

函数 主() -> 整数 {
    私有 整数 组 分 = {88, 92, 79, 95, 61}
    私有 整数 和 = 0
    对 x 在 分 {
        和 = 和 + x
    }
    打印行("总分 " .. 字符串(和))
    打印行("平均 " .. 字符串(浮点(和) / 浮点(#分)))
    返回 0
}
```

手机上支持的东西：

- 整数（含 `整数8/16/32` 的位宽截断）、浮点、布尔、字符串
- 组、映射、结构、枚举
- 函数、递归、函数值
- 字符串方法、数学函数、结果类型
- `引入`（同目录的相对路径）

不接的，遇到会明确告诉你：图片、声音、大数、线程、通道、网络。

## 三个看不见的坑

**一、字符串常量的引号。** 中间表示里存的常量是**源码原文**，带引号。
C 后端有个 `写字面量` 做反转义，解释器一开始没做，于是 `打印行("你好")`
输出 `"你好"`。两处必须逐字一致，否则同一个字符串在两边长度都不一样。

**二、零值结构没有字段表。** `私有 矩形 r` 不写初值时，IR 给一条"常量 零值"。
解释器只把数值置零、没建字段表，后面 `r.左下 = ...` 就找不到落点。

**三、APK 里没有 classes.dex。** `d8` 把 dex 写在 `dex/` 子目录，构建脚本
`cd` 到工作目录后 `zip classes.dex` ——目录里没有这个文件。`zip` 只警告一声，
APK 照样签了出来。**能装，点了就闪退**，构建阶段完全看不出来。

第三个的修法不是"小心一点"，是在签名前把内容念一遍：

```bash
unzip -l "$APK" classes.dex | grep -q classes.dex || exit 1
```

## 为什么值得有一个解释器

它不只是"手机上的玩具"。同一个程序，现在有三条执行路径：

```
C 后端（gcc -O2）  ==  原生后端（自出 ELF）  ==  解释器
```

三方输出逐字相同，才算这个程序"语义清楚"。任何一条路径算得不一样，
就说明某处有个没人写进规范的隐含假设。

`手机/测试.sh` 就是这么用的：22 个用例对拍，6 个"明确不支持"的边界检查，
再加一层执行链路自测（写文件 → fork → 读管道 → 崩溃隔离）。

## 下一步

手机版还是个"跑一下"的工具，不是完整 IDE。明显的缺口：

- 多文件编辑（现在只有 `main.jy`）
- 组和映射在原生后端仍然缺失
- 解释器没有做任何优化，递归斐波那契 30 会跑很久

最后一条不是缺陷，是取舍：**先把语义跑对，性能是下一步的事**。
